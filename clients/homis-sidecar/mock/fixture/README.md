# 疑似電子カルテ（HOMIS互換）— 診療報酬算定テスト用データセット

在宅医療クリニックの電子カルテ **HOMIS**（ブラウザ型EHR）の画面・DOM構造を模した
**疑似カルテ環境**です。診療報酬の自動算定を検証したい貴社向けに、実カルテを匿名化した
患者データを、実HOMISと同一の操作感・同一のDOM構造で提供します。

> 本環境は完全にスタンドアロンで動作します。外部通信・LLM・データベース・認証を必要としません。
> **収録データはすべて架空**です。画面上のシステム表示名は **bomis**（疑似環境名）です。

---

## 1. これは何か

- 各カルテの **行為欄（画面下部・DOM上は `#action_list`）に、その日の正しい算定結果（＝答え合わせ用の正解データ）** を
  埋め込んであります。
- 貴社は、
  1. 本環境を**ブラウザで閲覧**して電子カルテの中身（病名・カルテ本文・処方・書類・診療計画）を確認し、
  2. **自社のスクレイピング／算定エンジン**で各カルテから算定を行い、
  3. その出力と **行為欄（正解データ）** を突き合わせて精度を検証する、
  という使い方を想定しています。
- スクレイピングで取得したい場合は、実HOMISと同じ **要素ID・XPath・JS関数** を再現しているため、
  末尾の「DOM構造」に従って走査できます（ベースURLを本サーバに向けるだけ）。

---

## 2. 匿名化方針

| 項目 | 方針 |
|------|------|
| 氏名・フリガナ | 実名と字面の相関がない、完全に架空の氏名へ置換 |
| 住所・電話・保険番号 | 架空（住所は実在の町名を含むが番地・建物名は架空） |
| **日付** | 実カルテと相関しないよう加工した**合成日付**。対象月＝**2025年1月**（TARGET）、前月＝2024年12月（PREV）を各患者に収録＝**患者ごと2か月分**。 |
| 臨床情報 | 算定判定に必要な構造（訪問種別・居住形態・難病等・処置・書類・診療計画）は保持 |

日付シフトにより曜日は実日付と異なります（合成タイムライン上で内部整合しています）。

## 4. 起動方法

必要環境: Python 3.10+、`fastapi` / `uvicorn`。

```bash
cd mock_homis
pip install -r requirements.txt
./run.sh                 # ポート8899で起動（PORT=9000 ./run.sh で変更可）
# または
python3 -m uvicorn app:app --host 0.0.0.0 --port 8899
```

ブラウザで **http://localhost:8899/homic/login.php** を開く（ID/パスワードは任意の値で可）。

## 5. 画面構成

- **患者一覧・検索**（`?pid=top_patients`）: 氏名・フリガナ検索、13名を一覧表示。氏名クリックで別タブ表示。
- **カルテ画面**（`?pid=patient_detail&patient_id=…`）— 上部タブで切替:
  - **基本情報**（1号紙）: 氏名・生年月日・**診療開始日**・保険・**訪問先住所**。
  - **病名**: プロブレム（登録病名）一覧。fixtureでは可視ラベルで全件表示を明示する。
  - **カルテ**: 左＝介護・訪問看護情報／中央＝SOAP本文／右＝障害区分・在宅医療機器・処方欄／下＝**行為欄（正解データ）**。
    - 疾病等・在宅医療機器欄には、このfixtureで状態管理一覧を全件表示していることを示す可視ラベルを置く。このラベルはmock評価用の完全性契約であり、実HOMISでは同等の画面仕様を別途確認する。
    - **カレンダー**（当月訪問日をハイライト、日付クリックで該当カルテへ、◀▶で月移動）
    - **日めくり**（前後カルテへ移動。前月へも遡れ、前月カルテ表示時はカレンダーも前月へ追従）
  - **診療予定**: 予約パターン、当月予約日、可視の当月受診履歴（診療日・受診種別・状態・カルテID）。fixtureでは可視ラベルで全件表示を明示する。
  - **書類**: 訪問看護指示書・特別訪問看護指示書・診療情報提供書（期間・記入日付き）。

## 6. 算定精度の検証方法（推奨）

1. 各患者・各訪問日について、貴社のスクレイピング／算定エンジンで算定項目を生成する。
2. 同じ日のカルテの **行為欄（`#action_list`）＝正解データ** と突き合わせる。
3. 一致／不足／過剰を集計し、精度を評価する。

行為欄には、その日にクリニックが実際に算定した項目（在医総管・各指導管理料・加算・処置・コメント等）を
埋め込んでいます。訪問種別（定期／電話再診／臨時往診）・居住形態（個人宅／施設）・難病等・書類・
診療計画（月回数・予約日）など、算定に必要な文脈はすべてカルテ内に含まれています。

> 🔶 の項目（超音波・胃瘻交換・療養費同意書）は、キーワード一致では取りこぼしやすく、
> カルテ本文の意味理解が必要です。貴社エンジンの真価が問われる箇所としてご活用ください。

## 7. 再現しているDOM構造（スクレイピングする場合の参照）

| 情報 | 取得方法 |
|------|----------|
| 患者検索 | `#patient_name` 入力、結果は `a[href*="patient_id="]` |
| 訪問種別 | body内 `診療記録　{種別}　「{院名}」`（定期／電話再診／往診 …） |
| 診察日時 | `//*[@id="pdetail_karte"]/div[2]/div[2]/div/div[2]/p[1]` |
| SOAP本文 | `//*[@id="pdetail_karte"]/div[2]/div[2]/div/div[2]` |
| 要介護度・認知症自立度 | `//*[@id="pdetail_karte"]/div[2]/div[1]/div[2]/div` |
| 訪問看護情報 | `//*[@id="pdetail_karte"]/div[2]/div[1]/div[3]` |
| 障害支援区分 | `//*[@id="pdetail_karte"]/div[2]/div[3]/div[1]/div[2]` |
| 疾病等・在宅医療機器 管理状況 | `.device-box`（完全性は可視の `.condition-management-list-status`、内容は `.device-text`） |
| 処方欄 | `//*[@id="pdetail_karte"]/div[2]/div[3]/div[3]/div[2]/table` |
| 行為欄（正解データ） | `#action_list` |
| 単一建物患者数 | body内 `単一建物：{n}` |
| 日めくり（前カルテ） | JS関数 `pdetail_kartePrev(patient_id)` を実行 |
| 診療開始日 | `#p1` タブ → `//*[@id="grid"]/div[1]/div[1]/div[2]/table`（「開始終了」行） |
| 訪問先住所 | `#p1` タブ内の住所テーブル |
| 病名一覧 | `?pid=patient_problem` の本文行（`No 病名 日付`） |
| 書類・期間 | `?pid=docs_index` のテーブル（特別訪看指示／訪看指示／診療（医療）） |
| 診療計画パターン | `?pid=patient_plan0` の `//*[@id="grid"]/div/div/div[2]` |
| 当月受診履歴 | `?pid=patient_plan0` の `.encounter-history tbody tr` にある可視4列（日付・種別・状態・カルテID） |

ルーティングは実HOMISに合わせて全て `/homic/` 配下・`?pid=` ディスパッチです。
自社スクレイパのベースURLを `http://<本サーバ>:8899/homic/` に向けてください。

## 8. 注意・免責

- 本環境・データはすべて**架空**であり、実在の患者・診療実績とは無関係です。
  氏名・住所・生年・保険番号・日付は実カルテと相関しない形へ加工しています。
- 行為欄（正解データ）は、在宅医療クリニックの**実運用上の算定挙動を再現**したものです。
  診療報酬点数・算定ルールは検証用の再現であり、最新の告示と細部が異なる場合があります。
  実際の請求可否は各機関でご確認ください。
- 本環境は認証・暗号化を備えないデモ実装です。**閉じたネットワーク**でご利用ください。
