## 決定事項(レビュー疑問への回答)

1. **初期対象範囲**: 外来・訪問診療・往診・電話再診。**入院は明示的に対象外**
   (基本料体系・評価データが別物。既存エンジンの入院経路は現状維持で、
   whitebox経路はsetting=inpatientでは起動しない)。
2. **candidateOnlyの構造保証**: エンコーダ由来の高確信イベントも、人の承認前に
   確定点数へ入ることは**ない**。WX1のprovenanceゲート+回帰テストで構造的に
   保証する(高確信は「確認の優先度・既定表示」にのみ影響)。
3. **最重要KPIは算定漏れ抑制(recall)を優先**。理由: 過剰側は
   candidateOnly+人承認+決定論ゲート(背反・頻度)の3重で構造的に抑止されるが、
   漏れは人の目に入らない。昇格必須条件は「goldコード単位recallが現行LLM経路比で
   非劣化」。過剰側の許容上限は候補却下率≤50%を初期値とし、WX0基線で再校正する。
4. **合成と実データの分布差検証**: (a)実カルテからは**統計量のみ**算出して比較
   (本文非保存。語彙OOV率・行長分布・セクション構成・spanカテゴリ頻度)。
   (b)WX1 shadowの経路不一致率をセル別に合成評価の予測値と突き合わせ、
   乖離が大きいセルを分布ギャップとしてWX4穴レポートへ流す。
5. **専用推論サービスへの分離は許容**。worker APIのoperation境界を保つ設計に
   しておき、WX0-E6の負荷実験でp95が目標を超えるなら同一イメージ別Cloud Run
   サービスへ分離する(構成変更で済む形を最初から保つ)。

## 背景

### 現状の到達点と限界

現在の抽出は gpt-5.4-nano + v15契約(line_role全行契約・strict schema・照合リトライ・
サンプリングmerge・決定論降格ゲート・行メモ)で、プロンプト工学としてはやり切りに近い。
それでもL7計測で観測されたとおり、**同一本文でイベント数が0/3/14に揺れる**。
原因はプロンプトではなく、「自由記述から行為を生成する」というタスクの出力空間が
広すぎること(生成サンプリングの本質的な非決定性)にある。

また評価・チューニングが在宅(yamamoto)系に偏っており、全診療科×全受診区分への
一般化は未検証。

### 戦略的文脈(2026-07調査)

- 米国の自律コーディング最上位 **Nym Health** は、まさに「言語理解で構造化→
  ルールオントロジーでコード割当」の white-box 構成で95%+精度・監査証跡付きを実現。
  「分類+照合」路線の産業実証がある。**Fathom/CodaMetrix** はconfidence scoringで
  自動化率を稼ぎ低確信のみ人へ——「LLMは例外係」の実証。
- 国の**共通算定モジュールが2026年度に本格提供**され、決定論計算はコモディティ化へ
  向かう。**差別化の主戦場は「カルテ→構造化」の抽出理解レイヤ**である。
- 技術部品は揃った: GLiNER系(小型エンコーダのspan抽出、bi-encoderで数千タイプへ
  スケール)、日本語臨床基盤(UTH-BERT/MedNER-CR-JA/ModernBERT-Ja)、
  日本語埋め込みSOTA(Ruri v3+リランカー)、SapBERT式の同義語対照学習。

### 核心の洞察

**エンコーダ推論は決定論である**(同一入力→常に同一出力)。生成LLMの揺れを
プロンプトで抑えるのではなく、揺れが構造的に存在しないアーキテクチャへ移す。

## 目標アーキテクチャ(5層)

```
カルテ本文(行前処理済み)
   │
L1 span検出(決定論エンコーダ)          … GLiNER方式。行×スパン×行為カテゴリの閉集合分類
   │ spans: {lineId, span, category, confidence}
L2 マスタ照合(埋め込み検索+リランク)    … span→診療行為/薬剤/病名マスタのtop-k→候補コード
   │ links: {span, candidates:[{code, score}]}
L3 文脈判定(小型分類器)               … 実施状態/時制/実施主体/継続状態の多軸+abstain
   │
L4 選択的LLM(例外のみ)               … L1〜L3の低確信・未知表現だけ現行v15経路へ
   │                                    LLM使用率はKPI(下げていく)
L5 決定論エンジン+監査証跡(既存)       … 施設ルール・頻度・背反・月次ゲート
                                        span→候補→文脈→ルールの全連鎖trace(white box)
```

## 不変の原則(全子ページ共通)

1. **確定は人・提案はcandidateOnly**。抽出エンジンがどれだけ強くなっても不変。
2. **点数・制度判定は決定論エンジン**。AIレイヤはコードを「提案」するだけで、
   算定可否・点数・背反は既存エンジンが決める。
3. **合成データのみで訓練・評価**する。実カルテ・承認データの学習利用は
   契約・匿名化規約の整備(WX4)が済むまで行わない。
4. **shadow→計測→切替**。全レイヤは既存LLM経路と並走するshadowモードから入り、
   一致率・差分を計測してからルーティングを切り替える(背反強制で確立した手順)。
5. **ゲートは3系統+マトリクス**: gold seed-300 / fee-soap-e2e-v2 exact /
   安定性コーパス、およびWX0の診療科×受診区分マトリクス。モデル・索引の
   バージョン更新は全ゲート通過が昇格条件。
6. **モデル・索引もマスタと同じ扱い**: バージョン付きアーティファクト、
   生成スクリプト+検証(G1方式)、完全性チェック。失敗時挙動はレイヤの性質で
   区別する——**提案補助レイヤ(L1〜L3)は degraded 継続を許容**
   (無効化して現行経路で続行。ただしmetrics/ログ/readyzで必ず可視化)、
   **提出・確定に関わる経路は fail-closed**(背反強制と同じ規律)。
   「fail-closed」の語は後者にのみ使う。
7. 監査証跡: 全候補は「どの行・どのスパン・どのマスタ候補・どの文脈判定・
   どのルール」から来たかをtraceに残す(Nym型white box)。

## 実行環境の方針

- 推論はpythonワーカーに同居させる(`python/medical_fee_calculation/worker.py` の
  operation dispatchに追加。`name_scan`/`checkLookup`と同じ経路)。
  ONNX Runtime(CPU)を第一候補とし、**決定論設定**(単一スレッド固定・
  非決定的最適化の無効化・モデルとランタイムのバージョン固定)を必須にする。
- モデルサイズはRuri v3系(30m〜310m)・GLiNER small級を想定し、Cloud Run CPUで
  現実的なレイテンシ(目標: L1+L2+L3合計 < 500ms/カルテ)に収める。
  現行LLM経路の中央値約10秒に対し20倍以上の短縮を狙う。
- 外部API依存が減る(nanoはL4のみ)。PHI観点でも自社推論が有利。

## フェーズと受入ゲート

| フェーズ | 内容 | 昇格条件 |
| --- | --- | --- |
| WX0 | ゼロショット実測+診療科×区分マトリクス整備 | span recall・linking精度の地図完成。以降の全判断の物差し |
| WX2 | L2マスタ照合を現行経路の後段に投入(name_scan強化) | 3ゲートgreen+マトリクスでlinking精度が現行辞書比で非劣化、STG shadow計測 |
| WX3 | L3文脈分類器で降格ゲートをML化(正規表現は安全網として残置) | 既存反例テスト全green+誤降格率が現行以下 |
| WX1 | L1 span検出をshadow並走→confidence routing | goldコード単位recall/precision非劣化+人が裁定した不一致分析(LLM一致率は診断指標のみ)。LLM使用率KPIの初期基線化 |
| WX4 | フィードバックループ常設化 | 再訓練→ゲート→昇格の自動サイクルが1周する |

依存: **WX0 → WX2 → WX3 → WX1 → WX4**(第1改訂で確定。WX1のルーティングは
L3の文脈判定を前提にするため、WX3が先)。WX2はWX0の結果が悪くても
現行辞書スキャンの改善として独立の価値がある(最小リスクの初手)。

2026-07-24時点ではWX0の共有契約・コーパス検証・実験ランナーまで実装済み。
reviewedコーパスは0/320件で、モデル実測と分岐決定は未完了のため、
WX2以降の製品経路は意図的に未着手。

## リスクと対応

- **日本語臨床でのゼロショット性能が不明** → だからWX0を最初に置く。実測が悪ければ
  「L2のみ製品化+L1はFTデータが貯まるまで保留」に縮退できる構成にしてある。
- **GPU/並列由来の非決定性** → CPU単一スレッド+ONNX決定論設定で回避。
  同一入力100回で完全一致、を安定性コーパスのテスト項目に追加する。
- **モデル更新による回帰** → 原則6(アーティファクト管理)+ゲート昇格制で、
  マスタ更新と同じ規律を適用。抽出メモはextractorVersionをキーに含め、
  モデル更新時は自動失効(promptVersionと同じ機構)。
- **ライセンス** → 使用モデル(GLiNER系/Ruri/ModernBERT-Ja)・データセット
  (MedTxt等は研究ライセンスの可能性)の商用利用可否を各子ページの冒頭タスクで
  確認し、出典と共に記録する(推測で使わない)。
