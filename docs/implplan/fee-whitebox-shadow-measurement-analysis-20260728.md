## 結論

R0〜R6は**概ね成功**。ただし受入条件は **3/4 達成・1件未達**で、
未達の原因はR1の実装ではなく**WX3のモデル品質**にある。
律速は完全にWX3へ収束した。

## 数字の読み方に2つの罠がある

### 罠1: 分母が 88 → 68 に変わった(R5の効果)

R5で**構造化事実20件が別レーンへ分離**され、`20/20 (100%)` で解決した。
処方箋料のような項目は本文の類似度ではなく**セッション構造**
(院外処方の有無等)で決まるため、埋め込み照合に載せること自体が誤りだった。

副次効果として `retrieval_miss` が 26→8 へ激減した。
2026-07-28の初期分析では「retrieval_missの主因は語彙ギャップ」としたが、
**実際はその多くが「そもそも埋め込み照合すべきでないもの」**だった。
残る8件が真の語彙ギャップ(サチュレーション / X－P / 縫合 / ガーゼ交換 等)。

**したがって比率での世代間比較は無効**。top-1は39.8%→51.5%に見えるが
**分子は35のまま**であり、分母が88→68に減っただけである。
以後は分子で比較し、レポートにも分母定義を明記する。

### 罠2: joint eligible 9→3 は退行ではない

00196で通過していた9件のうち**6件は偽陽性**だった
(カロナール錠300 / ゲンタシン軟膏 / ザイザルシロップ / CRP /
セファレキシン×2)。別の節の過去・否定cueを継承して安全除外に落ちており、
**実施した行為を消す**危険な誤りである。

R1がcue継承を意図的に制限したことでこれらは通過しなくなった。
実質は **9(内6件が誤り) → 3(すべて正しい)** であり改善。

## 受入条件の照合: 3/4 達成

R0 fixtureの真値に対する実測:

| 目標 | 結果 |
| --- | --- |
| 算定対象3件(鼻処置 / 副鼻腔自然口開大処置 / 在宅小児経管栄養法の指導管理) | **3件とも一致** ✅ |
| 安全除外禁止6件が昇格しない | 昇格せず ✅ |
| 真の安全除外1件 `関節腔内注射` が戻る | **未達** ❌ |

実際に安全除外側へ通ったのは `末梢血液一般検査`(160008010)であり、
fixtureが指定した `関節腔内注射`(130005310)ではない。

### 未達の原因はR1ではなくWX3

`関節腔内注射` の診断:

```
retrieval: exact_code_top1        ← linkerは正解をtop1で当てている
blockers:  classifier_requests_llm, context_abstain_or_low_confidence
```

linkerは正しく引けており、**WX3が判定を放棄している**ため通らない。
R1(入力契約の復旧)は正しく機能しており、これはモデル品質側の課題である。
R1の受入としては「実装は妥当、fixture 1件はWX3改善後に再判定」と扱う。

## 現在のボトルネックはWX3へ収束した

```
context_abstain_or_low_confidence  52   ← 最大
context_unresolved                 49
span_low_confidence                47   (strictのみ)
linker_low_margin                  20   (shadow)
linker_family_low_margin           10
retrieval_miss                      8   (真の語彙ギャップ)
```

`context_unresolved` が49と高いのは**意図した代償**である。
R1でcue継承を制限した結果、述語が `unknown` を返す頻度が上がり、
分類器が迷うとLLMへ落ちる。「誤って安全除外にして算定を消す」より
「LLMへ回す」方が安全であり、KPI(漏れ抑制優先)に照らして正しい。

R6の新指標も律速を裏付ける:

- routable lines 74/128 (57.8%)
- **span-bearing routable lines 9/62 (14.5%)** ← 算定関連行に限ると低い
- expected LLM clauses 133/239 (55.6%)

前者は自明な非算定行を含むため**律速判断には使わない**。後者を使う。

## T1. [P0] WX3の強化(最優先)

**根拠**: 最大ブロッカー(abstain 52 + unresolved 49)であり、
他を直しても通過しない。人手レビューを待たずに着手できる唯一の主要項目。
受入未達の `関節腔内注射` もここで解ける可能性が高い。

1. P4計画どおり、時制・実施主体が対立する文を集中生成して
   train/devへ追加(テンプレ単位split維持、holdout非混入)。
2. `build_wx3_context_artifact.py` で再訓練 → dev較正でabstain閾値を再算出。
3. **ベース比較を1回だけ実施**: MiniLM-L12(現行) vs
   `sbintuitions/modernbert-ja-130m`(E1採用候補・MIT・revision固定済み)。
   日本語臨床文の軸判定はトークン化品質の影響が大きく、
   abstain率の改善が見込める。比較環境はtokenizer差があるため、
   採用前に**runtime環境での100回決定論とruntime測定**を必須にする。
4. 受入: `関節腔内注射` が安全除外側へ戻ること。
   abstain 52件の減少幅を記録し、**危険方向(実施を除外に落とす)の
   誤りが増えていない**ことを反例テストで確認する。

## T2. [P1] 語彙ギャップの解消(残8件)

**根拠**: R5で構造化事実を除いた後に残った、真の口語↔正式名称ギャップ。

1. **train splitのspanテキストを索引の別名文書として追加**する。
   WX0コーパスには977件の(カルテ表現 → コード)ラベル対があり、
   これはそのまま別名教師である。
2. **リーク防止(必須)**: 追加してよいのは **train split のみ**。
   dev/holdoutのspanテキストを索引へ入れると評価が自己充足になる。
   ビルダーに split フィルタを実装し、**違反時はビルドを失敗させる**
   (人の注意力に依存させない)。
3. 効果が不足する場合のみ、WX2設計 §5 の対照学習(SapBERT方式)へ進む。

## T3. [P1] 計測レポートの分母定義を明示

R5で分母が変わったことにより、世代間の比率比較が無効になった。

1. レポート(`README.md` / `result.json`)に**各指標の分母定義**を併記する
   (例: `linker評価対象 = 当日自院span − 構造化事実`)。
2. 世代比較セクションでは**分子を主表示**し、比率は補助にする。
3. 分母定義が変わった場合は、レポートに
   `denominatorContractVersion` を出して**変更を検知可能**にする。

## T4. [P2] holdout人手レビューの着手(リードタイム律速)

技術では短縮できない。80件のレビューが
「昇格適格性 / 閾値較正 / 最終判定」の3つを同時に解錠するため、
**早期着手が全体のリードタイムを決める**。
手順は `fee-whitebox-wx0-execution-plan-20260725.md` S1/P5。
