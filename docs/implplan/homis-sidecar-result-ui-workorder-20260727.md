# 作業依頼: sidecar算定案パネルの可読性改善(U1〜U6) (2026-07-27)

対象: `clients/homis-sidecar/extension/`(sidepanel.html / sidepanel.js / sidepanel.css)
関連: [ゲート再設計ワークオーダー](./fee-whitebox-gate-redesign-workorder-20260727.md) S2
(名前分解の規約を共有する)。

## 背景と設計制約

実機スクリーンショットで、算定案パネルの可読性に問題が出ている:

- 「在宅患者訪問診療料（１）１（同一建物居住者以外）」が2行に折り返し、
  結果として**点数が「890」と「点」に分断**されている。
  最も見たい情報(何を・何点)が最も読みにくい。
- 追加提案の全行に「〜の算定確認」の語尾が付き、名前をさらに押し広げている。

原因はマスタ正式名の構造にある。名称は**語幹+区分修飾**でできており、
現UIは両方を同じ太字で並べているため、区分修飾が点数を追い出している:

| 語幹 | 区分修飾 |
| --- | --- |
| 在宅患者訪問診療料 | （１）１（同一建物居住者以外） |
| 外来・在宅ベースアップ評価料 | （１）３（訪問診療時）イ |
| 在宅データ提出加算 | （在医総管・施医総管） |

**設計制約(確定事項)**:

1. **折りたたみ(progressive disclosure)は禁止**。情報を隠さず、
   タイポグラフィと横方向レイアウトだけで階層をつける。
   現行の`<details>`2箇所は**この規約違反であり撤去対象**(U3)。
2. **このパネルに採用/却下の操作は追加しない**。表示専用であり、
   確定はfee-web側(candidateOnly原則)。行の右側に操作領域を確保しない。
3. 拡張機能は`test/dependency-guard.test.mjs`によりサーバ内部モジュールを
   importできない。**表示用の分解結果はAPI応答で受け取る**(U2)。
   拡張側で正規表現を再実装すると、S2のfamilyKey規約と二重管理になり乖離する。

## U1. [P0] 点数の折り返し禁止と列固定(CSSのみ)

対象: `sidepanel.css` `.candidate-row header`。

現状は`display:flex; justify-content:space-between; gap:10px`のみで、
点数側に`flex-shrink`指定がないため名前に圧迫されて折り返す。

1. 点数要素に `white-space: nowrap; flex-shrink: 0;` を付与する。
2. 点数を**右揃えの固定幅列**にし、候補行をまたいで数字の右端が揃うようにする
   (確認作業では縦に数字を追うため)。
3. 名前側は `min-width: 0`(flexアイテムの折り返しを許可するため必須)。

APIもJSも変更不要。**これだけで点数分断は解消する**ので最初に入れる。

## U2. [P1] 表示名の分解をAPI側で提供

### 意図

ユーザーの要求は「区分よりも算定名と点数が重要」。語幹を主・区分修飾を従として
表示するには名前の分解が必要だが、制約3により拡張側では実装しない。

分解規約は**S2の`familyKey`導出と同一のもの**を使う。1つの規約を
3用途(linkerの族グルーピング / 表示階層 / 将来の重複検知)で共有する。

### 実装

1. サーバ(`services/fee-api/src/server.js` のsidecar calculate応答)の
   各候補へ表示用フィールドを追加する:
   ```
   display: {
     stem: "在宅患者訪問診療料",          // 語幹
     qualifier: "（１）１（同一建物居住者以外）"  // 区分修飾(無ければ空文字)
   }
   ```
   - 分解対象は**マスタ名称**であり、提案タイトルの「〜の算定確認」語尾は
     stemに含めない(セクション見出し「追加提案」が既に意味を伝えるため)。
   - 既存の `name` / `title` は**互換のためそのまま残す**
     (fee-web等の他の利用者を壊さない)。
2. 分解ロジックはS2で作る規約(NFKC正規化 → 末尾`「…」`除去 →
   `strip_parenthetical_qualifiers`相当の修飾括弧除去)と同一実装を参照する。
   S2より先に着手する場合は、**S2側が後からこの実装を共有する**前提で書く
   (規約を2つ作らない)。
3. 拡張側(`sidepanel.js` `renderCandidates`)は
   `display.stem` があればそれを主表示、`display.qualifier` を従表示にする。
   フィールドが無い応答(旧サーバ)では従来どおり `name` 全体を表示する
   (段階デプロイでも壊れない)。

### 表示レイアウト

```
┌────────────────────────────────────────┐
│ 在宅患者訪問診療料              890点  │  stem: 太字・主色 / 点数: 太字・右固定
│ （１）１ 同一建物居住者以外  114001110 │  qualifier + code を同一行・小・グレー
└────────────────────────────────────────┘
```

区分修飾とコードを**別行にせず1行にまとめる**のが要点。どちらも
「確かめる時に見る」二次情報であり重みが同じなので、行を分ける必要がない。
情報は1つも減らさずに1件あたり3〜4行→2行になる。

## U3. [P0] `<details>`(折りたたみ)の撤去

制約1の違反箇所。いずれも**常時表示**へ変更する。

1. **警告・確認事項**(`sidepanel.html:112`付近)
   現在15件が既定で閉じており、施設基準の未届出など**算定に直結する情報が
   見えない**。実害があるためこれを優先する。
   - `<details>/<summary>` を通常の見出し+リストへ置換。
   - 件数は見出しに残す(「警告・確認事項 15件」)。
   - 縦に伸びるため、行送りを詰め、**重要度順**(施設基準・算定要件 →
     参考情報)に並べる。並び順の根拠は既存のseverity/issueCodeを使い、
     UI側で新しい重要度を発明しない。
2. **「N件の区分から選択が必要」**(`sidepanel.js` `renderCandidates`内)
   選択肢コードが隠れている。`<details>`をやめ、
   `2件から選択  114003710 / 114004110` の1行として常時表示する。

## U4. [P1] 「要選択」候補の視覚的区別

人の作業が発生するのは`requiresSelection`の候補だけなのに、
現在は確定点数の候補と同じ見た目になっている。

1. 文言を「点数未確定」→**「要選択」**に変更(状態ではなく行動を示す)。
2. 行の左に色帯(border-left)を付け、一覧の中で作業対象が一目で分かるようにする。
3. 色だけに依存しない(色覚特性への配慮)。文言「要選択」が主で、色帯は補助。

## U5. [P2] 合計点数の固定表示

`total-points`は結果セクション先頭にあり、候補を読んでいるとスクロールアウトする。
確認作業中に「今いくら」が常に見えるよう、結果セクションのヘッダーを
`position: sticky`で固定する。パネル幅が狭いため、固定領域は
**合計点数と「承認前」バッジのみ**に絞る(高さを取りすぎない)。

## U6. [P2・別問題] 重複候補の調査

スクリーンショットで**同じ判断を2回求めている**行がある:

- 「在宅酸素療法指導管理料の確認」→ 114003710 / 114004110
- 「「在宅酸素療法」の算定区分確認」→ 114003710 / 114004110

これはUIではなく**候補生成ロジック側の重複**(`clinical-calculation-input.js`の
提案生成が別経路から同一コード集合を2回出している疑い)。

1. 2つの候補がどの生成経路から来ているかをtraceで特定する。
2. 意図的な別物(例: 指導管理料そのものの確認 vs 区分の確認)なら、
   **UIで区別が付く文言**に変える。同一なら生成側で統合する。
3. 統合する場合はfee-web側の表示にも影響するため、両方で確認する。

## 実施順

```
U1(CSSのみ・即効) → U3(折りたたみ撤去・実害あり) → U2(名前分解) → U4 → U5
U6は別調査(サーバ側)
```

## テスト・受入

- 拡張のテスト(`clients/homis-sidecar/test/`)を維持: dependency-guard
  (サーバimport禁止・`innerHTML`禁止・固定拡張ID等)に抵触しないこと。
  **DOM生成は既存どおり`textContent`/`createElement`で行う**。
- 折りたたみが1箇所も残っていないことの機械チェック(`<details>`/`<summary>`が
  sidepanel.htmlとsidepanel.jsに存在しない)をテストへ追加する。
- U2の後方互換: `display`フィールドが無い応答でも従来表示になる。
- 受入: スクリーンショットと同じ算定案で、①点数が1行に収まる
  ②1候補が2行に収まる ③警告15件が全て見える ④要選択が一目で分かる。
