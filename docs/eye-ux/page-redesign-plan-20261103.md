# 全画面 UI/UX 改善計画（2026-11-03）

8 画面それぞれについて競合を調べ、改善案を作った。画面ごとの詳細（競合の出典、問題の一覧と重大度、画面の見本図、修正項目）は同じフォルダの `ux-*-20261103.md` にある。受付は `research-reception-board-20261103.md` の案で実装済み。

## 1. 画面をまたぐ方針

受付の作り直しで評価された型を、他の画面にもそろえる。

- 情報は絞る。毎回同じ値の列、空の欄、使わないボタンは出さない。
- 主な操作は 1 つだけ目立たせる。その他は「…」メニューか引き出しに入れる。
- 色は「状態」にだけ使う。行の左端の帯、数字の色（黄 → 赤）、チップの点。背景を広く塗らない。
- 1 行で読める一覧にし、詳細は行を押して開く。
- 下書き・未確定は、画面でも紙でもはっきり示す。
- 部品は共通化する。患者登録ダイアログ、印刷の枠（PrintShell）、マスタ一覧などは 1 つにまとめる。

## 3. 画面ごとの改善の柱

## 4. 進め方

各画面とも 3 段階で進める。

- P0: 不具合
- P1: API を変えない作り直し
- P2: 小さな API の追加

API とデータモデルの判断が必要なもの（目標眼圧、角膜曲率の項目、医薬品マスタ、並び順、操作記録の期間絞り込み、印影など）は後回しにする。

推奨する API の追加は次のとおり。どれも既存の項目は変えず、足すだけ。

- 会計連携: 連携時の項目の写しを保存し、差分を返す。版を含まない指紋（itemsFingerprint）を使う。修正中のカルテにも連携状態を付ける。
- ホーム: 未確定カルテ・紙カルテ要約・文書の下書きを、患者をまたいで返す（`GET /v1/eye/worklist`）。
- 患者検索: ひらがなとカタカナを同じに扱う、名だけでも引ける、生年月日で探せる（検索用の索引を作り直す）。
- 文書: 下書きを破棄できるようにする。
