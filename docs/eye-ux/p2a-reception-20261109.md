# 段階 2A: 受付・患者検索・患者登録・予約の画面（2026-11-09）

`replicate-plan-20261109.md` の段階 2A の実装メモ。形はデジカル（`spec-digikar-ops-20261109.md` §2〜§5、§10.2〜§10.6）、色は眼科のトークン。

## 受付（/reception）
- 段階ごとのまとまり・人数チップ・「次の 60 分」の間引きをやめ、画面幅いっぱいのフラットな表 1 枚にした。
- 2 行目のツールバー: `受付` ‹［日付（押すと月のカレンダー。見出しは「2026(令和8)年11月」、［今日］［閉じる］）］› ・「全 N件」（絞り込み中は「M / N件」）・［▼ 絞り込み］［×］… 右寄せで［予約状況］［予約を追加］［当日受付］［↻］。URL の `?date=` で日付を開ける。
- 列（左から）: 番号（3 桁、予約は「-」）/ 予約時間 / 受付時間 / ステータス / 患者番号 / 氏名（上にカナ）/ 生年月日（「1954(S29)/05/03」）/ 年齢（性別を添える）/ 目的（保険の位置。保険はレセコンで扱うので出さない）/ 診療科 / 医師 / 前回受付日（初めては「初」）/ 患者メモ / 受付メモ / 会計 / 進捗（視・圧・オーダー）/ 散瞳 / 待ち時間。右端に［予約］（次回予約）と「…」。
- どの列も見出しで並べ替え（押すたびに昇順・降順）。既定は番号の昇順で、番号のない予約は予約時刻の順に上。並べ替えと表示する列は端末ごとに localStorage に覚える（読めない環境では既定）。スマホ幅でまだ選んでいない端末は、受付時間・患者番号・生年月日・診療科・医師・前回受付日・患者メモを隠した状態で始める。
- 絞り込み（▼）: ステータス（件数つき、すべて選択／クリア。取消は既定で外す）・医師・診療科・表示する列の 4 列と、下段に患者メモ・受付メモの文字列。選ぶとすぐ反映し、外を押すか Esc で閉じる。
- ステータスはプルダウン（全 11 種。再計待は表示だけで選べない）。`POST /appointments/:id/status` でどこへでも移す。カルテのある受付の取消は API の 409 をそのまま出す。従来の「受付する／検査開始…」の一押しボタンは置かない（デジカルにないため）。
- 行を押す（氏名のボタンも同じ）: カルテがあれば開く。来院済み（受付中〜会計待）でカルテを書ける役割なら作って開く。予約済・取消・不在の行と、カルテを書けない役割（医療事務）は患者のページへ（予約だけで下書きカルテは作らない。spec §10.2-6 の会計連携の「未確定」に出る問題のため）。
- 予約時間・目的・診療科・医師のセルは ✎ で予約／受付の編集。患者メモ・受付メモのセルは小さなダイアログ（［キャンセル］［登録］）。患者メモは `PUT /patients/:id/memo`、受付メモは `PATCH /appointments/:id {receptionMemo}`。
- 会計: 会計待で確定済みカルテのある行に［会計］、再計待の行に［再送］。確認「レセコンへ会計情報を渡しますか？」→ `POST /billing/send {date, encounterId, appointmentId}` → CSV を保存 → 一覧を読み直す（会計済）。失敗はセルに「失敗」と［再試行］。未確定は「未確定」、会計済・連携済は「連携済」。
- 受付編集履歴（spec §2.9）は API が要るので未実装。

## 患者検索
- ヘッダーの入力欄（`/` で入る、↑↓・Enter）はそのまま残し、右に虫めがね（［詳しく検索（受付・予約・編集）］）と、候補の下に「詳しく検索…」を足した。どちらもデジカルと同じ形のモーダルを開く。
- モーダル: 1 行の入力（番号・カナ・氏名・生年月日。入れるとすぐ検索）、×、右上に［新規患者登録］。結果の列は 患者番号 / フリガナ / 名前 / 性 / 生年月日（和暦）/ 年齢 / 最終受付日 / 患者メモ、行に［表示］［編集］［受付］［予約］。50 件で打ち切り、それ以上は「50件以上」と出す。スマホ幅は 1 人 1 枚のカード。
- 傷病名・受診期間・電話番号の条件は出していない（検索 API が対応していない。電話は platform の患者検索の索引に contact が無く、全件を読むことになるため見送り）。

## 患者登録
- 項目の順をデジカルに: 患者番号 → 氏名 → フリガナ → 性別 → 生年月日 → 住所（郵便番号・都道府県・市区町村・番地・建物）→ 電話番号1・2。住所・電話は platform の `contact` に `{postalCode, prefecture, address1, address2, address3, phone1, phone2}` で入れる（ほかのキーは消さない）。
- ボタンは［キャンセル］［登録］［登録して受付］。［登録して受付］は登録のあと受付登録（当日受付のダイアログ、患者は固定）へ続け、受付一覧へ知らせる（`halunasu-eye-reception-changed` イベント）。編集は［更新］。受付に紐づける用途（未登録の受付から）は従来どおり［登録して受付に紐づける］だけ。
- 似た患者のパネルはデジカルの右の情報パネルの位置（2 列）に置いた。
- 患者番号の自動採番（前回＋1）は入れていない。番号の最大値を取るには全患者を読むか platform に索引付きの問い合わせを足す必要があるため（spec §10.4 の設定「自動採番／レセコン番号」と一緒に決める）。

## 予約・受付登録（AppointmentDialog）
- 予約は 2 列: 左にこの患者の予約一覧（新しい順。✎ 編集・取消（確認つき、取消の状態にする）・カルテ）と［＋］、右にフォーム（予約日＋［予約状況］・患者・医師・診療科・目的・予約時間（空欄可）・受付メモ）→［キャンセル］［登録］／編集は［更新］。
- 当日受付と来院済みの受付の編集は 1 列（受付日は表示だけ）。
- 医師・診療科は、この患者の前回の受付の値を最初から入れる（自分で選んだら上書きしない）。診療科はマスタがないので自由入力＋候補（眼科と過去の値）。
- ［予約状況］はダイアログの中に予約状況カレンダーを開き、枠を押すと予約日・予約時間に入る。

## 予約状況（/reception/schedule）
- デジカルにはナビの入口がないので、ナビには足さず、受付のツールバーの［予約状況］から開く。
- 左: 月の小さなカレンダー（日ごとの件数、［今月］）と医師の切り替え（全員／医師ごと）。右: 週（日〜土）× 時間の表。1 段目は「終日」（時刻なし）、その下は 30 分ごと。件数は「9:00 – 1件」のブロック（狭い画面は件数だけ）。枠を押すとその日時を入れた予約登録を開く。
- `GET /appointments/range` を月（6 週 = 42 日）と週で 1 回ずつ引く。

## 追加した API（後方互換・追加だけ）
- `GET /v1/eye/doctors`: 担当医の候補（眼科で doctor の役割を持つ有効な職員）。`{ doctors: [{ memberId, displayName, printName }] }`。
- `GET /v1/eye/appointments?patientId=`: 1 人の予約・受付（新しい順、100 件まで、`displayStatus` つき）。存在しない患者は 404。
- `GET /v1/eye/appointments/patient-details?date=`: その日の受付の患者ごとの `{ primaryPatientNumber, patientMemo, patientMemoRevision, previousVisitDate }`。受付の写し（patientSnapshot）に患者番号が無いので、番号はいまの患者情報から返す。前回受付日は、その日より前の来院した受付（受付時刻か来院の状態）とカルテの日付のうち最も新しいもの。一覧の 15 秒ごとの更新では引かず、日付を変えたとき・患者が増えたとき・メモを保存したときだけ引く。
- `POST /v1/eye/patients/search` に `details: true`: 各患者に `lastVisitDate`（今日を含む）と `patientMemo`、応答に `limit`。ヘッダーの候補は従来どおり付けない（軽いまま）。
