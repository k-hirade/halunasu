元資料（同じフォルダ）:
- `research-eye-emr-20261101.md` — 眼科専用カルテ（国内: NAVIS-CL / CLIPLA Eye / Claio C-Note 調達仕様 ほか、海外: ModMed EMA / Nextech / Epic Kaleidoscope / Compulink / Eyefinity ほか）
- `research-jp-cloud-emr-20261101.md` — 国内クラウドカルテ（CLINICS / デジカル / Henry ほか）と受付・順番待ち

## 2. 現行 eye-web の差分（監査より、検証済みの主要項目）

### 致命的
1. **暗室表示が壊れている**: ナビが白いまま、見出し・過去カルテ・比較値がコントラスト 1.02:1 で読めない（88/245 要素が AA 不合格）。
2. **CSS 読み込み順が逆転**: バンドル後 `globals.css` → 共通 `halunasu-ui.css` の順になり、共通側の色・罫線・フォント・行間・ナビ背景が眼科側を上書き。トークンが二重定義（緑が 2 色、本文色が 2 色）。
3. **スマホ幅（390px）でナビが 1 文字ずつ縦に折れる**。全画面で横スクロール発生（設定 635px、検査表 732px）。

### 重要
4. 文字が小さい: エディタ表示文字の **84% が 13px 以下**、11 段階のバラバラなサイズ、h3 が本文より小さい。
5. 1180px 未満で 1 カラム化 → iPad では「確定前の確認」「前回比較」が約 5,000px 下へ。固定ヘッダーが画面の 27〜35%。
6. 主ボタン 3.98:1、リンク 3.74:1、プレースホルダー 2.5:1（「例 0.3」が入力済みに見える）。
7. 44px 未満のターゲット: エディタ 120/132、受付 43/43。
8. 再診入力の Tab 動線: 右矯正視力 → 右眼圧まで Tab 24 回。ショートカットは Cmd+S のみ。
9. **日付が UTC**: 朝 9 時前に作った文書の発行日が前日になる（`services/eye-api/src/documents.js` の `now.slice(0,10)`、設定のエクスポート名も同様）。
10. 情報設計: ホーム「本日の受診」と受付で当日患者が二重管理、設定は 4,400px の 1 ページ、操作記録に生 ID、Do 処方が既定で「今回処方」チェック済みのまま確定できる。
11. ナビが `<a href>` で毎回フルリロード（暗室で白フラッシュ）、全画面で hydration mismatch。

### 良い点（残す）
前回値ヒント、眼圧 21 超警告、前回比較の差分、項目単位の Do、「今」ボタン、散瞳タイマー、確定前チェックパネル、受付ボードの経過時間。

再診の定型操作（受付→VA/IOP 両眼→Do→確定）は現状 **10 クリック + 10 入力**。

## 3. 改善方針（提案）

### デザイン原則
1. **デスクトップ優先・1 画面完結**: 1280×800 のファーストビューに「患者帯・両眼 VA/IOP・主訴・今日の処方・確定前チェック」が収まる。
2. **画面幅の役割分担**（競合と同じ）:
   - ≥1280: 3 カラム（履歴 / 記録 / 補助パネル）
   - 1024〜1279（iPad 横）: 2 カラム + 補助パネルはドロワー。検査入力・受付・シェーマはタッチ対応（44px）
   - 768〜1023（iPad 縦）: 1 カラム + セクションジャンプ。受付はリスト表示
   - <768（スマホ）: **閲覧と受付操作のみ**。ナビはハンバーガー、表は縦積み
3. **色は状態だけ**。R/L は位置とラベルで区別し、背景色は補助。
4. **キーボードで完結**: Enter で次の欄、ショートカットを画面に表示。

### デザイントークン（単一ソース化）
- 文字: 12（注記のみ）/ 13（表・補助）/ **14（本文・既定）** / 16（入力値・小見出し）/ 20（ページ見出し）。数値は `tabular-nums`。行間 本文 1.5、表 1.35。
- 行・ターゲット: 表の行 36px、入力 36px（タッチ画面は 44px）、主要ボタン 40px。
- 色: アクセント 1 色（白文字 4.5:1 以上、例 #0a6f68）、本文・補助・罫線を 1 系統に統合。暗室テーマは全トークンを上書きし、`<head>` 内スクリプトで先に適用（フラッシュなし）。
- 角丸 6/10 の 2 種、ボタン高さ 3 種に統一。
- 共通 `halunasu-ui.css` とは `@layer` で優先順位を明示し、読み込み順に依存しない。

### 画面別の主な改修
- **カルテ編集**: 患者帯を 1 行 64〜80px に圧縮（アレルギーは常に赤バッジ）、セクションの折りたたみ + 左ミニナビ（ジャンプ）、検査表の Tab 順を「右 VA→右 IOP→左 VA→左 IOP」に、Enter で前進、視力の候補入力（0.01〜2.0 の候補/キーパッド）、R→L 複写、所見の「異常なし」一括、Do 処方は「引き継ぎ候補」として明示承認、確定ダイアログに処方差分、「下書きを破棄」を確定ボタンから離す、保存状態をはっきり表示。
- **受付**: 列幅を可変・空列を圧縮、行の主アクション 1 つ + その他はメニュー、患者名ターゲット拡大、絞り込みタブ、スマホは縦リスト。ホーム「本日の受診」は受付データに一本化。
- **ナビ / 全体**: Next の `Link` 化、スマホはハンバーガー、現在地表示、ショートカット一覧（`?` キー）。
- **設定**: タブ分割、操作記録を人が読める表示（患者名・日本語イベント名）。
- **バグ**: 日付の JST 統一、hydration mismatch、ファイル入力の日本語化。

### 目標値（受け入れ基準）
| 指標 | 現状 | 目標 |
|---|---|---|
| 再診の定型操作 | 10 クリック + 10 入力 | **5 クリック以下** + 値入力 |
| 右 VA → 右 IOP の Tab 数 | 24 | 2 以下 |
| エディタで 13px 以下の文字 | 84% | 25% 以下（12px は注記のみ） |
| AA コントラスト不合格（暗室含む） | 最大 88 要素 | 0 |
| 390px での横スクロール | 全画面 | 0 |
| 1280×800 ファーストビューに両眼 VA/IOP | 一部 | 全部 |
| iPad 横で確認パネルまでの距離 | 約 5,000px | 0（常時表示またはドロワー） |

### 進め方（案）
- **P0 基盤**: トークン統合・CSS 優先順位・暗室修正・タイプスケール・ナビ（Link/ハンバーガー）・日付 JST・hydration。← 全画面に効く
- **P1 カルテ編集**: レイアウト（患者帯、ミニナビ、2/3 カラム）と入力効率（Tab 順、Enter、候補入力、R→L、正常一括、Do 承認、ショートカット）
- **P2 受付・ホーム**: ボード再設計、スマホ/タブレット対応、当日患者の一本化
- **P3 その他画面**: 検査画面・眼鏡・文書・会計・設定（タブ化、操作記録）
- 各段階で同じ監査スクリプト（5 幅スクリーンショット + 計測）を再実行し、上の目標値で判定。段階ごとにコミット、STG へデプロイ。
