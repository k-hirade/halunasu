# replicate-2 カルテの承認・基準値の設定（approval）2026-11-11

オーナーの決定（2026-11-11）の 3 点を入れた。

1. カルテの「承認」（指導医の承認）を、確定とは別の状態として持つ。
2. バイタルの基準値を医院ごとに変えられるようにする。
3. 検査の基準値を眼圧以外にも付け、同じ設定で変えられるようにする。

色はハルナスのトークンのまま（新しい CSS は `app/styles/approval.css` を globals.css から 1 行で読む）。競合のアイコン・画像・文言は使っていない。

## 1. カルテの承認

### 手本

- トプコン IMAGEnet eカルテの「承認」（確定とは別に、承認した人と日時を残す）。
- 研修医のカルテを指導医が承認する流れ（デジカルなど国内の電子カルテの「指導医承認」）。研修医が確定 → 指導医が承認か差し戻し → 研修医が直して確定 → もう一度承認。

### 流れ

| 場面 | 動き |
|---|---|
| 設定 | 設定 › 医院 › 「カルテの承認」で［承認を使う］を入れる（既定は使わない＝これまでの動き）。同じ画面の表で、医師ごとに「承認者（指導医）」「承認が必要（研修医など）」の印を付ける。利用者管理の編集ダイアログにも同じ 2 つの印を置いた（一覧に「承認」の列）。 |
| 確定 | 「承認が必要」の医師が確定（→ 次へ・確定）すると、その版が **承認待ち** になる。確定の知らせに「指導医の承認待ちになりました」。 |
| 承認者 | カルテを開くと中央の見出しの下に［承認］［差し戻し…］。差し戻しは理由が必須（ダイアログ。⌘/Ctrl+Enter で送る。変換中の Enter では送らない）。自分が確定した版は承認できない。 |
| 差し戻し | カルテは確定済みのまま（会計は止めない）。書いた人のカルテには赤いバーで理由が出る。直す（そのまま入力すると修正が始まる）→ 確定で次の版が承認待ち。 |
| 承認後の修正 | 直すと新しい版になり、もう一度承認待ち。前の版と承認の記録は残る。承認者が直して確定した版は、そのまま承認済み（「指導医が確定」）。 |
| 承認待ちの一覧 | 診察（ホーム）のタブに「承認待ち（件数）」。承認者か、承認を使う医院で承認待ちがあるときだけ出る。行を押すとカルテ。 |
| 表示 | カルテの見出しの札（承認待ち・承認済み・差し戻し）とバー、カルテガイドの最後の「承認」（済=緑・待ち/差し戻し=黄・修正中=白。押すと版履歴）、版履歴の版ごとの記録（承認・差し戻しと理由・未承認）、患者のカルテ一覧の札。 |
| 会計 | 送信は止めない。会計連携の一覧の行とレセコン送信の確認、カルテの［¥ 送信］のダイアログに「未承認」の札と注意。 |
| 印刷 | 未承認の版を印刷すると、紙の受診日の行に枠付きの「未承認」（白黒でも読める）。承認済みの版は「承認 日時 氏名」。画面の上にも「未承認の版です」と出す。 |

### データ（追加のみ・後方互換）

- カルテ（eye_encounters）に `approval` を足した: `{ status: pending|approved|returned, version, contentHash, requestedBy, requestedAt, decidedBy, decidedAt, comment, auto, history: [{ action: requested|approved|returned|auto_approved, version, contentHash, by, at, comment }] }`。承認の流れに入ったカルテだけが持つ。
- 確定したときの revision を `finalizedRevision` に持つ。承認・差し戻しで revision が進んでも、確定のときに開いていた画面からの修正（自動で修正を始める保存）は止めない（内容は確定のときのまま）。
- 確定した版（eye_encounter_versions）は書き換えない。どの版を承認したかは `approval.version` と `contentHash`（版の内容のハッシュ）で残す。
- 職員（eye_staff_profiles）に `approver`・`requiresApproval`（真偽値）。platform-api は変えていない。
- 施設管理の追加の設定（clinic-config）に `approval`（`{ enabled }`）と `referenceRanges` の 2 項目。

### API

- `POST /v1/eye/encounters/:id/approve` `{ expectedRevision, version }` — 承認。
- `POST /v1/eye/encounters/:id/return` `{ expectedRevision, version, comment }` — 差し戻し（comment 必須、1000 文字まで）。
  - どちらも 医師・管理者の役割 ＋ 職員の「承認者」の印 が要る（管理者でも印が無ければ 403）。CSRF 必須。
  - 確定済みでない・承認待ちでない・見ている版（version）が最新でない → 409。自分が確定した版 → 403。revision がずれていれば 409。
  - 操作記録 `eye.encounter_approved` / `eye.encounter_returned`（版・ハッシュ・理由の有無だけ。理由の本文は残さない）。確定で承認待ちになったときは `eye.encounter_approval_requested`。操作記録の分類は「確定」。
- `GET /v1/eye/approvals` — 承認待ちの一覧（今の版が承認待ちの確定済みカルテ。氏名・日付・版・確定した人だけ）。カルテを書ける人。
- `GET /v1/eye/worklist` に `approval: { enabled, canApprove }`・`approvalPending`・`approvalPendingCount` を追加（既存の `counts` は変えていない）。
- `GET /v1/eye/encounters/:id` に `approval`（要約）・`approvalContext: { enabled, approver, requiresApproval, canApprove, canDecide }`、`versions[].approvalEvents` を追加。確定の応答に `approval`。
- カルテの要約（`GET /v1/eye/encounters?date=`・患者のカルテ一覧・会計の下書き）と `GET /v1/eye/billing/day` の行に `approval`（要約。承認を使っていないカルテは null）。
- `PUT /v1/eye/staff-profiles/:memberId` は `approver`・`requiresApproval` を受け取る（送った項目だけ変える。印だけ・氏名だけの保存もできる。承認者にできるのは医師・管理者の役割の人）。
- `PUT /v1/eye/clinic-config/approval` `{ expectedRevision, value: { enabled } }`（管理者）。
- 店（ストア）に `listApprovalPendingEncounters`（Firestore は `approval.status == "pending"` の単一フィールド条件。複合索引は不要）。

### 決めた細かいこと（オーナーの確認がほしいもの）

- 承認者が直して確定した版は、自動で承認済み（`auto`）にした。指導医が自分で直したものを別の人に回す運用なら変える。
- 差し戻しはカルテを「下書き」に戻さず、確定済みのまま「差し戻し」にした（会計を止めないため）。
- 「承認を使う」を後から外しても、残っている承認待ちは一覧に出て承認・差し戻しできる。新しく確定したカルテだけが承認待ちにならない。
- 管理者でも「承認者」の印が無ければ承認できない。承認者と承認が必要の両方の印を付けた人は「承認が必要」として扱う（自分の版は承認できない）。
- 承認待ちになったことの通知（メール・プッシュ）は無い。診察のタブの件数だけ。
- 会計の CSV に承認の状態は入れていない（レセコン側の取り込みの形は変えない）。

## 2・3. 基準値（バイタル・検査）

設定 › 受付・カルテの候補 › 「基準値（バイタル・検査）」。表で今の値と既定の値を見て、［✎ 編集］で下限・上限を入れる（空欄はその側の線を引かない。行の［既定］で既定に戻す）。全角数字も受け付ける。保存は `PUT /v1/eye/clinic-config/referenceRanges`（管理者・CSRF・版つき。下限 > 上限・範囲外は 400）。bootstrap の `clinicConfig.referenceRanges` でカルテ左が読む（保存していない項目・あとで増えた項目は既定の値）。

カルテ左の「バイタル」「検査」の表で、基準値の列・外れた値の色（高い・低い）・グラフの破線に使う。グラフの線は R・L で同じ値のときは 1 本にまとめて「基準値」と書く（線の数が増えて読みにくくならないように）。

### 既定の値と根拠

どれも成人の一般的な目安で、診断の基準ではない（色分けの目安）。

| 項目 | 既定 | 根拠・前提 |
|---|---|---|
| 血圧（上） | 90〜139 mmHg | 高血圧治療ガイドライン 2019（日本高血圧学会）の診察室血圧 140 以上を高血圧。90 未満を低血圧の目安。これまで固定で入れていた値と同じ。 |
| 血圧（下） | 89 以下 | 同じく 90 以上を高血圧。 |
| 脈拍 | 60〜100 回/分 | 成人の安静時の一般的な範囲。 |
| 体温 | 35.5〜37.4 ℃ | 37.5 ℃ 以上を発熱とする一般的な扱い（感染症法の届出基準の「発熱」と同じ）。 |
| SpO2 | 96 % 以上 | 一般に 96〜99 % を正常の目安とする。 |
| 血糖 | 70〜139 mg/dL | 低血糖 70 未満、随時血糖 140 以上を要確認の目安（従来の値）。 |
| 身長・体重 | なし | 個人差のため基準値を持たない。 |
| BMI | 18.5〜24.9 | 日本肥満学会の判定（18.5 未満 低体重、25 以上 肥満）。 |
| 裸眼視力 | 基準なし（既定） | 近視・遠視で外れるのが普通なので既定では付けない。医院の設定で付けられる。 |
| 近見視力 | 0.7 以上 | 老視で外れやすいため 0.7 を目安にした。 |
| 矯正視力 | 1.0 以上（小数視力） | 小数視力 1.0 を正常の目安とした（学校保健の判定でも 1.0 以上が A）。裸眼は近視・遠視で外れるのが普通なので、色は「要確認」ではなく目安として読む。近見は矯正下で測る前提。 |
| 眼圧 | 10〜21 mmHg | 正常眼圧の統計的な範囲（平均 ±2SD の上限 21 mmHg。緑内障診療ガイドラインの記載）。従来と同じ。 |
| 屈折 S | −0.50〜+0.50 D | 正視の目安（研究で多く使われる「±0.50 D 以内を正視」）。外れたら近視・遠視。 |
| 屈折 C | −1.00〜+1.00 D | 1.00 D を超える乱視を臨床的に意味のある乱視とすることが多い。マイナス・プラスどちらの表記でも外れが分かるよう両側に置いた。 |
| 角膜曲率 K1・K2 | 41〜47 D | 平均は約 43〜44 D。47 D を超えると円錐角膜を疑う目安（Rabinowitz の基準など）、41 D 未満は扁平角膜。曲率半径ではおよそ 8.2〜7.2 mm（337.5 ÷ R）に当たる。 |
| 瞳孔径 | 2〜5 mm | 散瞳前の室内光での目安（明所でおよそ 2〜4 mm）。左右差は別に見る（今回は扱わない）。 |
| C/D 比 | 0.6 以下 | 緑内障の健診判定で垂直 C/D 0.7 以上を緑内障疑いとすることに合わせ、0.6 までを範囲内とした。 |

- 眼軸長（22〜25 mm）・角膜曲率の mm 表記: カルテの検査値に項目が無い（眼軸長は IOL 管理の術前値、角膜曲率は D で入れている）ため、今回は設定に入れていない。検査値に足すときに同じ設定へ足せる形にしてある（`packages/eye-core/src/reference-ranges.js`）。

### 決めてほしいこと

- （2026-11-11 決定）裸眼視力は既定で基準なし（空欄）。近視・遠視の患者で毎回色が付くのを避ける。医院の設定で付けられる。
- （2026-11-11 決定）近見視力の既定は 0.7 以上（老視で外れやすいため）。
- 屈折 S の正視の幅（±0.50 D）を医院の運用に合わせるか。

## オーナーの決定（2026-11-11）

- 承認者が自分で直して確定したカルテは、自動で承認済みにする（今の動き）。
- 差し戻したカルテは確定のまま残す（会計連携を止めない）。
- 承認待ちの通知（メールなど）は今は付けない。診察画面の件数だけ。
- 裸眼視力の既定は基準なし、近見視力の既定は 0.7 以上。
