# 競合調査: 受付 / 患者フロー(待ち)画面の設計

調査日: 2026-11-03 / 対象: Halunasu eye 受付ページ(現行 5列カンバン+縦長カード)の見直し

> 確度の表記: **[確認]** = 公式ヘルプ・マニュアル・公式画像で確認した / **[二次]** = 第三者記事や他院の研修資料で確認した / **[未確認]** = 公開情報で確認できなかった(推測や伝聞は書いていない)

---

## 0. 結論(先に要点)

1. **主流は「1つの表 + ステータス列」。** 国内の汎用クラウドカルテ(CLINICS、デジカル、デジスマ、CLIUS)は、どれも当日の患者を **1行1患者の表** で出している。ステータスは列(またはプルダウン)で持ち、**チェックボックスで絞り込み、列見出しでソート** する。海外でも athenahealth と NextGen の Patient Tracker は表/リスト型だった。
2. **カンバン(カード)型は眼科で少数派として存在する。** CLIPLA Eye は「ステータス別カード + 並べ替えで状態変更」。ただしカードは **3行ほどの小さいもの** で、詳細は **クリックするとその場で開く** 作りになっている。初めから全部の情報を載せてはいない。
3. **いちばん参考になるのは「グループ化したリスト」型。** athenahealth の Status view は、1本のリストを **ステータス見出しで区切り、見出しごとに折りたためる**。グループ内は **待ち時間の長い順**。CLIUS の旧受付画面(2019)も、ステータスごとに表のセクションを縦に積む形だった。カンバンの「どの段階に何人いるか」と、表の「読みやすさ・密度」を両立できる。
4. **CLIUS「みえるか診療一覧」(2024) は2段構成。** 上段に部屋/段階ごとのレーン(1患者を **番号+氏名の1行チップ** で表示し、あふれた分は「他4人」に畳む)、下段に全項目の表を置く。カンバンを採る場合でも、**カードはチップ程度まで小さくする** のが他社の答えになっている。
5. **時間の出し方。** 受付からの経過(滞在)時間と、今の状態に入ってからの時間の **2つ** を持つ製品が多い(NextGen、OpenEMR、athena)。表示は分単位で、120分を超えると時間単位(athena)。**しきい値を超えたら目立たせる** 方式は OpenEMR(ステータスごとにアラート分数を設定して点滅)で確認した。ただし「黄→赤」の具体的な分数は製品ごとの設定で、標準値は公開されていない。
6. **眼科特有の工夫。** 段階を細かく分けている(Epic 導入眼科では「Technician In / Waiting for Visual Field / Dilating in Exam Room / Dilating in Waiting Room …」)、検査指示書(バーコード付き)の一括印刷(CLIPLA Eye)、前回の検査値を載せた受付票(Claio)。散瞳タイマーを受付ボードに載せている例は、海外の小規模ベンダーの宣伝でしか確認できなかった **[二次]**。

**提案:** 現行の5列カンバンをやめ、「**ステータス見出しで区切った1本の高密度リスト(1行 40〜48px)**」に変える。上部には **段階ごとの人数チップ(押すと絞り込み)** を置く。行の右端には **主ボタンを1つだけ** 置き、残りは「⋯」にまとめる。行を押すと右側に詳細パネルが開く。予約(未来院)は同じリストの先頭グループ「来院予定」として畳んでおく。詳細は §3。

## 1. 製品ごとの調査結果

### 1-1. CLINICS カルテ(メドレー) — 表型 [確認]
- 出典: https://intercom.help/clinics/ja/articles/2892057 (「【カルテ】受付一覧画面の機能と使い方」)
- **レイアウト:** その日に診察する患者を並べた表。予約患者もこの表に自動で入る。
- **ステータス(7種):** 受付待ち / 診察待ち / 診察中 / 算定待ち / 会計待ち / 完了 / キャンセル。**チェックボックスで表示・非表示を切り替える**(例: 診察待ちだけを出す)。
- **ソート:** 列見出しの「診察予定」「受付(受付時間)」「終了(診察完了時間)」で昇順/降順。
- **絞り込み:** 担当医、診療メニュー、氏名・カルテ番号の即時検索(かな入力でもヒット)。
- **操作:** 予約患者の受付は **行の右端の[受付]ボタン**。予約外の患者は画面右上の[当日受付]。
- **色:** 「会計エラー」は赤い文字で出る。それ以外の色分けは公開ページに記載なし。
- **未来院と来院中の分け方:** 同じ表の中で「受付待ち」ステータスとして扱う。別の一覧には分けていない。
- 補足: 当日メモ・ラベルで院内に共有する運用が案内されている(FAQ Q5)。

### 1-2. エムスリーデジカル — 表型 [確認]
- 出典: 操作マニュアル(ORCA連動版, 2026/10/6更新) https://digikar.m3.com/documents/digikar_manual.pdf の p.32〜37
- **列(左から):** 番号(受付順に 001〜、取り消すと欠番) / 予約時間 / 時間(受付時刻) / ステータス / (診療科・医師) / 患者メモ(毎回表示) / 受付メモ(当日だけ) / 初 / 端(アプリ) / 支払 / 会計([会計]ボタン) / 処方箋(FAX希望を緑背景で表示) / 出 / 問診回答 / 連絡 / 予約 / 受付詳細。
- **ステータス:** 予約済 → 診察待(または受付中。施設設定で選ぶ) → 診察中 / 検査中 / 処置中 / 不在(どれも手動・任意) → 会計待(カルテを「次へ」で保存すると自動) → 会計済(ORCA送信時) / 再計待 / 取消。
- **操作:** **行(患者)をクリックするとカルテが開く**(「予約済」の患者をクリック → カルテ、p.1690行付近)。会計は **行内の[会計]ボタン**(会計待のときだけ出る)。メモ欄はクリックしてその場で編集する。
- **ソート・絞り込み:** 各列の見出しでソート。フィルターで「会計済は表示しない」などステータス単位の非表示ができる。**表示する列も端末ごとに出し入れできる**(p.37)。
- **未来院と来院中の分け方:** 同じ表の中で「予約済」ステータスとして扱う。
- 補足: カルテ画面の上部に「患者リスト」(診察待の患者)があり、**診察待の人数をバッジで表示** する(p.29)。医師は受付表を見ず、自分の待ち行列だけを見る作り。

### 1-4. CLIUS(Donuts) — 2019年: ステータスごとの表セクション / 2024年: レーン+表の2段 [確認]
- 出典(2019): https://clius.jp/news/reception (公式スクリーンショット付き)
  - **レイアウト:** 「受付」「診察待」「診察終了」「ORCA送信済」の **4つのセクションを縦に積み**、それぞれが同じ列構成の表になっている。ヘッダーにステータス別の件数(受付:2 / 診察待:2 …)を出し、診療科・担当医で絞り込める。
  - **列:** No. / 受付時刻(診察終了・会計終了の時刻も) / ラベル(リボン5色・注射・マグカップなど) / 患者番号 / 氏名 / カナ / 性別 / 年齢 / 生年月日 / 保険 / 患者メモ / メモ(当日) / 診療科 / 担当医。
  - **密度:** 1行は約20px。罫線だけの業務表で、色は使っていない(色はラベルのアイコンだけ)。
- 出典(2024): 「CLIUS患者案内」プレスリリース https://www.donuts.ne.jp/wp-content/uploads/2024/07/PRESSRELEASE-240703_clius_patientinfo-DONUTS-3.pdf の p.2「みえるか診療一覧」の画面イメージ
  - **レイアウト:** 上段に **部屋・段階ごとの横並びレーン**(会計 3人 / 診察室01 9人 / 診察室02 4人 / 処置室 1人 / X線室 4人 / 部屋B 4人)。レーンの中の患者は **「番号 + 氏名」の1行チップ**(高さは表の行と同じくらい)。レーンの見出しに人数を出し、**入りきらない分は「他4人」と畳む**。レーンの上辺は段階ごとの色(オレンジ・青・黄など)で、チップは白地。
  - 下段に、従来どおり全患者の表(No. / 受付 / 予約 / 患者ID / ラベル / 氏名 / カナ / 性別 / 年齢 / 生年月日 / 保険 / 患者メモ / 診療科 / 担当医)。
  - 売りの文句は「次は誰を採血するのか / どこで誰が診察中なのか / どこが混雑しているか / 誰を算定すれば良いか」。**ボードは状況を一目で掴むため、表は作業のため** という役割分担。
- 眼科向けには「CLIUS-Cross」(ニデック NAVIS-Cross と連携)がある。資料の機能一覧に「受付一覧」「ステータスカスタマイズ」はあるが、画面の詳細は **[未確認]**(https://clius.jp/wp-content/uploads/CLIUS-Cross_DOCUMENT.pdf)。

### 1-5. CLIPLA Eye(クリプラ) — カンバン型(眼科専用) [確認]
- 出典: https://clipla.jp/eye/service/ (公式の画面画像 img_step01_01.png / img_step01_02.jpg)
- **列(ステータス):** 受付済 / 検査・処置・手術 / 診察中 / 会計待ち / 会計済み の5列。列の見出しは矢印型の帯に件数バッジ付き。ステータスの名前と順番は医院ごとにカスタマイズできる。
- **カードの中身(閉じた状態は3行+入力欄):**
  - 1行目: [新]バッジ・診療科・患者ID・受付時刻(00:35)・受付番号バッジ(17)
  - 2行目: **氏名(太字) + 年齢バッジ**(色付き。男女の色分けと思われる **[未確認]**)
  - 3行目: カナ(小さい灰色の文字)
  - 4行目: 受診目的の1行入力欄(Enterで保存)
  - カードの上に「1 ― 24分前」(列内の順番と経過時間)
  - カードの右端に **色付きの縦帯**(7色から選ぶ「カラー」。院内で自由に意味を決める)
- **操作:** **カードの並べ替え(ドラッグ)でステータスを変える**。カードをクリックすると **その場で縦に開き**、生年月日・保険種別・診療科・診断種別・ステータス(プルダウン)・カラー・[指示書を印刷する]・[受付をキャンセル]が出る。
- **眼科特有:** 列の見出しに「一括印刷」がある(**患者IDバーコード付きの検査指示書** を列ごとにまとめて印刷。指示書には前回来院日・定期処方・前回処方・指示が載る)。受付の後はそのまま検査に回る眼科の動線に合わせている。
- **多人数への対応:** 列の中で縦に積むだけ。画像では会計待ち5人で列がはみ出しかけている。どの端末で動かしても他の端末に自動で反映される。
- 印象: カンバンではあるが、**カードはかなり小さく、操作ボタンはカードの外(開いた詳細の中)に追い出している**。現行の Halunasu のカード(メモ欄・時間2つ・ボタン3つ)と比べると、閉じた状態の情報量は半分以下。

### 1-9. 海外

#### athenahealth(athenaOne) — ステータスで区切ったリスト型 [確認]
- 出典: https://help.athenahealth.com/Ohelp/Content/Features/C_Walk-In_Encounter_Management_Feature_A.htm
- **Status view(医療者向けホームの予定表):** 1本のリストを次のグループに分け、**グループごとに折りたためる**。
  - Scheduled(未来院。予約時刻順) / Waiting room(来院済み。「Ready for staff」は先頭へ) / Ready for provider / With staff/provider / Done with exam
- **行の項目:** Wait time(チェックイン開始からの在院時間。分で表示し、120分を超えると時間、24時間を超えると日で表示。チェックアウトで止まる) / 予約種別・受診理由 / Urgent(**赤い縦帯** と赤い文字) / Room / Room Status(空いている部屋) / Pending・Result の院内オーダー件数(押すと一覧が開く)。
- **並び順:** **グループ内は待ち時間順**(緊急を指定した場合は緊急を優先)。
- **オプション:** Encounter Status Timestamp を有効にすると、**各ステータスでの滞在時間と全体の時間** を表示し、各グループ内を最長待ち順に並べる。
- 色の慣例(ある医療機関の研修資料, https://www.smlcares.com/training) **[二次]**: 紫=来院 / 橙=スタッフ対応待ち / 薄緑=医師待ち / 濃緑=医師対応中 / 灰=チェックアウト。氏名の右の丸印で進み具合を示す。

#### NextGen(NextGen Office / MediTouch)Patient Tracker — 表型 [確認]
- 出典: https://www.community.nextgen.com/mtknowledge/articles/Knowledge/Patient-Tracker
- ※ Nextech(眼科EHR)とは別の会社。Nextech の Patient Tracking の公開ドキュメントは **[未確認]**。
- **列:** Room(部屋の状態を色付きの四角で示す+部屋名) / Time(予約時刻) / Wait(患者の状態+待ち時間) / Patient(氏名。下にコメント・フォローアップ) / Appointment Type / Age / Sex / Reason for Visit / Provider / Vitals(入力済みなら緑のチェック) / Priority(高=上矢印、低=下矢印、通常は空欄) / Chat。
- **Wait の表示:** 時間が1つなら「チェックインから診察開始まで」。2つなら「チェックインから診察開始まで」と「診察開始からチェックアウトまで」。
- **操作:** **押す場所で動作が変わる**。時刻 → 診察を開始、氏名 → カルテ、予約種別 → 予約の編集、部屋の色の四角 → 部屋状態を変更。右からプレビューパネルがスライドして出る。
- **絞り込み:** Waiting / In a room / Checked out / All と「Hide Checked Out」。

#### Epic(Department Appointments Report = DAR) — 表型 [確認/二次]
- 出典: https://epicsupport.sites.uiowa.edu/epic-resources/check-incheck-out (アイオワ大の Epic サポート)
- DAR は1日・1部門の予約を並べた表で、チェックイン/アウトの中心になる画面。ツールバーの操作は「部屋に案内(Room Patient)」「EOD ステータス更新」「ラベル印刷」など。**表示する列はユーザーが選ぶ**(個人用レポート)。
- 色: 2018年の外来アップグレード資料(Riverside)を引いた検索結果によると、予定=青 / 待ち=橙 / 診察中=黄 **[二次。原本は接続できず未確認]**。ED の Track Board では在院時間の時計アイコンが3時間で黄、4時間で赤、6時間で点滅という構築例がある **[二次・外来ではなく救急の例]**。
- **眼科での運用例 [確認]:** Epic を使う大学眼科のステータスラベル(https://www.dovepress.com/clinic-flow-metrics-before-and-after-relocation-to-a-new-academic-eye--peer-reviewed-fulltext-article-OPTH):
  Arrived / Technician In / Waiting for Visual Field / At Visual Field / Visual Field Complete / Waiting for Imaging / At Imaging / Imaging Complete / **Dilating in Exam Room / Dilating in Waiting Room** / Waiting for Resident/Fellow / Waiting for Physician / Resident/Fellow In / Physician In / Visit Complete
  → **検査ごとに「待ち / 実施中 / 完了」を持ち、散瞳は「どこで散瞳中か」まで分けている**。

#### OpenEMR Patient Flow Board — 表型(OSS) [確認]
- 出典: https://open-emr.org/wiki/index.php/Patient_Flow_Board
- ステータスごとに **色** と **アラートの分数** を設定する。**Current Status Time(今のステータスに入ってからの時間)がアラートの分数を超えると点滅** する。ステータスを変えるとこの時間はリセットされ、来院からの合計時間は動き続ける。
- 行の色はステータスの色。チェックアウト済みの患者は N 分後に隠す設定がある。20秒ごとに自動更新。

#### ModMed EMA / Nextech / Compulink / Weave
- **ModMed EMA:** 「patient flow monitoring」を宣伝文句に挙げ、データ辞書に Office Flow(部屋の利用ログ)や **散瞳の記録テーブル(眼ごと)** がある。画面の形式は **[未確認]**(https://www.modmed.com/specialties/ophthalmology/)。
- **Nextech(IntelleChartPRO):** 「Clinical Workflow Manager がチェックインから患者の動きを追う」とだけある。画面は **[未確認]**。
- **Compulink:** 部屋の割り当てから「今診ている患者」を判断し、カルテを自動で開く。作業リスト(work lists)型。詳細は **[未確認]**(https://compulinkadvantage.com/optimizing-patient-flow-to-improve-care-quality-and-operations/)。
- **Weave:** 連絡・決済ツールで、院内の動線ボードは見当たらない。
- 参考(眼科の古い例): Brevium は院内の見取り図で部屋の使用状況を色分けし、待ち・散瞳中の時間を色付きのタイムラインで表示していた(Review of Ophthalmology, 約20年前の記事)。https://www.reviewofophthalmology.com/article/using-computers-to-monitor-patient-flow
- 参考(宣伝のみ): ReyanLabs は「散瞳のカウントダウンタイマー(20〜40分)」、Lyne は「点眼した時刻を記録し、散瞳が終わったら通知。それまで医師への『準備完了』通知を止める」と宣伝している **[二次・宣伝]**。

## 2. まとめ

### 2-1. どのレイアウトが主流か

| 形式 | 製品 |
|---|---|
| 1つの表 + ステータス列(チェックボックスで絞り込み) | CLINICS、デジカル、デジスマ、NextGen、Epic DAR、OpenEMR |
| ステータスで区切った1本のリスト/表(折りたためる) | **athenahealth Status view**、CLIUS(2019) |
| 段階レーン(小さいチップ) + 下に表の2段 | **CLIUS みえるか診療一覧(2024)** |
| カンバン(カード、並べ替えで状態変更) | **CLIPLA Eye**(眼科) |

→ **表・リスト型が多数派**。カンバン型は CLIPLA Eye しか確認できず、その CLIPLA Eye もカードは小さく、詳細は開いて見る方式。**縦長のカードに全部を詰め込んだカンバンは、どの製品も採っていない**。

### 2-2. よく出る項目と並び順(左から)
1. **番号**(受付番号/呼出番号): すべての製品にある
2. **時刻**: 予約時刻と受付時刻(2列にするか、片方を小さく出す)
3. **氏名 + カナ**: 同じセルで上下に置くか、隣り合う列。カナは小さく灰色
4. **年齢・性別**: 小さく(CLIPLA は年齢バッジ)
5. **区分バッジ**: 初診「新/初」、ラベル(色リボン・アイコン)
6. **受診目的・予約種別**
7. **ステータス**: 列、またはグループの見出し
8. **待ち時間/経過時間**
9. 部屋・担当医・診療科(絞り込みの軸にもなる)
10. メモ(患者メモと当日メモを分ける。デジカル、CLIUS、デジスマ。**長文ではなくアイコンや1行に省略して出す**)
11. 業務の状態アイコン(問診済、バイタル✓、オーダー件数、処方箋FAX)
12. 操作(行の右端)

### 2-3. 行のつくり(共通パターン)
- **行全体を押す → カルテ/詳細**(デジカル、CLIPLA、NextGen の氏名)。
- **右端に「今その状態で行う操作」を1つだけ出す**(CLINICS[受付]、デジカル[会計]、デジスマ[受付]/[請求])。**ステータスによって出るボタンが変わる**。
- その他の操作はアイコンかメニューにまとめる(デジスマの予約・チャット・詳細アイコン、Epic のツールバー)。
- 詳細は **右からのパネル**(NextGen Encounter Preview)か **その場で開く**(CLIPLA)。
- ドラッグ&ドロップで状態を変えるのは CLIPLA だけ。表型の製品は、ステータスのプルダウン、カルテの保存などの操作に連動した自動遷移、または行の中のボタンで変える。

### 2-4. 多人数への対応
- 表型: **ステータスの表示・非表示**(CLINICS、デジカル)、**条件の保存**(デジスマ)、**列の出し入れ**(デジカル)、件数表示、検索、ソート。
- グループ型: **グループの折りたたみ**(athena)、**終わった人を自動で隠す**(OpenEMR、NextGen の Hide Checked Out)。
- レーン型: **「他N人」に畳む**(CLIUS)。
- カンバン型: 列の中で縦に積むだけ(CLIPLA。多人数時の対策は確認できなかった)。

### 2-5. 未来院 / 来院中 / 終了の分け方
- **同じ一覧の中のステータスで分ける製品がほとんど**(CLINICS の受付待ち、デジカルの予約済、athena の Scheduled グループ)。別画面や別の表に分ける例はなかった。
- 終了者は **初期状態で隠すか、折りたたむか、下へ回す**(CLINICS の「完了」チェックを外す、デジカルの「会計済は表示しない」、OpenEMR の N 分後に隠す)。

### 2-6. 見た目(密度・色・時間)
- **密度:** 国内の表は1行 20〜28px で、かなり詰まっている(CLIUS、デジカル)。CLIPLA のカードは1枚 80px ほど。どれも余白は小さい。
- **ステータスの色:** **帯・ドット・小さなバッジなど、面積の小さいところにだけ使う**(CLIPLA の右端の縦帯、CLIUS のレーン上辺、athena の緊急の赤い縦帯、NextGen の部屋の色の四角)。**行の背景を塗りつぶす例は少ない**(OpenEMR の行の色くらい)。
- **時間:** 「受付からの経過」と「今の段階に入ってからの時間」を持つのが基本で、分で表示する(athena は120分を超えると時間表示)。**しきい値の扱い:** OpenEMR はステータスごとのアラート分数を超えると点滅、Epic ED は構築例で3時間=黄、4時間=赤。**外来の標準的な分数は公開されていない**。眼科なら「段階ごとに設定できる」ようにし、初期値は自社で決めるのが妥当(例: 診察待ち 30分で注意、60分で警告)。
- 赤は「緊急」「エラー」「長い待ち」だけに使う(CLINICS の会計エラー赤字、athena の Urgent)。

### 2-7. 眼科特有の要素
- **検査の進み具合:** Epic 導入眼科は検査ごとに「待ち / 実施中 / 完了」をステータスとして持つ。行に **検査チップ(視力✓ 眼圧✓ 視野… OCT…)** を並べる形は、athena の「オーダー件数」や NextGen の「Vitals✓」と同じ考え方。
- **散瞳:** Epic 導入眼科は「Dilating in Exam Room / in Waiting Room」を独立したステータスにしている。ModMed は散瞳を眼ごとに記録している。点眼時刻からのタイマーと完了通知は海外の小規模ベンダーが宣伝している。→ **点眼時刻を記録して経過分を表示し、所定の分数(例: 20〜30分)で「散瞳OK」に変える** 機能は、他社との差別化になる。
- **検査指示書の一括印刷**(CLIPLA)、**前回の検査値付き受付票**(Claio)。
- 視能訓練士(ORT)の割り当て: 公開情報では **[未確認]**(デジスマの「スタッフ」列、athena の With staff、Epic の Technician In が近い)。

## 3. Halunasu eye への提案

### 3-1. 方針
1. **5列カンバンをやめ、ステータスで区切った1本のリストにする**(athena 型+ CLIUS 2019 型)。横幅を全部使えるので、氏名・目的・検査の進み具合を1行に並べられる。カードを縦に積む問題もなくなる。
2. **上部に段階ごとの人数チップを置く**(`来院予定 12 | 受付済 3 | 検査中 4 | 散瞳中 2 | 診察待ち 5 | 診察中 1 | 会計待ち 2 | 終了 18`)。押すとその段階だけに絞り込む(CLINICS のチェックボックスをチップにしたもの)。カンバンの「一目で人数がわかる」良さはここで残す。
3. **1行は 44〜48px(タブレットのタップ領域を確保できる下限)。2段にせず、カナは氏名の右に小さく出す。**
4. **ボタンは行の右端に1つだけ**(状態に応じて 受付 / 検査開始 / 呼び出し / 診察開始 / 会計)。「検査入力」「カルテ作成」は「⋯」メニューに入れるか、行を押して開く右パネルに移す。
5. **メモは行に本文を出さない。** 📝 アイコンと先頭の約12文字だけを出し、全文はパネルで読む。
6. **時間は1つに絞る。** 行に出すのは「今の段階での待ち」(例: `待 23分`)だけ。受付からの経過はパネルかツールチップに回す。しきい値を超えたら **数字の色だけ** を amber → red にする(行は塗らない)。しきい値は段階ごとに設定でき、初期値は例として 診察待ち 30/60分、検査待ち 20/40分。
7. **散瞳は専用の表示にする:** 点眼した時刻を記録すると `散瞳 12/25分` のように進み具合を出し、規定の分数に達したら緑の `散瞳OK` に変わる。
8. **検査の進み具合をチップで出す:** 指示された検査を `視✓ 圧✓ 屈✓ OCT・ 視野・` のように並べる(✓=完了、・=未実施、◐=実施中)。視能訓練士の担当は名前のイニシャル(例: `ORT:佐`)。
9. **来院予定は同じリストの先頭グループに入れ、初期状態は「次の60分だけ表示、残りは畳む」**。終了は最下部のグループに入れ、初期状態は畳む(件数だけ見せる)。
10. **ステータスの色は行の左端の4px帯と人数チップのドットだけに使う。** 背景は白か、ごく薄い灰色。

### 3-3. 1行の構成(左から, 目安の幅)
| # | 要素 | 幅 | 備考 |
|---|---|---|---|
| 1 | 状態の帯 | 4px | ステータス色 |
| 2 | 受付番号 | 40px | 等幅の数字、太字 |
| 3 | 時刻 | 48px | 受付時刻。未来院なら予約時刻+「予」 |
| 4 | 氏名+カナ | 可変(最小180px) | 氏名は15px太字、カナは12px灰色で同じ行に |
| 5 | 年齢・性別 | 40px | `72女` |
| 6 | 区分+目的 | 可変 | `[新]` バッジ+目的のテキスト(省略記号あり) |
| 7 | 検査チップ / 散瞳 | 可変 | 眼科特有。ここが一番の差別化ポイント |
| 8 | メモの印 | 24〜120px | 📝+先頭の文字だけ |
| 9 | 待ち時間 | 56px | 段階での待ち。しきい値で文字色を変える |
| 10 | 主ボタン | 80px | 状態に応じて1つ |
| 11 | ⋯ | 32px | 検査入力 / カルテ作成 / ステータスを戻す / 取消 |

### 3-4. タブレット・スマホ
- タブレット: 同じリストで、項目5(年齢・性別)と項目8(メモ)を氏名の下の2行目に移す(1行 56〜64px)。
- スマホ: 人数チップを横スクロールにし、1行を2段にする(1段目: 番号・氏名・待ち時間、2段目: 目的・検査チップ・主ボタン)。

### 3-5. 実装で気をつけること
- 「受付からの経過」と「段階での待ち」は、両方をデータとして持ち、**表示は1つだけ** にする(athena / NextGen / OpenEMR がこの形)。
- 段階ごとのしきい値と、散瞳の規定分数は、設定画面で変えられるようにする。
- 終了者を何分後に畳むか(OpenEMR 方式)も設定にする。
- ドラッグ&ドロップは入れない(タブレットでの誤操作、多人数時のスクロールとの干渉)。状態の変更は主ボタン、⋯メニュー、カルテ・検査の操作に連動した自動遷移で行う。
