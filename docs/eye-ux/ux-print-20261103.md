## 0. 結論

1. **眼鏡処方箋は「日本眼科医会の様式そのものの紙面」にする。** 様式は **A4 縦1枚** で、上から「No. → 表題 → 氏名・年齢・性別 → Ⅰ レンズ種類 → Ⅱ レンズ値(右の行が上、PD は右端の1列)→ 軸度・基底の確認図 → Ⅲ 用法(装用目的・装用方法)→ Ⅳ 有効期間 5・10・30日 → Ⅴ その他(頂間距離12mm、多焦点の PD は遠用基準)→ Ⅵ 特記 → 年月日・医師住所・医師名・印 → 注意書き」の順 [一次]。今の画面にはこのうち **医師住所・印・No.・Ⅴ の定型文・注意書き・有効期間の書き方** がない。施設名は空で出ている(スクリーンショットで確認)。
2. **今の両画面は「画面のページ」に印刷ボタンを付けただけで、紙が見えない。** 用紙の境界、余白、ページ番号、医療機関名がない。`@page` の指定もないので、ブラウザ既定のヘッダー・フッター(URL に患者の受診 ID、日時、タイトル)がそのまま紙に出る。
3. **未確定のまま印刷すると、紙面のどこにも未確定と分かる目印が出ない(処方箋)。目印があっても小さい(カルテ)。** 処方箋は、警告が `no-print` の中にしかない。紙面には「下書き」の目印が一切出ず、正式な処方箋のように見える紙が出てしまう。**ページ全体に「下書き・未確定」の透かしを入れる**のが最優先。
4. **データの取り違えにつながるバグが3つある。** ①処方箋の医師名に `updatedBy`(最後に保存した人。視能訓練士のこともある)を使っている。②カルテ印刷の年齢が「今日の年齢」になっている(過去の版を印刷しても今日の年齢が出る)。③次回の予約日(`nextVisit.date`)が印刷されない。
5. **提案:** 共通の `PrintShell`(画面上のツールバー + 紙のプレビュー)に作り直す。ツールバーは「← カルテに戻る / 状態(確定 v2・下書き)/ 用紙 A4・A5 / 印刷・PDF保存」。紙面の側は `@page`、透かし、ページ番号、施設ヘッダーを持つ。新しい API は要らない(既存の `/bootstrap` と `/versions/:n` で足りる)。モデルに足したい項目(装用方法、レンズ種類など)は P2 の API 変更として分けた。

### 1-4. 海外の眼鏡・CL 処方の印刷
- ModMed EMA: 屈折の検査結果から光学処方を組み立て、**作ったらワンクリックで印刷** できる [二次・メーカー宣伝] https://www.modmed.com/ophthjourney/optical-shop/
- NextGen Ophthalmic Suite: 「印刷用の眼鏡処方」に最大3件まで載せられる。値はレンズメーターと屈折から取り込んで編集し、**確定後に1件ずつ印刷** する [二次・検索スニペット。本文は 403 で取得できなかった]
- Eyefinity ExamWRITER: 印刷の入口が3つある(処方欄から / 印刷アイコンで種類を選ぶ / **確定(Finalize)ダイアログで「眼鏡処方を印刷」「CL 処方を印刷」にチェックして保存**)。確定した処方には受領確認文と署名欄を付けられ、**PD を印刷するかは医院の設定** で決める。CL は2部印刷し、署名した1部を医院が保管する [一次] https://help.eyefinity.com/eehr/ftc/omew.htm
- 共通する考え方: **処方の印刷は「確定」に結びついている**(確定の操作の中で印刷を選ぶか、確定したものだけを印刷する)。下書きの印刷を前提にしていない。

### 1-5. ブラウザ印刷の技術的な前提(実装の安全性のため)
- `@page { size: A4; margin: … }` は主要ブラウザで使える。**Chrome は `@page` の margin box(`@bottom-center { content: counter(page) }`)に対応している(Chrome 131 以降)。Safari は未対応** [未検証。リリースノートの記憶による]。ページ番号は「出なくても壊れない飾り」として扱う。
- `position: fixed` の要素は、Chrome・Safari の印刷で **全ページに繰り返し描かれる**。透かしや施設のフッターに使える [未検証。経験則]。
- ブラウザ既定のヘッダー・フッター(URL・日付・タイトル)は、利用者が印刷ダイアログでオフにしない限り出る。`@page` の margin を小さく(約 10mm 以下に)すると Chrome では出なくなる [未検証]。URL には受診 ID が入るため、出さないほうがよい。

## 3. 再設計案

### 3-1. 考え方
- **画面 = 「紙を机の上に置いて見ている」状態にする。** 灰色の背景の上に、実寸比の白い用紙(A4: 210×297mm / A5: 148×210mm)を影つきで置く。ページの切れ目は印刷時にしか確定しないので、画面では **用紙の幅と余白だけを実寸で再現** し、高さは流れに任せる(ページの区切りを JS で計算するのはバグの元なので、やらない)。
- **画面の操作は全部ツールバーに集め、紙面には一切置かない。** 紙面の要素は、画面でもそのまま印刷と同じに見せる(WYSIWYG)。
- **確定と未確定は、紙でも画面でも一目で分かるようにする。** 未確定なら全ページに透かしを入れ、ツールバーにも警告の帯を出す。止めはしない(下書きを医師が確認する用途があるため)。そのかわり、ボタンの文言を「下書きとして印刷」に変える。
- **白黒・FAX・コピーで読めること。** 紙面の色は黒と灰色だけにし、ティールは画面のツールバーだけで使う。

ツールバーの仕様:
- **← カルテに戻る**: `<a href="/encounters/{id}">`。新しいタブで開いていても、普通のリンクなので確実に動く。`window.close()` は「スクリプトで開いたタブ」でしか効かず、ブラウザごとに挙動が違うので使わない。
- **表題 + 患者名**: 何を印刷しようとしているかを確かめるため。
- **状態のチップ**: `確定 v2(11/03 14:20 院長)` は灰色、`下書き` は黄。

  - 下書きのときは文言を **[下書きとして印刷]** に変え、副ボタンの見た目(枠線)にする。
  - 処方箋で blocker があるときも押せるようにしておく(下書きの確認用)。透かしが必ず入る。
- **警告の帯**: blocker を1行にまとめ(`/` 区切り、はみ出したら折り返す)、「入力欄へ→」で `/encounters/{id}#optical` に飛ぶ。アンカーが今ないなら、カルテに戻るリンクだけでよい。
- 狭い幅(< 720px): ツールバーを2段にする(1段目: 戻る・表題、2段目: 用紙・印刷)。用紙は `width: 100%` に縮め、`aspect-ratio` は付けない。

### 3-6. 透かし・ヘッダー・フッター・ページ番号

- **透かし**: `<div className="print-watermark" aria-hidden>下書き・未確定</div>` を、紙の中で `position: fixed` にして中央に置く(画面では用紙の上に重ねるため、用紙に `position: relative` を付け、`.print-watermark` は画面では `absolute`、印刷では `fixed` にする)。出す条件:
  - カルテ: `!version && encounter.status !== "finalized"`
  - 処方箋: `encounter.status !== "finalized" || !optical.issue || problems.length > 0`(未発行や不備がある紙が処方箋として使われないようにする)
- **フッター**: 患者氏名・番号・印刷日時・印刷者。`position: fixed; bottom: 0` で全ページに出す。ページ番号は `@page { @bottom-right { content: counter(page) " / " counter(pages) } }` で、対応するブラウザでだけ出す。
- **施設ヘッダー**: カルテの印刷では 1ページ目の上に置くだけにする(fixed にすると本文と重なる高さの調整が要り、バグの元になる)。
- **写しの表示**: カルテの印刷の右上に「診療録(写し)」と出す。

12. **カルテの印刷: 左右の値を1つの表に**(`colgroup` + `table-layout: fixed`)。空の行・空の節を出さない。視力を `0.9(1.2×S-1.00D=C-0.50D Ax180°)` の形の1行にまとめる(書式は `lib/format.js` に `formatVisualAcuityLine` として足す。**表記は院長に確認**)。P5 / P6 / P7
13. **カルテの印刷: `orders`(実施のみ)、眼圧の時刻、矯正の種類を出す。** P3 / P4
14. **フッター**(患者・番号・印刷日時・印刷者・ページ番号)と、`h2` / `tr` の改ページ制御。C9 / P8
15. **A5 の切り替え**(処方箋のみ)。`localStorage` で覚える。`@page` は条件つきの `<style>` で出す。

### P2(API・データモデルの変更が要る。**要相談**)
16. `content.optical` に **`wearMode`(常時・必要時)と `wearNote`、`lens`(素材・焦点・コート・カラー)** を足す。CL 用に **`schedule`(終日・時間)、`replacement`(交換周期)、`quantity`** も足す。→ `packages/eye-contracts` の `validateOptical` と、入力 UI(`encounter-sections.js`)の変更が要る。
17. **処方箋の No.(通し番号)**: 発行時にサーバーで採番する(`opticalIssueNumber`)。今は `encounterId` の一部を出すくらいしかできず、意味がない。
18. **医師の表示名と「役割の付いた表示名」を分ける**: スクショの「院長(管理者・医師)」のように、`displayName` に役割が入っている(またはデモデータの問題)。紙には **医師氏名だけ** を出したい。`finalizedBy` に `doctorName`(医籍の氏名)を持たせるか、スタッフのマスタに氏名の項目を足す。
19. **施設の住所・電話を bootstrap で確実に返す**: 今の `facilitySnapshot` は `address` / `phone` を持っていない。`documents.js` は `facility.address` を読んでいる。bootstrap の施設に住所が入っているか確認し、なければ返すようにする。

### P3(新しい機能)
20. **2号紙形式(見開き)のレイアウト**(1受診分は API 不要。期間を指定した一括出力は、受診の内容をまとめて返す API が要る)。開示請求用に「写し・印刷日時・出力者」を必ず入れ、**出力したことを監査ログに残す**(API 変更)。
21. 軸度・基底の確認図の SVG(まず白紙の図、線を引くのは向きを確かめてから)。
22. 処方箋を確定するときに、ダイアログで「眼鏡処方箋を印刷する」を選べるようにする(Eyefinity と同じ流れ)。

### やらないこと(バグを招きやすいので)
- JS で改ページの位置を計算して、画面に「1ページ目 / 2ページ目」を描くこと。フォントや印刷ダイアログの倍率で必ずずれる。
- ◯で囲む選択肢を CSS の絶対位置で重ねること。■/□ で表す。
- `window.close()` の「閉じる」ボタン。
- サーバーでの PDF 生成(今回の範囲外。日本語フォントの埋め込みと、版との整合で別の設計が要る)。
