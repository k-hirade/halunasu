## 0. 結論(要点)

1. **競合の会計の入口は「受付一覧の状態(算定待ち・会計待ち)+行の右端の1ボタン」**。会計専用の「1日分の縦長カード一覧」を持つ製品は確認できなかった。CLINICS は 受付一覧の「算定待ち」行の [算定] → 算定確定 → [請求へ] → [確定] で「会計待ち」に変わる [確認]。Henry は受付の「会計待ち」タブから入る [確認・既存]。
2. **カルテ修正後の扱いは、どこも「差分を見せて、明示的に取り込ませる」**。Henry は赤字の「変更あり」で確定をブロックし、[会計に取込] で解消 [確認・既存]。CLINICS は [カルテ内容を反映] ボタンで反映し、「漏れ・余分がないか確認」を求める [確認]。日レセ API の中途データは **変更(class=03)は前回データの置換(削除→追加)** であり、日レセ側で展開・編集済みだと置換できない [確認]。
   → **当システムの CSV は「置換」ができない。再連携した CSV をそのまま取り込むと、レセコン側で二重登録になりうる**。だから「何が変わったか」を事務に見せることが、この画面の最重要機能になる。今はそれがない。
3. **現行画面の大きな問題**(詳細は §2)
   - **[高] 再連携が必要な患者でも「何が変わったか」が出ない**(タグと枠色だけ)。
   - **[高] 修正のために医師がカルテを開くと、連携済みの患者が一覧から消える**(status が draft に戻るため)。上部の「未確定のカルテが n 件」に混ざり、新規の未確定と区別できない。
   - **[高] 再確定すると、実施内容が同じでも必ず「再連携が必要」になる**(指紋に `versionCount` が入っている)。誤警告は「黄色を無視する癖」を作る。
   - **[高] 初期選択に「再連携が必要」が含まれ、主ボタン1回で再出力される**。二重登録の入口になる。
   - **[高] 「この日のすべてを CSV で再出力」は連携済みも含む全件 CSV を、確認なしで出す**。主ボタンの隣に同じ重さで並ぶ。
   - **[中] 会計連絡票の印刷が「画面の全カードを流し込むだけ」**。見出しも医院名もなく、日付は最後に小さく出るだけ。1人1枚にならず、選択も効かない。
   - **[中] 一覧が「1患者=縦長カード+7列の表」**。2品目で約210px。30人で 6,000px を超える。状態ごとの人数もない。
4. **提案**: 受付画面の再設計(状態で区切った1本のリスト、人数チップ、1行1患者)と同じ文法にそろえる。グループは **要再連携 → 未連携 → 修正中・未確定 → 連携済み(畳む)**。各行には **品目の要約(「検査3 処方2 文書1」)と、変わった品目の差分チップ** を出す。主ボタンは「未連携を CSV 出力」1つに絞る。再連携は差分を見て行ごとに行う。印刷は「1人1枚の連絡票」にする。
   API の変更は **2点が必須、1点が任意**: (a) 連携時に品目のスナップショットを保存して差分を返す、(b) 指紋から `versionCount` を外す(旧データは互換で扱う)、(c) 任意: 連携回ごとの CSV を再取得できるようにする。

## 1. 競合調査

### 1-1. CLINICS カルテ(メドレー) [確認]
- 出典: 「会計画面の開き方から入金額確定まで」https://intercom.help/clinics/ja/articles/8290036 、「会計を修正する」https://intercom.help/clinics/ja/articles/8296969 、「会計プロセス改善(2026年7月)」https://intercom.help/clinics/ja/articles/15885890 、「診察完了後にカルテ画面を修正する」https://intercom.help/clinics/ja/articles/3591905 、「会計画面で発生する警告やエラー」https://intercom.help/clinics/ja/articles/7877825
- **入口と状態**: 診察が終わると、受付一覧で **「算定待ち」**。行の右側の **[算定]** → 算定確定画面(保険の組合せ、診察区分、自動算定の項目を確認・編集) → 右下の **[請求へ]** → 請求額を確認して **[確定]** → **「会計待ち」** → 行右側の **[会計]** → [会計処理] で [登録]。**状態は操作に連動して自動で進む**。
- **カルテ修正後**: 「カルテ修正・保存後は、会計の修正も行ってください」(運用で担保)。会計画面の **[カルテ内容を反映]** で反映する。「漏れや余分がないか」を人が確認する。請求額が変われば「未収金」「過入金」として差額を出す。
- **エラーと警告**: 会計画面で「エラー」と「警告」を区別する。受付一覧にも「会計エラー」を赤字で出す [確認・既存調査]。
- **2026年7月の改善**: 確定時の **最終確認ポップアップを廃止**。明細書発行などのチェックボックスを **[確定]/[登録] ボタンのすぐ隣** に移した。注意は「入力欄の近くのメッセージ」や「画面上部の警告」で出す。→ **確認ダイアログを重ねるより、ボタンの隣で状態を見せる** 方向に動いている。
- **印刷**: 「診療費明細書を発行」のチェックと、後からの [帳票印刷]。

### 1-2. Henry 外来会計 [確認・既存調査の再掲]
- 受付の「会計待ち」タブ → [計算・請求]。**左に当日のカルテと過去の会計、右に請求の編集** の左右分割。
- カルテ側に変更があると、左の「会計」タブに **赤字の「変更あり」** を出して **確定をブロック**。**[会計に取込]** で差分を取り込むと消える。**[初期化・再取込]** は手で直した分が消える(と明記)。
- 自動算定の項目に **★**。右下に **[確定して請求]**。
- 一括操作、印刷の詳細: **[未確認]**。

### 1-3. 日医標準レセプトソフト(ORCA / WebORCA)の中途データ [確認]
- 出典: API 一覧 https://www.orca.med.or.jp/receipt/tec/api/overview.html 、中途データ API https://www.orca.med.or.jp/receipt/tec/api/medicalmod.html
- `/api21/medicalmodv2`: **class=01 登録 / 02 削除 / 03 変更 / 04 外来追加**。登録すると `Medical_Uid` が返る。変更と削除にはこの uid が要る。
- **変更は「uid のデータを削除し、要求内容に置き換える」**。条件は「日レセにて送信したデータを展開および内容変更していない場合に限り」。展開・編集済みなら置換できない(エラー 31/33「内容が更新されている可能性」)。
- 同日の診療データが既にあると「既に同日の診療データが登録されています」。
- 中途終了患者の一覧は `/api01rv2/tmedicalgetv2`。受付一覧は `acceptlstv2`(受付中/受付済み/全受付)。
- OpenDolphin(CLAIM 連携)は「算定は ORCA の責任」とし、カルテ保存時に送信、ORCA 側は **[中途表示]** で受けた内容を見る [二次: https://gist.github.com/dolphin-dev/c75e4ca63689779bfdf7]。
- **示唆**: レセコン側の正しい再送は「前回分の置換」。CSV 方式の当システムは置換できない。そのため、**事務が日レセで前回分を直すための「差分」と「前回の版」を画面と連絡票に出す** のが現実的な代わりになる。将来 API 連携するなら、`Medical_Uid` を連携記録に保存する設計にしておく(今回はやらない)。

## 3. 再設計案

### 3-1. 方針
1. **受付の再設計と同じ文法にする**: 上に人数チップ、状態で区切った1本のリスト、1行1患者、右端に1ボタン、行を押すと詳細が開く。
2. **例外を上に**(Epic の考え方): グループの順番は **要再連携 → 未連携 → 修正中・未確定 → 連携済み(初期は畳む)**。
3. **差分を出す**: 要再連携の行に「+追加」「−削除」「~変更」のチップを出し、開くと前回と今回を並べて比べられる(Henry の「変更あり」+取込、CLINICS の「漏れ・余分の確認」に当たる)。
4. **一括で出すのは「未連携」だけ**。要再連携は差分を見て、行ごとに [再連携] する(二重登録を防ぐ)。
5. **全件 CSV は「⋯」の中に移し、注意文を付ける**。
6. **連絡票は1人1枚**にし、印刷の対象を明示する(選択した患者 / この行だけ)。

### 3-6. 操作
- **初期選択 = 未連携の全員**(今と同じ考え方。ただし要再連携は含めない)。グループ見出しの [☑ 5人すべて] で全解除・全選択する。行のどこを押しても選択が切り替わる(▾ とリンクを除く)。
- **主ボタン「CSV を出力して連携済みにする」**: 選択した未連携の人だけ。押すと今と同じ `POST /v1/eye/billing/handoffs`。終わったら、その人たちが「連携済み」へ移ったことを1行の通知で示す(「5人を連携済みにしました。CSV: eye-billing-2026-11-03-a1b2c3.csv [もう一度保存]」)。[もう一度保存] は、その場で返ってきた `payload.csv` をメモリに残しておき、再ダウンロードする(API の変更なしでできる。ページを離れたら消える)。
- **再連携**: 行ごとに [差分を見る] → [この人だけ CSV を出力して再連携]。`encounterIds` を1件にした同じ API を使う。確認ダイアログは出さず、ボタンの直上に注意文を常に出す(CLINICS 2026 の方式)。
- **全件 CSV**: 「⋯」→「全件 CSV(確認用)」。メニューの中に「連携済みも含みます。レセコンへの取込には使わないでください」と書く。`busy` 中は押せない。
- **連絡票の印刷**: 「選択した n人」「この人だけ」「この日の全員」(⋯ の中)の3つ。どれも1人1枚。
- **日付を変えたら** `error` と `notice` を消す。読み込み中は前の日のデータを消す(今と同じ)。
- **キーボード**: `J/K` で行の移動、`Space` で選択、`Enter` で開く。受付の割り当てに合わせる(受付側で決まっていなければ見送る)。

### 3-10. 事故を防ぐための注意(実装時)
- 差分のキーに配列の順番(`index`)を使わない。同じ薬が2行あるときは「名称+眼+用法」まで含めて比べ、それでも同じなら件数で比べる。
- 選択の状態は `encounterId` の Set のまま。再読み込みのとき、選んでいた人が `pending` でなくなっていたら外す(今の「読み込みのたびに全部選び直す」動きは、操作の途中で選択が変わるので、連携の後だけ選び直す)。
- 印刷の対象の切り替えは、印刷の後に必ず元に戻す(`afterprint` と、念のため `setTimeout` による戻し)。
- 新しい `itemsFingerprint` の計算は、品目を作る関数と同じ正規化(並び順・空文字・null)を通す。テストで旧と新の両方の記録を確かめる。
