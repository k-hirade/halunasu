# 患者ページ・画像の比較 UX 調査と再設計案（2026-11-03）

対象: `/patients/[id]`（`components/patient-chart.js` / `trend-chart.js` / `files-panel.js` / `documents-panel.js` / `patient-banner.js`）、`/patients/[id]/images`（`components/image-compare.js`）、`app/globals.css`
見た画面: `scratchpad/pages-now/patient-*.png`、`images-*.png`（5幅）、`metrics.json`
注意: デモ患者（模擬 和子 D003）にはファイルが0件のため、画像の比較は空の状態しか撮れていない。比較表示の中身はコードから判断した。

## 0. 結論（要約）

1. **医師が最初に知りたいことが一番上にない。** 欲しいのは「前回の値と方針」「今日までの経過」「前回までの受診」。ところが受診歴（カルテ履歴）は、1440幅でも右列の最下部（y≈1240、ファーストビューの外）にある。1024幅以下では1列になり、y≈1650/2519 まで下がる。
2. **同じ情報が3回出ている。** 病名は「患者帯のチップ」「現在の状態の病名」「履歴の各行（同じ文が3行続く）」に出る。逆に、受診ごとの視力・眼圧はグラフにホバーしないと読めない。
3. **グラフの効率が悪い。** 4点しかないのに、幅1000pxのグラフが2枚あり、高さは計420pxになる。0.01〜2.0の対数軸と0〜30の眼圧軸で、縦の大半が空白になっている。点眼の開始・中止はグラフの下に文章で並ぶだけで、グラフと同じ時間軸にない。目標眼圧の帯はなく、21の破線にはラベルもない。390幅では日付ラベルが重なって読めない。
4. **右列の大半が「たまにしか使わない操作」で占められている。** 取り込みフォームは0件でも常に開いていて、高さは約330px。文書作成ボタンが4つある。データの出力（開示・移行用）は年に数回しか使わない。そのうえ「取り込む」が緑の主ボタンになっていて、ページの主操作「本日のカルテを開く」と競合している。
5. **画像の比較が「比較ビューア」になっていない。** 選び方はプルダウン2つだけで、サムネイルも時系列もない。左右で「前のもの / 次のもの」に送る操作もない。患者帯（アレルギー）が出ない。戻るリンクのラベルが「← カルテ一覧」なのに、実際の行き先は患者ページ（不具合）。

再設計の方針は、受付で好評だった考え方をそのまま当てはめる。**1行の行、情報の刈り込み、主操作は1つ、色は状態だけに使う。**
患者ページは「患者帯 → 1行の現況ストリップ → 経過表（グラフ＋受診ごとの行。カルテ履歴と点眼の変更を統合）」を主列に置く。右列は「予約・画像サムネイル・文書」の一覧だけにする。作成・取り込み・出力は、ボタン1つかメニューにしまう。

### 1.2 眼科 EHR（海外）

- **Nextech Glaucoma Flowsheet** [宣伝 2020, biospace]
  - 1ページに「**眼圧・点眼・C/D比・処置**」の表がある（カスタマイズとフィルタ可）。
  - **拡大した眼圧グラフ**に「関連する点眼と処置のデータ点」を重ね、「**目標眼圧の範囲内にあるか**」を見られる。
  - 同じ画面に、リスク因子・**直近の検査日**・治療計画・画像（表示する種類を選んで当日と比較）がある。
  - 印の具体的な描き方と、目標眼圧の設定方法は公開資料にない [未確認]。
- **紙の緑内障フローシート（Review of Ophthalmology, 臨床医の実践例）** [一次: 臨床記事]
  - **1受診 = 1列**で、6回分を横に並べる。各列の上には日付と時刻、最後に点眼した時刻、視力がある。
  - **眼圧グラフはその上**に描き、その下に「その受診で開始した薬」の行を**受診の列にそろえて**置く。こうすると「上のグラフで薬への眼圧の反応が見える」。
  - 左端に「試した薬」の縦リストがあり、反応や副作用を略号で付記する。
  - 下段の行には、その回に行った検査（散瞳・画像を色の枠で区別）、評価、次回に予定する検査がある。
  - 目標眼圧は欄として固定せず、「**毎回の動的な判断**」を推している。
  - → 「**グラフと薬の変更を同じ時間軸にそろえる**」ことと「**受診ごとの値を表で読める**」ことが要点になる。
- **ModMed EMA**: 「主要な疾患指標を1画面で概観」[宣伝]。眼圧グラフや目標眼圧の具体像は**見つからない [未確認]**。
- **Epic Kaleidoscope**: 緑内障などのワークフローとテンプレートがあり、機器と連携する [宣伝・二次]。フローシートの画面は**ログインが必要で未確認**。患者をまたいで検査を一括判読する「Imaging & Procedures Home」がある [確認: アイオワ大 Epic 研修サイト、前回調査]。

### 1.3 画像ビューア・比較

- **OptosAdvance（比較の手順書）** [確認: 公式 PDF G-109989]
  - 前回の検査があると、**ツールバーの下に時系列（タイムライン）**が出る。
  - 「Prev/Next」かキーボードの→で、**当日と直近の前回を自動で左右に並べる**（Hanging Protocol）。
  - 「HP Priors Scrolling」の Forward で、**右側のビューポートだけを過去へ送る**。タイムラインの**番号付きの丸**とビューポート右下の番号で、どの日付が出ているかを対応させる。
  - 3枚以上はレイアウトを 1×3 などに変え、拡張タイムラインの**サムネイルをドラッグしてビューポートに入れる**。OD/OS はツールバーで切り替える。
- **Eyefinity EHR（画像管理ヘルプ）** [確認: 公開ヘルプ]
  - サムネイルをクリックすると全画面になる。「Filter: All Files」と検索がある。**検査機器×日ごとの「プルーフシート」**でまとめて見る。
  - **Compare で左右2面**になり、各面の上のプルダウンで画像を差し替える。**Sync で左右のスクロール・ズーム・送りを連動**させる。
- **ZEISS FORUM / Glaucoma Workplace**
  - 視野と OCT を1枚の構造・機能レポートにまとめる。進行は「Possible / Likely Progression」という**平易な言葉の警告**で出す。MD・VFI と**眼圧のグラフを1レポートで比較**する [宣伝]。
  - iPad の Viewer には画像・レポートを左右に並べる比較モードがあり、**縦積みと左右並べを切り替え**られる [宣伝]。
  - 比較から**ベースラインを外せる**（2014年の業界誌）。
  - 画面の細部は [未確認]。
- **Topcon Harmony**: 「Timeline View で検査履歴を見て画像間を移動」、「単一画面に全臨床データ」[宣伝]。サムネイル帯の具体像は [未確認]。

→ 比較ビューアに**共通する最小の型**は次の5つ。
1. **時系列のサムネイル（またはタイムライン）**
2. **既定で「最新 vs 前回」を左右に並べる**
3. **片側だけを前後に送る**
4. **どちらの面に何日のものが出ているかを常に表示**
5. **右眼/左眼の切り替え**

Sync ズームは上位製品（Eyefinity・Optos）にはあるが、必須ではない。

### 1.4 調査から導いた設計の原則

1. 患者ページで最初に見せるのは「**前回の値（左右）・処方中・方針・次回**」。病名は患者帯にあれば足りる（再掲しない）。
2. **経過は「グラフ＋受診ごとの行」を1つのブロックに**する。薬の変更は同じ時間軸に印を付け、行にも書く（紙フローシート・Nextech）。
3. **過去回は1行の時系列リストにし、クリックで開く**（CLINICS）。行には**その回の左右の視力・眼圧と処方の変更**を出す（同じ病名の繰り返しは出さない）。
4. 目標眼圧の帯は「緑内障患者の価値の中心」（Nextech）。ただし**データモデルにない → API 変更が必要**。
5. 画像は「**サムネイル帯 → 最新 vs 前回 → 片側を送る**」。
6. 作成・取り込み・出力は**ボタン1つ（ダイアログ）かメニュー**にする（国内製品は作成フォームを常時出していない）。

- **1024×768（iPad 横向き）**

### 3.8 バグ回避の注意

- `VisitTable` の結合は `encounterId` で行う（`trend.points` には encounterId がある）。点眼の変更は、A3 が入るまで日付で結合し、同日に2件あれば両方の行に出す（誤って欠けるよりは重複のほうが安全）。
- 前回差の計算は「確定済みで値がある直前の点」と比べる。null を飛ばさないと「↓14」のような誤表示になる。
- y 軸をデータ依存にするときは、点が1つだけ・全部同じ値のケースで幅0にならないよう、最小幅を確保する（IOP は最小10mmHg 幅、VA は最小1段）。

- `StatusTag` の変更は受付やホームにも効く。v1 を消す場合は、全画面のスクリーンショットで確認する。
