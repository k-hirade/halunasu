## 受付・予約の画面が読む API（reception への申し送り）

すべて追加の API で、従来の動きは変えない。保存が無いときは既定の値を返す。

- `GET /v1/eye/bootstrap` に追加: `clinicConfig: { receptionLabels, clinicHours, printSettings, otherSettings }`（どれも値そのもの）と、`orderCatalog` の末尾に院内検査項目（`code: "lab:<itemId>"`, `source: "clinic"`）。
- `GET /v1/eye/clinic-config` → `{ clinicConfig: { <項目>: { value, revision, updatedAt, updatedBy } } }`（眼科の役割を持つ全員）。
- `GET /v1/eye/clinic-config/<項目>` → `{ section, value, revision, updatedAt, updatedBy }`。項目: `docTemplates` `labLists` `receptionLabels` `clinicHours` `printSettings` `otherSettings`。知らない項目は 404（古い API も 404 なので、画面は 404 を「未対応」として扱う）。
- `PUT /v1/eye/clinic-config/<項目>` `{ expectedRevision, value }`（管理者・CSRF 必須）。版が違えば 409。操作記録は `eye.clinic_config_saved`（設定の種類、名前や本文は残さず件数だけ）。
- `receptionLabels.value`:
  - `labels: [{ labelId, name(≤20), tone: "teal"|"blue"|"amber"|"red"|"gray", active }]` … 受付メモに付けるラベル。受付の記録には `labelId` を持たせる（名前を変えても ID は同じ）。`active: false` は新しく付ける候補に出さないだけで、付いている記録は表示を続ける。
  - `marks: [{ markId, name(≤20), symbol(1〜2文字), tone, active }]` … 氏名の横のマーク。
- `clinicHours.value`: `{ slotMinutes: 10|15|20|30|60, days: { mon|tue|wed|thu|fri|sat|sun|holiday: [{ from: "HH:MM", to: "HH:MM" }] (各 3 つまで・重なりなし・時刻順), note }`。全部空なら未設定（`lib/admin.js` の `hasClinicHours`）として従来の 8〜18 時を使う。
- 経営データ集計: `GET /v1/eye/reports/visits?from=YYYY-MM-DD&to=YYYY-MM-DD[&includeMemo=1]`（管理者）→ `{ report: { range, totals, days[], months[], visits[] }, generatedAt }`。出力は操作記録 `eye.report_exported`（種類「出力」）。
- 文書雛形の差し込み: `POST /v1/eye/documents/:id/apply-template` `{ expectedRevision, templateId }`（文書の権限・CSRF、下書きだけ。確定済みは 409）。
- 医療機関情報 `PUT /v1/eye/facility-settings` に任意の欄 `nameKana` `representative` `representativeKana` `prescriptionRoute`（"outside"|"inside"） `invoiceRegistrationNumber`（T + 13 桁）。

## platform-api の変更（デプロイは院長の承認が必要）

- `services/platform-api/src/store/memory-store.js`・`firestore-store.js`: 利用者の一覧（`GET /v1/organizations/:orgId/members`）の各利用者に、ログインの識別情報から `lastLoginAt` と `passwordUpdatedAt` を添える。読むだけで、利用者の記録には保存しない。パスワードのハッシュなど識別情報のほかの値は出さない。テスト: `services/platform-api/test/member-activity.test.js`。
- 利用者の登録・役割・無効化・パスワードのリセットは、既存の `POST/PATCH /v1/organizations/:orgId/members` をそのまま使う（契約の管理者 `org_owner`/`org_admin` の権限・CSRF・最後の管理者を無効にできない、は既存の判定のまま）。
- 画面は基盤の一覧が読めないとき（権限なし・古い API）は、以前と同じ「印刷用の氏名だけ」の表に戻る。日時の列は値が無ければ「—」。

## 写さなかったもの（理由）

- 労災・自賠、電子処方箋、共通パスワード設定、RME 通知、データ提出加算、連携（ORCA）、警告管理、サポート依頼ログ: 保険・算定・外部サービスで、レセコンや契約の基盤の担当（院長の決定: 保険・算定は範囲外）。
- ログインログ: ログインの記録は契約の基盤（platform）の監査にあり、眼科の操作記録には無い。利用者管理の「最終ログイン」で代わりにする。
- 証明書: 文書の「診断書」と文書雛形で作れる。
- 添付ファイル使用量: 全患者のファイルを読む集計が要り、今の保管の API では重い。見送り。
- 会計（点数・負担金・入金・調整金・一括再計算 R p.177）、トプコンの算定入力（50）: 算定はレセコン（範囲外）。
- 帳票の PDF を別タブで開く（53）: 紙面のプレビューの形だけを写し、PDF は作らない。
- ヘッダーの Q&A 検索・チャット・お知らせ: 該当する機能が無い（作り物になるので出さない）。
- 利用者メニュー（63）・パスワード変更（64）: 形が同じ。
