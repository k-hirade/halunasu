## 0. 結論(要点)

1. **今いちばん大きいのは見た目より「直せない」こと。** よく使う薬剤と定型文は **追加と停止・再開しかできない**。名前の誤字、滴数、用法、定型文の本文は直せない(UI に編集の入口がない)。API はもともと `presetId` / `phraseId` を付けた上書き保存(upsert)に対応しているので、**API を変えずに直せるようにできる**。競合はどこも編集できる(CLINICS は鉛筆、デジカルは[編集])。
2. **表の列が多すぎて、読む情報が埋もれている。** 薬剤の表は8列で、1440px では「用法」列が全行「—」、「状態」列には全行に緑の「使用中」タグと「停止」ボタンが並んでいる。1行の中で目に入るのはこの緑のタグで、肝心の薬剤名と既定値ではない。390px では薬剤名が1行2〜3文字に折れ、1行が 150px 以上になり、「状態」列ははみ出している。
3. **競合の型は「左に一覧(フォルダ・検索)、選んだ1件を右または別画面で編集」。** CLINICS と デジカルはセットを **フォルダ** で分け、**検索** し、**並び順を決められる**(デジカルはドラッグ、CLINICS は名前の頭に番号)。CLINICS はラベル(最大4つ)で絞り込み、初期表示はスタッフごとに保存する。Epic は「施設のセット」と「自分版(User version)」「お気に入り」を分けている。
4. **操作記録は「いつ・誰が・誰の」で絞れるのが最低限。** デジカルの監査ログは日付を選んで「いつ・誰が・誰の情報に」を表示し、ログインログとは別に分けている。CLINICS は年月日を指定して表示し、列は 時刻・操作・ログインID・利用者名・患者ID・患者名。今の Halunasu は **直近200件をまとめて取得し、自由文1つで絞るだけ**。期間を指定できず、「200件より前」は見る方法がない。対象(どの薬剤・どのセット)も出ない。
5. **提案:** ①5タブを **左の縦ナビ(2グループ)** に変える ②薬剤と定型文は **「1行1件の詰まった一覧 + 右の編集パネル」** に統一し、セットも同じ型に寄せる ③停止中は一覧の末尾に **畳んだグループ** として置き、タグの列は消す ④操作記録は **期間・種類・担当・患者のフィルタ行** と、対象の名前の表示を足す。①〜③と④の一部は **API を変えずに** できる。並び順の保存、操作記録のサーバー側の絞り込み、医師が自分でセットを作る権限は **API の変更が必要**(§4)。

## 1. 競合調査

### 1-1. CLINICS カルテ(メドレー)

**セット登録・編集** [確認] https://intercom.help/clinics/ja/articles/5486693
- 入口はカルテ画面右側の「セット」パネル。「新規作成」(空から)と「**カルテ内容で作成**」(今のカルテの内容を初期値にする)の2つ。
- 編集は対象セットの「︙」→「編集」。セット作成画面の中で、別のセットの「︙」→「編集」を選ぶと **同じ画面のまま編集対象が切り替わる**。
- 項目: フォルダ(プルダウン。「＋」でその場で追加、未選択でも可)/セット登録名/主訴・所見(リッチテキスト)/傷病名/処置・行為。右上に「基準日」がある(その日に有効なマスタだけを候補に出す)。
- ボタン: 「作成」/「上書き保存」/「**続けてセットを作成する**」/「診察画面に戻る」。上書き保存の前に確認画面が出る。保存しないで離れようとすると「破棄して進む」の確認が出る。
- 基準日に無効になっている診療行為があると「有効期限外の診療行為です」と警告する。
- 削除・無効化の方法は記事にない [未確認]。

**並び順** [確認] https://intercom.help/clinics/ja/articles/3595360
- セット・主訴所見テンプレート・ラベル・シェーマ・書類フォルダは **名前順** で並ぶ。順番を決めたいときは **名前の頭に「01.」などの番号を付ける** よう案内している(画面上の並べ替え操作はない)。→ 利用者の負担が大きい方式で、**競合の弱点**。

**セットの検索・絞り込み** [確認] https://intercom.help/clinics/ja/articles/15643040 / 15867738
- セットパネルの上部に検索欄。セット名・処置行為名・主訴所見・傷病名を部分一致で検索し、**ひらがなでカタカナのセット名も当たる**。
- 診療行為グループのアイコン(投薬・検査・画像・注射など)を押すと、その種別を含むセットに絞り込む。
- **フォルダラベル**(色付き、医院で自由に作成、1フォルダに最大4つ、**ドラッグで並び替え**)。複数選ぶと AND 条件。「リセット」で解除。
- 「初期表示」(開いたときのラベル絞り込みとフォルダの展開状態)を **スタッフごとに保存** できる。ラベル作成には「マスタ管理権限」が必要。

**主訴・所見テンプレート(= 当社の定型文)** [確認] https://intercom.help/clinics/ja/articles/2892084
- 項目は「テンプレート名」「フォルダ」「内容(リッチテキスト)」。「カルテ内容を反映」で今のカルテから作れる。**鉛筆マークで編集**。一覧で名前にカーソルを合わせると **内容の一部をプレビュー** する。

**ログ管理** [確認] https://intercom.help/clinics/ja/articles/11142991
- 「ログインログ」と「操作ログ」の2種類。**年月日を指定して「表示する」**。
- 操作ログの列: 時刻 / 操作 / ログインID / 利用者名 / 患者ID / 患者名。操作の種類は 患者登録・受付・キャンセル・カルテ参照・カルテ保存・診察完了。
- 担当・操作・患者での絞り込み、CSV 出力、保存期間は記事にない [未確認]。

**データ出力** [確認] https://intercom.help/clinics/ja/articles/4005831
- 期間と端末の OS を選んで出力する。**サーバー側で非同期に作り、終わったらメールで知らせる**(画面を開いておく必要はない)。2号用紙は1回8日分まで。完了後一定時間でファイルが消える旨の注意がある(12時間と読めたが、要再確認)。

### 1-2. エムスリーデジカル [確認] 操作マニュアル(ORCA連動版) https://digikar.m3.com/documents/digikar_manual.pdf
- **セット登録(p.90〜93):** カルテに入力した内容から[セット登録]。セット名と **格納フォルダ** を選ぶ。フォルダは **親フォルダを指定して階層にできる**(例: 内科セット > 投薬)。傷病名も[＋]で検索して入れられる。保存すると **セットタブの先頭に追加**。
- **並び替え(p.92):** フォルダやセットの先頭にあるつまみを **ドラッグ&ドロップ** で並べ替える。
- **セット編集(p.93):** セットタブの[編集] →「現在のカルテで上書き」にチェックして保存(カルテ画面で直してから上書きする方式)。
- **定期登録(p.94):** 患者専用のセット。表示頻度を「次回 / 毎回 / ○ヶ月毎」から選ぶ。
- **学習リスト(p.83):** カルテに入力した内容を自動で学習し、**よく使う順に表示**する。6件を超えると件数を出し、カーソルを合わせると全部を出す。
- **マスタラベル(p.85〜86):** 診療行為・検査・医薬品マスタに独自のラベル(色付き、3つまで)を付け、検索画面とカルテ画面に出す。用途の例は「在庫がない薬」「算定に注意する検査」「**医薬品の換算メモ(1本=10mL 等)**」。
- **マスタ管理(p.204):** 医薬品などのマスタは **ORCA で作り、デジカルでは[更新]で取り込むだけ**。
- **監査ログ(p.198):** 施設管理 →「監査ログ」→ **日付を選ぶ**。「いつ」「誰が」「誰の」情報にアクセスしたかを表示する。ログインログ・サポート依頼ログ(リモート操作を許可した記録)とは画面を分けている。受付の編集履歴の詳細は約45日で消える(p.63)。

### 1-8. 医薬品マスタ(YJ コード等)

## 3. 再設計案

### 3-1. 方針
1. **タブをやめて左の縦ナビにする(≥1024px)。** 2つのグループに分ける。
   - 「カルテ入力の候補」: よく使う薬剤 / セット / 定型文
   - 「管理」(管理者だけ): データ出力 / 操作記録
   将来の設定項目(受付の待ち時間しきい値、散瞳の分数、医院情報など)が増えても破綻しない。項目名の右に件数(`薬剤 10`)を出す。
2. **マスタ3つ(薬剤・セット・定型文)を同じ型にそろえる:「一覧 + 右の編集パネル」。**
   - 一覧は1行1件、高さ 40px、**読むための列は3〜4つまで**。
   - 行を押す → 右に編集パネルが開く(1440 では一覧の右に並べる。1024 以下では右から重なる)。
   - 新規も同じパネル(「＋ 薬剤を追加」で空のパネルが開く)。
   - **表の行の中で直接編集(インライン編集)はしない**。保存のタイミングがあいまいになり、数値の途中入力で保存されるなどの不具合を生みやすい。パネルの[保存]で1回だけ保存する。
3. **停止中は一覧の末尾に畳んだグループ「停止中 (n)」として置く。** 使用中のタグの列は消す(使用中なのが普通なので印を付けない)。停止と再開はパネルの中に置き、一覧には出さない。
4. **検索を全マスタに付ける**(一覧の上。かなとカナを同じに扱う。名前・用法・本文を対象)。種類(点眼/眼軟膏/内服/注射/その他)・差し込む欄でチップで絞り込む(受付の `flow-chips` と同じ見た目)。
5. **数値は右揃え・等幅。** 既定値は1つの文にまとめる(`1日4回 ・ 5mL/120滴`)。
6. **操作記録は「フィルタ行 + 詰まった表」。** 期間・種類・担当・患者を別々に絞れるようにし、対象(どの薬剤か、どの患者か)をリンクにする。
7. **タブ(項目)を URL のハッシュに残す**(`/settings#sets`)。カルテの空表示から目的の項目へ直接飛べる。`useSearchParams` は Suspense が必要になり不具合のもとなので、ハッシュで十分。

- 1行 36px の詰まった表。日時は等幅で `MM/DD HH:mm`(年は期間が年をまたぐときだけ)。
- **種類のチップ** は `EVENT_LABELS` のキーから機械的に分類する(`_viewed`=閲覧、`_created/_updated/_saved/...`=作成・更新、`_finalized`=確定、`_exported`=出力、`drug_preset/order_set/phrase`=設定)。対応表を1か所に置き、未知のイベントは「その他」に入れる。
- **対象・内容** は API の変更なしで出せる:
  - `targetType` が drug_preset / order_set / phrase → 画面が持っている薬剤・セット・定型文から `targetId` で名前を引く(消えたものは「(削除済み)」ではなく ID の先頭だけ出す。本システムは削除がないので基本は引ける)。
  - `safePayload.patientCount` / `encounterCount` / `date` → 「患者 N 人」「11/03 分・N 件」。
- 患者名は患者カルテ(`/patients/[id]`)へのリンク。
- 「担当」の氏名は今の API では取れない(loginId だけ)。→ A3(§4)。それまでは loginId のまま。
- **期間・担当の絞り込み** は、今は **取得済みの200件の中だけ** でしかできない。誤解を防ぐため、API が対応するまでは期間の入力欄を出さず、「表示中: ○○ 〜 ○○ の N件(直近200件)」をはっきり出す(A7 の対策)。API 対応後に期間欄と「さらに読み込む」を出す。
- CSV 保存は、表示中の行をそのまま書き出す(クライアントだけで可能)。書き出した事実も記録すべきなので、本当は API で記録を残したい(A4)。最初は入れずに後回しでもよい。

### 3-7. 1024px
- 左ナビは幅 56px のアイコン+短いラベルに縮めるか、上部の横並び(今のタブと同じ位置)に戻す。**おすすめは上部の横並び**(アイコンを新しく作らずに済む)。
- 一覧は全幅。編集パネルは右から重なるシート(幅 440px、背景を薄く暗くする)。既存の `.dialog-backdrop` に近いが、中央ではなく右寄せ。
- 操作記録の「対象・内容」列は2行目に回す(行 52px)。

### 3-8. 390px
- 上部のナビは `<select>` 1つ(「よく使う薬剤 ▾」)にする。横スクロールのタブは隠れる項目が出るのでやめる。
- 一覧は **カード状の2段の行**(56〜64px):
  ```
  ┌──────────────────────────────────────┐
  │ オロパタジン点眼液0.1%          点眼 ›│
  │ 1日4回 ・ 5mL/120滴                   │
  ├──────────────────────────────────────┤
  │ 低濃度アトロピン点眼液0.01% [院内] 点眼 ›│
  │ 1日1回 ・ 5mL/120滴                   │
  └──────────────────────────────────────┘
  ```
- 行を押すと全画面の編集シート(上に「‹ 戻る」と「保存」)。
- 検索欄は一覧の上に全幅。チップは横スクロール(端をフェードさせて続きがあると分かるように)。
- 操作記録は1件2段(1段目: 時刻・操作、2段目: 担当・患者・対象)。

### 3-9. 操作の細部(不具合を生まないための決めごと)
- **保存は1か所(パネルの[保存])。** Enter は単一行の入力でだけ保存、textarea では改行。
- 保存が成功したら: パネルを閉じず「保存しました」をパネルの中に2秒出す(画面上部の通知は使わない)。一覧はサーバーの返り値でその1件だけ差し替える(`load()` で全部を取り直さない。G4)。API は保存した1件を返している(`{ drugPreset }` / `{ orderSet }` / `{ phrase }`)。
- 停止・再開はパネルの中のボタン。押すと即時保存(確認は不要。いつでも戻せるため)。保存後、その行は「停止中」グループへ移るので、パネルの見出しに「停止中」のタグを出して、どこに行ったか分かるようにする。
- 編集パネルを開いたまま別の行を押したとき: 変更がなければすぐ切り替える。変更があれば確認する。変更の有無は「開いたときの値」との比較で判定する。
- 検索は入力のたびに絞り込む(クライアント側。件数は多くて数百件なので十分)。かなとカナは同じものとして比べる(`ア`〜`ン` と `ぁ`〜`ん` の文字コードの差 0x60 で変換する小さな関数)。
- 並べ替えのドラッグは **入れない**(タブレットでの誤操作、スクロールとの干渉)。並び順を持たせるなら、パネルの中の「上へ / 下へ」ボタンか「先頭に固定(ピン)」にする(§4 の A1。API 変更が必要)。

### 3-10. 削るもの・まとめるもの
| 今 | 変更 |
|---|---|
| ページの h1「設定」+ タブ + パネルの h2 の3段 | 左ナビの見出し「設定」と、右の見出し「よく使う薬剤 10」の2つだけ |
| 「状態」列(使用中タグ + 停止ボタン) | 削除。停止中は末尾の畳んだグループ、操作はパネルへ |
| 「1日の回数」「用法」の2列 | 「既定」1列にまとめる(`1日4回 就寝前`) |
| 「1本の滴数」「容量」の2列 | 「既定」の2行目にまとめる(`5mL/120滴`)。点眼以外は出さない |
| 「院内外」列 | 院内のときだけ名前の右に小さいタグ |
| 表の下の追加フォーム(薬剤・定型文) | 削除。「＋ 追加」で空の編集パネル |
| セット一覧の長い説明文 | 数だけ(`処方2 検査3 方針`) |
| 説明文(表の上の小さな文字) | 1行だけ残し、滴数の説明はパネルの入力欄の下へ |
