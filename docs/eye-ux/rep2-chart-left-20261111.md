## データ（追加のみ・後方互換）

- 患者のプロファイル（eye_patient_profiles）に項目を足した: `adverseDrugs`・`regularMedications`・`vitals`・`interviews`・`summary`（と更新者・日時）、アレルギーの `onset`（任意、YYYY か YYYY-MM）。
- 保存は区画ごとの新しい API `PUT /v1/eye/patients/:id/profile/sections`（`{ expectedRevision, section, value }`）。ほかの項目は変えない。版（revision）がずれていれば 409。役割はプロファイルの編集と同じ（EYE_PROFILE_ROLES）、CSRF 必須。監査ログは区画名と件数だけ（本文は残さない）。
- 既存の `PUT /profile`（アレルギー・病名・既往のダイアログ、病名タブ）で保存しても、足した項目は消えない（`applyProfileUpdate` で引き継ぐ）。
- 修飾語の候補: `GET /v1/eye/masters/search?type=modifier&common=1`（語が空のときだけ）。修飾語マスター自体は既にあった（scripts/build_eye_masters.mjs の変更は不要）。
- 住所・電話は platform の患者情報の `contact`（既存）。platform-api の変更はない。
- デモデータ（模擬 和子）に住所・電話・副作用薬・常用薬・バイタル・問診・サマリーの架空の値を足した（プロファイルがまだない患者にだけ入る）。

## 写さなかったもの・理由

- 保険等タブ・PHR・定期タブ: 保険と公費はレセコンで扱う（オーナー決定）。定期は別の範囲。
- 処方監査（常用薬・副作用薬・既往と処方の重複・禁忌のチェック）: 医薬品の成分・相互作用のデータが要るため今回は記録まで。
- 検査結果のビューアー（別ウィンドウ）・検査会社の取り込み・院内検査項目の管理: 外部のサービスと設定画面が要る。
- 文書雛形の管理（医院で雛形のファイルを登録する）: 設定画面の範囲。ここでは「この患者の過去の文書を雛形にする」にした。
- 診療履歴の PDF ダウンロード・印刷のボタン: 印刷は中央・下の操作帯の範囲（chart-main）。
- 23（新規登録）は流れが同じなので変えていない。
