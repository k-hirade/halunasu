## 0. 結論（先に要点）

1. **他社の検査員画面は「入力欄を並べた表」ではなく、「選ぶ・写す・済ませる」画面。** Eyefinity（iPad）は値をドロップダウンで選び、「Copy OD to OS」「Set to 20/20 OU」で一括入力し、検査ごとに「Save and Continue」で次へ進む [確認]。ModMed は「前回の検査を pull forward」「片眼の値をワンタッチでもう片眼へ」[確認(動画説明)]。CLIPLA Eye は「タブレット専用の検査入力画面」と「機器の値をワンクリックで取り込み、レフケラはレシート形式で表示」[確認(宣伝)]。**手でキーボード入力させる前提の画面は見つからなかった。**
2. **現行画面の一番の問題は、入力の順序と束ね方が検査の流れと合っていないこと。**
   - 国内の慣習では、矯正視力は「1.2（×S−1.00 C−0.50 Ax180）」のように**矯正レンズと一緒に1つの値として読む**（推測: 国内の一般的なカルテ記載法。出典は今回取れず [未確認]）。現行は「矯正視力」と「矯正 S/C/Ax」の間に眼圧の行が挟まり、矯正の種類はさらに下の別の行にある。
   - 他覚屈折（オートレフ）は通常いちばん最初に測るが、表では下から2番目にある。
3. **縦に長すぎる。** iPad 横（1024×768）で、1画面に見えるのは検査値の6行目まで。確認ボタン・散瞳・オーダー・申し送りはすべてスクロールしないと見えない（全体 1,396px）。1行あたり 65〜86px あり、その大半は「前回 1.0」の 12px の注記と余白。
4. **検査員が最後にすること（検査終了 → 診察待ちへ）がこの画面にない。** 状態を変えるには受付画面に戻って「検査終了」を押す必要がある。代わりに「右眼を確認」「左眼を確認」「両眼の検査値を確認済みにする」の**3つの確認ボタン**が、同じ1つの意味のために並んでいる。
5. **タッチ入力の仕組みがない。** 屈折値は `type=number` の手入力だけで、±0.25 刻みのステッパーも符号の切り替えもない。視力は `<datalist>` に頼っているが、iPad Safari では候補の出方が弱い（推測。実機で要確認）。**iPhone の `inputmode=decimal` キーボードにはマイナス記号がない**ため、390px 幅では負の度数を入力できない可能性が高い（推測。実機で要確認）。

**提案（§3）:** 受付の再設計と同じ方針で作り直す。**1画面に収まる、検査の順に並んだ4行の表**（他覚屈折 → 裸眼視力 → 矯正視力+矯正レンズ+種類 → 眼圧+測定法）。前回値は同じ行の右端に薄く1つだけ出す。入力は**タップで開く数値パッド**（符号・0.25刻み・前回値ボタン付き）と**視力のクイックピック**。下には「本日の検査（チェックリスト）」「散瞳」「申し送り」を横3列に並べ、画面下に**主ボタン1つ「検査終了 → 診察待ちへ」**を固定する。色は状態（眼圧高値・散瞳経過・未実施）にだけ使う。

## 1. 競合調査（設計レベル）

### 1-1. Eyefinity EHR（Encompass, iPad）— いちばん詳しい一次資料 [確認]
出典: https://help.eyefinity.com/eehr/iPad/visit/vision-pretesting.htm 、 https://help.eyefinity.com/eehr/iPad/visit/vision-refractions.htm 、 https://help.eyefinity.com/eehr/iPad/visit/vision-import-refractions.htm 、 https://help.eyefinity.com/eehr/doctor-remote/in-house-doctor-flow.htm
- **画面の単位:** 検査ごとのタブ（Pupils / IOP / Visual Acuity / Diagnostic Drops / Refractions）。各タブの最後に「Save」または「**Save and Continue**」（次の検査タブへ進む）。
- **入力の仕組み:** 屈折値（S/C/Ax/Add）は**ドロップダウンから選ぶ**のが既定。「**Manual**」トグルで手入力に切り替える。刻み幅・ピッカーの形（ホイールかリストか）はヘルプに書かれていない [未確認]。
- **一括入力:** 「**Set to 20/20 OU**」「**Set to J1+OU**」で視力欄を一度に埋める。「**Copy OD to OS**」で右眼の値を左眼に写す（屈折・処方・散瞳薬）。
- **sticky（前回の選択を保持）:** 遠見・近見の視標の種類、散瞳薬。
- **眼圧:** Method / Measurement / Reliability の3項目。Measurement に「**Attempted but not achieved**（測定を試みたができなかった）」がある。
- **視力:** 「Add UnCorrected」「Add Corrected」で行を足し、VA・PH（ピンホール）値・Other を入れる。矯正視力では矯正の種類（Distance/Near Correction Type）も選ぶ。
- **過去値:** Refraction History から前回の屈折を取り込む。オートレフは機器連携（Equipment Integration）で ARx タブに自動で入る。
- **完了の見える化:** 必須の5領域が埋まるとセクションの色がオレンジから緑に変わる（既存調査 §3.5）。
- **医師への引き継ぎ:** 遠隔診療の流れでは、検査員がソフト上で「ready for refraction」「ready for the eye exam」を合図する。ボタン名は書かれていない [未確認]。

### 1-4. Compulink（Objective タブ）[二次]

## 3. 再設計案

### 3-1. 方針（受付の再設計と同じ考え方）
1. **1画面に収める**（1024×768 でスクロールなし）。表は4行に絞り、1行 56px。
2. **検査の順に並べる**: 他覚屈折 → 裸眼視力 → 矯正視力（＋矯正レンズ・種類） → 眼圧（＋測定法）。
3. **前回値は同じ行の右端に1つだけ**。タップで今回に写せる。前回の日付は表の見出しに1回だけ出す。
4. **入力はタップで開くパッド**（数値・視力）。PC ではこれまで通りキーボードで打てる。
5. **主ボタンは1つ**: 「検査終了 → 診察待ちへ」。確認はこのボタンにまとめる。
6. **色は状態にだけ使う**: 眼圧高値（赤）、散瞳の経過（黄→緑）、オーダー未実施（黄の点）。R/L の列塗りはやめ、見出しの文字色だけにする。

### 3-3. 並び（表の行）と入力の流れ
| 行 | 右眼 | 左眼 | 前回（右・左） |

| 他覚屈折 | S・C・Ax | S・C・Ax | `−1.25 −0.50 180` |
| 裸眼視力 | VA | VA | `1.0 / 0.4` |
| 矯正視力 | VA（S・C・Ax）＋種類 | 同 | `1.2(−1.00 −0.50 180)` |

- **Enter / パッドの「次へ」の順**: 現行の「右眼の全項目 → 左眼の全項目」を残す（コードのコメントにある意図を尊重）。ただし**屈折の S→C→Ax も Enter で進む対象に入れる**（同じ行にまとまるので飛ばす理由がなくなる）。

### 3-5. 1440 と 390 の補足
**1440×900:** max-width 1100 の中央寄せをやめ、**表（左 ~900px）+ 右列 380px** にする。右列に「本日の検査」「散瞳」「申し送り」を縦に積み、表の下に余白ができたら**直近3回の推移**（視力・眼圧の小さな表）を置く。※推移は現行 API では前回1件しか返らない（`detail.previous`）ので、出すなら API 追加（§4）。

### 3-6. 操作の詳細

**(a) 数値パッド（屈折 S・C）**
- タッチ端末（`@media (pointer: coarse)` または `matchMedia`）では、欄をタップすると欄のすぐ下にパッドが開く。PC（マウス・キーボード）ではこれまで通り直接打てる。
- 配置:
  ```
  [ − ][ + ]        前回: −1.00
  [7][8][9]   [.00][.25]
  [4][5][6]   [.50][.75]
  [1][2][3]   [ 0 ][ ⌫ ]
  [ −0.25 ][ +0.25 ]   [ 次へ → ]
  ```
- 符号は**押した符号を使う**。既定は前回値（なければ反対眼）の符号。C（円柱）は国内ではマイナス表記が多いので、前回もなければ「−」（推測。院の設定で変えられるとよい）。**勝手に符号を反転する処理は入れない**（誤記録の元）。
- 小数は 0.25 刻みのキーだけ。整数キーを押してから「.25」を押す。`−0.25 / +0.25` のステッパーは微調整用（-6.00 を 24回押させない）。
- 表示は常に符号付き・小数2桁（`+0.50`、`−1.00`、`0.00`）。保存する値は今まで通り数値（`-1`）。**表示だけを整形する**ので、データの意味は変わらない。
- 範囲外（S ±40、C ±20）はパッドで入らないようにし、サーバーの検証（contracts `validateRefraction`）と一致させる。

**(b) 軸 Ax**
- 数字キー + クイック値 `[180][90][ 0 ]`。0〜180 の整数だけ。C が 0 または空なら軸は薄く表示（入れなくてよいことを示す）。

**(c) 視力のクイックピック**
- タップで 5列のタイルが開く:
  ```
  2.0 1.5 1.2 1.0 0.9
  0.8 0.7 0.6 0.5 0.4
  0.3 0.2 0.15 0.1 0.09
  0.08 0.07 0.06 0.05 0.04
  0.03 0.02 0.01  ─  ─
  指数弁(n.d.) 手動弁(m.m.) 光覚弁+ 光覚弁−  矯正不能(n.c.)
  [キーボードで入力（30cm/n.d. など）]
  ```
- 前回値のタイルに枠を付ける。選ぶと次の欄へ進む。
- 値は今まで通り文字列で保存（`vaUncorrected` は 40文字までの文字列）。「n.c.」を足すのは `VA_VALUES` に1つ加えるだけ。

**(d) 眼圧**
- 数字キー（整数、0〜90）。測定法は「NCT | GAT | iCare」のセグメントボタン（今の sticky はそのまま）。
- 「測定不能」を足すかどうかはオーナー判断（現行スキーマでは `iop` が数値なので、足すなら API 変更。§4）。

**(e) 右→左に写す / 前回を写す**
- 「右→左に写す」は**左眼の空欄だけ**を埋める。埋めた欄は 2秒だけ薄く光らせ、元に戻すトーストを出す（`update` を呼ぶだけなので、既存の保存・競合処理に乗る）。
- 「前回の矯正レンズを写す」も空欄だけ。視力は写さない（毎回測る値なので）。

**(f) 本日の検査（オーダーの消し込み）**
- 予定のオーダーを上に、実施済みを下に。1行 44px。左の丸をタップ → 「実施」（今の `setStatus(index, "performed")` と同じ）。実施者・時刻はサーバーが記録する（今のまま）。
- 「取消」「予定に戻す」「削除」は行の「⋯」へ（誤タップ防止）。
- 「＋検査を追加」で、カタログをチップで出す（よく使う順。最初は視力・眼圧・屈折・OCT・眼底写真・視野）。眼は「両|右|左」のセグメント。
- **値の入力からオーダーを自動で「実施」にはしない。** 実施は算定（行為欄）に結び付くため、自動化は誤算定の危険がある。代わりに「視力値あり・視力検査が予定のまま」のように**小さなヒントだけ**出す。
- 見出しに「2/4」と件数を出す。全部済むと見出しが緑（Eyefinity の完了色と同じ考え方）。

**(g) 散瞳**
- 未散瞳: `[散瞳開始]` + 「両|右|左」セグメント（既定は両）。ボタンは1つ。
- 散瞳中: 経過分数とバー（20分で緑）。**固定バーにも「散瞳 12分」を出す**（表を見ていても分かる）。
- 散瞳オーダーが「予定」であれば、散瞳開始時に「散瞳オーダーも実施にしますか」と1行で聞く（自動ではなく確認付き）。
- 散瞳薬の記録（Eyefinity は眼ごとに薬剤、sticky）は現行スキーマにないので、将来の API 変更（§4）。

**(h) 検査終了 → 診察待ちへ（主ボタン）**
- 押すと: ①未保存を保存 → ②値の入っている眼だけ `exam-confirm`（両眼とも値があれば `both`）→ ③当日の予約の状態を `in_exam → waiting_doctor` に変える → ④受付へ戻る（または次の検査待ちの患者を出す）。
- 値がまったく無い眼があれば、ボタンの前に1行で「左眼は未入力です」と出す（止めはしない）。
- ③は今の API で実現できる（`GET /v1/eye/appointments?date=` で同じ患者・状態 `in_exam`/`checked_in` の予約を探し、`POST /v1/eye/appointments/{id}/status`）。**同じ日に該当予約が2件以上ある、または見つからないときはボタンを「確認済みにする」だけに落とす**（誤った予約を動かさない）。将来は encounter に `appointmentId` を持たせる方が確実（§4）。
- 予約の状態が `checked_in` のままなら、③の前に `in_exam` を経由させる必要があるか、`APPOINTMENT_TRANSITIONS` を確認すること（contracts 71行目付近では `in_exam → waiting_doctor` のみ確認）。

**(i) 申し送り**
- textarea は 3行のまま。下に**定型チップ**（眼鏡持参なし / CL装用中 / 固視不良 / 測定困難 / 再検希望）。押すと末尾に追記するだけ（上書きしない）。チップの中身は既存の「定型文（phrases）」設定を使えれば、なおよい（bootstrap に `phrases` がある）。

### やらないこと（バグ・データ消失の危険）
- 値の入力からオーダーを自動で「実施」にすること（算定に影響。ヒント表示まで）。
- 符号の自動反転、値の自動補正（「1」→「1.00」以外の書き換え）。
- 前回値・反対眼の値で、入力済みの欄を上書きすること（空欄だけ。上書きは必ず確認）。
- 検査ページ用に Orders / ExamTable を直接書き換えて、カルテ全体画面（encounter-editor.js も同じ部品を使う）を壊すこと。`variant` か別の表示部品で分ける。
