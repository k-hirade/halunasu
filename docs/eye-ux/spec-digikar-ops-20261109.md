### 2.4 ステータス
- メニューに並ぶ順: **予約済 → 受付中 → 診察待 → 診察中 → 検査中 → 処置中 → 会計待 → 会計済 → 再計待 → 不在 → 取消**。[確認 M p.54] SS: img/p054.png
- 自動で変わるとき:
  - 予約を登録すると「予約済」になる。
  - 受付すると「診察待」か「受付中」になる（どちらにするかは施設設定「受け付けた時のステータス」）。[確認 M p.33, p.219]
  - カルテを［次へ］で保存すると「患者ステータス選択」ダイアログが出て、既定は「会計待」。[確認 M p.33, p.135]
  - ORCA へ送信する（一体型版は会計を保存する）と「会計済」になる。[確認 M p.33][確認 R p.32]
  - 会計済のカルテを直して保存すると「再計待」になる。[確認 M p.33, p.181]
- 手動で変えるとき:
  - 診察中・検査中・処置中・不在は自由に選ぶ。
  - 「取消」は手動。カルテがある受付は取り消せない（エラーになる）。[確認 M p.33, p.54]
  - 予約患者が来たら、予約済の行のステータスを「診察待」に変えるだけで受付になる（受付時間が入る）。受付をやめるときは「予約済」へ戻す。[確認 R p.47]
- 順番の決まりはない。どのステータスからどのステータスへも移れる［推測: メニューに全項目が並んでいるため］。

## 3. 受付登録（受付作成）

### 3.1 流れ（一体型版。Halunasu が自前で受付するのでこちらが近い）[確認 R p.45-47]
1. 受付画面のヘッダーで［検索］→ 患者検索モーダルで患者を探す（3.2）。
2. 結果の行の［受付］を押すと受付登録ダイアログ（3.3）が開く。
3. 必要なら下の項目にチェックを入れて［登録］。
   - 保険証確認
   - カルテ1号用紙を印刷する
   - 受付票を印刷する
4. 受付一覧に行が増え、番号が振られる。ステータスは「診察待」または「受付中」になる。

- 新しい患者のとき: 検索モーダルの［新規患者登録］→ 患者情報登録 →［登録して受付］で、そのまま受付登録ダイアログへ進む。[確認 R p.55-56]
- 予約していた患者のとき: 一覧のステータスを「予約済→診察待」に変えるだけでよい。[確認 R p.47]
- ORCA連動版のとき: 新患登録も受付も ORCA 側で行い、デジカルの受付一覧には ORCA の受付が取り込まれる。頭書き（患者情報）の修正も ORCA で行い、受付画面の［↻］で反映する。[確認 M p.48-50, p.64]

### 3.2 患者検索モーダル [確認 R p.36, p.45] SS: hi/r036c.png, hi/r036a.png, hi/r036d.png

  - 右端に［新規患者登録］。

## 6. 会計・ORCA送信

### 6.1 ORCA連動版（Halunasu＝「レセコンはアダプター」に最も近い）[確認 M p.167-189] SS: img/p167.png, img/p135.png
- 送信の入口は2つ。
  1. カルテ右下の操作バーの［¥］（送信）
  2. 受付一覧の［会計］（会計待の行だけ。中身の確認がいらないとき）
- 確認ダイアログ「レセコンへ会計情報を送信しますか？」で［キャンセル］［送信］の2択 → 送信 → ステータスが「会計済」になる。
- 病名も一緒に送るかどうかは施設設定「カルテ送信時病名自動送信」で決める。
- 送信の単位は**受付ごと**。同じ日に2回来た場合は、2回目の受付で2つ目のカルテが自動で作られ、それぞれ送信する。[確認 M p.60]
- 1つの受付で保険を分けたいとき（公費あり/なし）は、カルテのタブの［＋］でカルテを足す。それぞれ保存し、最後のカルテで［送信］。[確認 M p.171-172]
- 送ったあとに直したとき: カルテを保存するとステータスが「再計待」になる → ORCA 側で前回分をクリア → デジカルの受付一覧の［会計］で再送する。[確認 M p.181-185]
- ORCA 側の作業（中途表示 → F12確定 → 登録）は ORCA の画面で行う。デジカルは送るだけ。

#### 送信エラーの表示
- 送信失敗時の画面はマニュアルに**載っていない**。
- 状態の確認は、ヘッダーの「連携」アイコン（ORCAとの接続状態を出す）で行う。[確認 M p.27, p.29]
- 取り込み系の結果は「処理結果はステータス欄の表示（成功、失敗）」という履歴の表で出す方式（検査結果取込 [確認 M p.134]、マスタ更新 [確認 M p.204]）。送信の失敗も同じく［推測］トーストと連携アイコンのバッジで知らせる。

### 6.2 カルテの保存と［次へ］（会計待ちへの受け渡し）[確認 M p.31, p.135-136]
- カルテ右下の操作バー（右ペインの下端に固定）の並び:
  - 左側: ORCA版は［¥ 送信］［検査依頼］。一体型版は［自動算定］［¥ 会計］［検査依頼］。
  - 右側: **［💾 保存］［🖨 印刷］［→ 次へ］**。
- ［→ 次へ］を押すと保存され、「患者ステータス選択」ダイアログが開く。
  - 左列に「現在のステータス」、右列に「次のステータス」のラジオ（全ステータス。既定は会計待）。
  - ［キャンセル］［決定］のあと、患者リスト（診察待の一覧）へ移る。
- 保存時に警告があれば「警告一覧」ダイアログ → ［保存］で続ける。警告の種類は期限切れのマスタ、投薬チェック、院内/院外の併用、長期収載品など。

### 6.3 一体型の会計画面（参考: 点数を自前で計算する場合）[確認 R p.176-193] SS: hi/r177a.png
- 幅約400pxのモーダル「会計」。上から順に次の通り。

### 7.5 セット（約束処方）の管理 — **設定画面ではなくカルテ画面で行う** [確認 M p.90-96, p.46] SS: img/p090.png, img/p092-093.png

- **一覧**: カルテ右ペインの検索タブの先頭「セット」タブ。

- **定期（患者専用のセット）**: カルテ上部の［定期登録］で、セット名と繰り返し（次回 / 毎回 / ○ヶ月毎）を決める。
  - 右ペインの下の「定期診療」と左ペインの「定期」タブに出る。押すと入力される。
  - 左ペインの「定期」タブからは、交付年月日が空欄の処方箋を印刷できる。

## 10. Halunasu eye との対応と変更リスト

前提（社内の決定事項）:
- 当月の行為欄は評価専用で入力しない。
- 「レセコンはアダプター」として扱う。
- 保険・資格確認はレセコンで登録する（現行の `patient-register-dialog.js` にも「保険証・資格確認はレセコンで登録します」とある）。

このため、DigiKar の**一体型の保険入力と会計計算はそのまま写さない**。ORCA連動版の構造（送信だけ）に合わせる。

### 10.1 ステータスの対応表（データモデル）
`packages/eye-contracts/src/index.js` の `APPOINTMENT_STATUSES` / `APPOINTMENT_TRANSITIONS` との対応。

| DigiKar | Halunasu の現行 | 対応方針 |
|---|---|---|
| 予約済 | booked | そのまま |
| 受付中 | checked_in | ラベルを「受付中」にする案 |
| 診察待 | waiting_doctor | ラベルを「診察待」に |
| 診察中 | in_consult | そのまま |
| 検査中 | in_exam | そのまま（眼科では主役） |
| 処置中 | （なし） | **追加の検討**: `in_treatment`（散瞳点眼・処置）。散瞳は現行どおり encounter.dilationStartedAt から派生させるので、ステータスにはしない |
| 会計待 | checkout | そのまま |
| 会計済 | done | ラベルを「会計済」に。レセコンへ連携したら自動で done にする（10.5） |
| 再計待 | （なし。billing 側の handoff.state="changed"） | ステータスは増やさず、受付一覧に**派生ステータス**「再計待」として出す（billing/day の changed を一覧の API に含める） |
| 不在 | （なし） | **追加の検討**: `away`（呼んでもいない）。行き来は自由 |
| 取消 | cancelled | そのまま。カルテのある受付は取り消せないようにする（サーバー側の検証） |
| （なし） | no_show | 残す（DigiKar にはない眼科独自の値。メニューの最後に置く） |

- **衝突**: DigiKar はどのステータスからでも手動で移れるが、Halunasu は `APPOINTMENT_TRANSITIONS` で1段ずつ・1段戻しに限っている。
- ドロップダウンで全ステータスを出すには、次のどちらかが要る。
  - (a) 遷移表を「done/cancelled/no_show 以外は相互に移れる」に緩める（`validateAppointmentTransition` の変更、テストの更新）
  - (b) メニューに出すのは遷移できるものだけにする
- 推奨は (a)。statusHistory は残るので監査はできる。

### 10.2 /reception（`reception-workspace.js`）— 構造を全面的に作り直す
現状はステータスのグループ見出しと人数チップがあり、フラットな表ではない。DigiKar に合わせるため次のように変える。

1. **レイアウト**
   - page-head（h1＋要約文）をやめ、2行目のツールバー1本にする。左から `[‹][日付ボタン(カレンダーpopover)][›]  全N件 / M/N件  [▼フィルタ][×]`、右寄せで `[予約を追加][当日受付][受付編集履歴][↻]`。
   - `flow-chips`（人数チップ）は廃止。フィルタのポップオーバーのステータス列が代わりになる。人数をどうしても出したい場合は、フィルタ列の各項目の横に件数を出す。
2. **表**
   - `<ul class="flow-rows">` を `<table>` に替える。グループ見出し・「終了・キャンセル」の折りたたみ・「次の60分」の間引きは**廃止**する（フィルタとソートで代わりにする）。
   - 列は左から次の順。
     - 番号（`queueNumber` を3桁にゼロ埋め。予約は「-」）
     - 予約（`time`）
     - 時間（`checkedInAt` の時刻）
     - ステータス▾
     - 患者番号（`patientSnapshot.primaryPatientNumber`）
     - 患者氏名（上段にカナ、下段に漢字。未登録なら［未登録］チップ）
     - 生年月日（和暦併記。`eraYearLabel` を使う）
     - 年齢
     - 目的（`purpose`。DigiKar の「保険」の位置に置く眼科独自の列）
     - 医師
     - 前回受診日
     - 患者メモ
     - 受付メモ（`note`）
     - **進捗**（現行の `progressOf`: 視・圧・オーダー・散瞳。眼科独自の列で、医師列の右に置く）
     - 待ち（現行の `flow-wait`）
     - 会計
     - 行アイコン（予約📅、…メニュー）
   - 既定のソートは番号の昇順。予約済（番号なし）は予約時刻の順で上に置く。
3. **ソート**: 番号・予約・時間・ステータス・患者番号・患者氏名（カナ）・生年月日・年齢・待ちの見出しに ▲▼ を付ける。状態は URL のクエリか localStorage に持つ。
4. **フィルタのポップオーバー**
   - 4列にする: ステータス（すべて選択/クリア）・医師・目的（DigiKar の診療科の位置）・表示する項目。
   - 下段に患者メモと受付メモの文字列フィルタ。
   - 表示する項目は `localStorage`（端末ごと）に、try/catch で包んで保存する。
   - 絞り込み中は件数を「M / N件」にし、×で解除する。
5. **ステータスセル**
   - 現行の［次へ進める主ボタン］と［…メニュー］をやめ、`ステータス▾` のドロップダウンにする（全ステータス＋取消。10.1）。
   - 現行の「受付する/検査開始/…」の一押しで進める操作は、**眼科で手数を減らす意味があるので残してもよい**。その場合はステータスセルの右に小さな「→次」ボタンとして置く（DigiKar にはない追加要素であることを明記する）。
6. **行を押したとき**
   - 現行: カルテがあれば開き、なければ患者ページへ行く（カルテは作らない）。
   - DigiKar: 氏名を押すと必ずカルテが開き、予約済なら下書きになる。
   - 推奨は、氏名を押したら `openChart` でカルテを開く（なければ作る）こと。予約済の行で下書きのカルテを作るかは、医事の判断に任せる（下書きを作ると会計連携の「未確定」に出てしまう問題がある）。
   - 「患者のページ」は…メニューへ移す。
7. **セル内の編集**: 医師・目的・予約時刻のセルにカーソルを載せたら✎を出し、受付編集ダイアログ（`AppointmentDialog` を流用し、編集モードを追加）を開く。
8. **患者メモと受付メモ**
   - 患者メモの列は新しく作る。データは platform の patient `notes`。`services/eye-api/src/server.js` の `patientInput` は notes を通しているので、eye の PATCH を足せば実装できる。
   - 受付メモは `appointment.note` を使う。
   - 各セルを押すと専用の小さなダイアログ（テキストエリア＋［キャンセル］［登録］）を開く。受付ラベル（チップ）は第2段階に回す（`appointment.labels[]` と設定のラベルマスタが要る＝API の変更）。
9. **会計列**: checkout の行に［会計］ボタンを出す。押すと「レセコンへ渡しますか？」の確認 → `POST /v1/eye/billing/handoffs`（その患者の encounterId 1件）→ CSV を保存 → ステータスを done にする。billing の changed は「再計待」のバッジ＋［再連携］にする。
10. **受付編集履歴**
    - 新しいダイアログを作る。appointment の `statusHistory` と監査ログ（`eye.appointment_*`）から次の列を出す: 番号 / 予約 / 時間 / ステータス / 患者番号 / 氏名 / 作成日時 / 最終編集日時 / 最終編集者 / 詳細。
    - 取り消した受付も含めるので、取得は `GET /v1/eye/appointments?date=&includeHistory=1` のような拡張が要る。
11. **自動更新**: 現行の15秒ごとの更新は残し、［↻］ボタンを足す。
12. **空の状態**: 表の見出しを出したまま「全 0件」とし、本文の空メッセージは短く1行。

### 10.3 患者検索（`patient-search.js` ＋ `site-nav.js`）
- 現行のヘッダー内コンボボックス（`/` で入力欄へ移り、↑↓ と Enter で選ぶ）は**キーボードだけで操作でき、DigiKar より優れている。残す**。
- 加えて、DigiKar と同じ形の**検索モーダル**（ヘッダーの🔍、またはコンボボックスの「詳しく検索…」から開く）を足す。
  - 入力欄＋×＋▼（オプション）＋右端に［新規患者登録］。
  - 結果の表の列: 患者番号 / フリガナ / 名前 / 性 / 生年月日（和暦）/ 年齢 / 最終受診日 / 患者メモ。
  - 行のボタン: ［カルテ］［受付］［予約］［✎］。
  - 結果は100件まで。
  - オプションは眼科向けに置き換える: 傷病名 / 受診期間（今月・先月）/ 電話番号 / 診療記録の全文。
- **API の変更**
  - `POST /v1/eye/patients/search` に `lastVisitDate`・`notes` を返させる。
  - オプションの条件（`diagnosis`, `visitFrom/To`, `phone`）を受け付けるようにする。
  - 件数の上限と総件数（「N件中100件」）を返させる。
- コンボボックスの候補行も、DigiKar の列順（番号 → カナ → 氏名 → 性 → 生年月日 → 年齢 → 最終受診日）に揃える。

### 10.4 患者登録（`patient-register-dialog.js`）
- **項目の順を DigiKar に合わせる**。
  - 現行は 氏名 → フリガナ → 生年月日/性別 → 患者番号。
  - 変更後: **患者番号 → 漢字氏名 → カナ氏名 → 性別 → 生年月日 →（任意）郵便番号・都道府県・住所1〜3 → 電話1・電話2**。
- **必須**
  - DigiKar は番号・漢字・カナ・性別・生年月日のすべてが必須。Halunasu は性別と生年月日が任意（未入力のときは警告を出すだけ）。
  - レセコンへ連携するには性別と生年月日が要るので、少なくとも生年月日は必須に揃える案を出す。ただし、受付票の氏名だけで先に受け付ける（appointment.patientName）運用と衝突するので、ここは医事に確認する。
- **患者番号の自動採番**
  - DigiKar は「前回＋1」が最初から入っている。Halunasu はレセコンの番号に合わせる方針なので空欄が既定になっている。
  - 推奨は、設定で「自動採番（最大＋1）/ レセコン番号を手入力」を切り替えられるようにすること。自動採番には `GET /v1/eye/patients/next-number` が要る（API の追加）。
- **生年月日の入力**
  - 現行は `type=date`。
  - DigiKar は年・月・日に分かれ、年に和暦が出る。現行は下に「eraYearLabel・年齢」を出しているので、それで十分に近い。
  - 和暦の直接入力（S29.5.3 など。検索にはすでにある `parseBirthDateQuery`）を登録欄でも受け付けるようにすると、DigiKar 以上になる。
- **住所・電話**
  - platform の `contact`（形は自由）に入れる。eye-api の `patientInput` は contact を通している。
  - `contact: { postalCode, prefecture, address1, address2, address3, phone1, phone2 }` の形を `eye-contracts` に決めておく（データモデルを追加するだけ）。
- **ボタン**
  - 現行は［キャンセル］［登録して患者を開く］（または［登録して受付に紐づける］）。
  - DigiKar の3つ（**［キャンセル］［登録］［登録して受付］**）にする。［登録して受付］を押したら受付ダイアログ（10.6）へ続ける。
- **似た患者のパネル**（現行の `register-similar`）は残す。DigiKar の右側情報パネル（約40%）の位置に置けば、2ペインの構成になる。
- **保険の欄**: 写さない。保険はレセコンで登録するという決定事項による。代わりに、患者ページへ「保険（レセコン参照）」を読み取り専用で出す余地を残す。将来アダプターから取り込むときは、platform の `insurance` が**1つのオブジェクトだけ**なので、DigiKar のように複数の保険を有効期間で持つことはできない。複数にするなら `insurance[]` への変更（platform-contracts の破壊的変更）が要る。

### 10.5 会計（/billing と `billing-workspace.js`）
- DigiKar ORCA版の構造は「カルテ／受付一覧から1人ずつ［送信］→確認→会計済、修正したら再計待→再送信」。Halunasu の現行は「日ごとにまとめて CSV を出し、連携済みにする」。
- 推奨:
  1. **受付一覧の［会計］ボタン（1人ずつ連携）を主な経路にする**（10.2-9）。会計待の行で押すと、確認ダイアログ「レセコンへ会計情報を渡しますか？［キャンセル］［渡す］」→ その人だけの handoff → 受付のステータスを done（会計済）にする。
     - **API の変更**: handoff の成功と appointment の status=done をまとめて1回で行う（`POST /v1/eye/billing/handoffs` に `appointmentId` を受け付けさせ、サーバー側で遷移させる）。
  2. カルテ画面にも同じ［¥ 連携］を置く（右下の操作バー。10.7）。
  3. /billing はまとめて連携する画面として残す。DigiKar ORCA版にこの画面はなく、一体型の日計表に近い。
     - 並びを受付一覧に揃え、フラットな表にする。列は 患者番号 / 氏名 / 初再 / 確定 / 品目の要約 / 状態（未連携・連携済・**再計待**）/ 操作。
     - 「要再連携」の表示を **「再計待」** に揃える。
  4. **エラー表示**
     - 送信に失敗したら、行の会計セルに「失敗」チップを出し、その場で再試行できるようにする。ヘッダーにアダプターとの接続状態（DigiKar の「連携」アイコン相当）を出す。
     - 現在の CSV 方式には接続状態がないので、アダプターを入れるときの課題として記録する。
  5. 一体型の会計モーダル（請求額・入金・調整金・繰越）は、点数を計算しない方針と**衝突するので作らない**。

### 10.6 受付登録・予約（`appointment-dialog.js`）
- **受付ダイアログ**（当日受付）
  - DigiKar に合わせた項目順: 受付日（表示のみ）/ 患者（表示のみ、または検索）/ **医師** / **目的（＝診療科の位置）** / （保険は表示のみ。レセコン参照）/ 受付メモ / ☐受付票を印刷する。
  - 前回の受付の医師と目的を最初から入れる。
  - **データモデルの変更**: appointment に `doctorMemberId`（任意）を足す。`validateAppointmentInput` と一覧の API で返す値に追加する。
- **予約ダイアログ**を2ペインにする。
  - 左（約1/3）: その患者の予約一覧。各行に✎・🗑・カルテ。**API の変更**: `GET /v1/eye/appointments?patientId=&from=today` が要る。
  - 右: 予約日＋📅（予約状況カレンダー）/ 医師 / 目的 / 予約時刻（空欄可）/ 受付メモ / ☐予約票を印刷 / ☐受付メモを備考に印字 → ［キャンセル］［登録］。
  - 患者が決まっていない入口（受付画面の［予約を追加］）では、右ペインの先頭に患者検索（現行の候補リスト）を残す。
- **予約状況カレンダー**を新しく作る。
  - 左に月のミニカレンダー（日ごとの件数）と医師の切り替え。右に週×時間の格子（終日の段と1時間の段）。件数ブロックを出し、空いた枠を押すと日時が入る。
  - **API の追加**: `GET /v1/eye/appointments/summary?from=&to=&doctorMemberId=`（日ごと・時間ごとの件数）。
- 予約を変える入口: 受付一覧の予約行の医師・目的・時刻のセルを押すと、予約編集が開く（10.2-7）。
- 「下書きカルテ」（予約済から開く）は、次回の処方・検査の申し送りに使える。ただし、Halunasu の encounter は確定前のものが会計連携の「未確定」に出てしまうので、`encounter.draftForAppointmentId` のような区別が要る（データモデルの変更）。第2段階に回す。

### 10.7 診察（/ ＝ `home-workspace.js`）とカルテの終了操作
- DigiKar の「患者リスト」（診察待の一覧と人数バッジ）は、Halunasu の / に当たる。現行の構成（段階ごとの一覧と要対応）で十分。人数バッジ（`site-nav.js` の `nav-badge`）は DigiKar と同じ。
- **カルテ右下の操作バー**（`encounter-editor.js` 側）を DigiKar の並びにする。
  - 左: ［¥ 連携］［検査依頼（オーダー）］
  - 右: ［保存］［印刷］［→ 次へ］
- ［→ 次へ］を押したら保存し、「患者ステータス選択」の小さなダイアログ（左に現在、右に次のステータスのラジオ。既定は会計待（checkout）。眼科では検査中・診察待へ戻すこともある）→［決定］→ / の次の患者へ。
- 現行の「診察終了」ボタンは、この流れに置き換える。

### 10.8 設定（/settings と `settings-workspace.js`）
- レイアウト（左サイドメニュー＋右パネル）はすでに DigiKar の施設管理と同じ形。並びと見出しを揃える。
  - 管理: **医療機関情報**（新設。`/v1/eye/bootstrap` の facilities を読み取り専用で表示し、［✎編集］は管理者だけ）/ **利用者**（新設。core-admin のメンバーを eye の役割付きで一覧表示する。列は ログインID / 氏名 / 役割 / 設定権限 / 状態 / 最終ログイン。作成・無効化は platform 側の API が要る＝API の変更、もしくは core-admin へのリンクで済ませる）/ 印刷用の氏名 / **その他設定**（新設: 受付時のステータスの初期値（受付中/診察待）、自動採番、受付票の印刷の既定）/ データ出力 / 操作記録
  - カルテ入力の候補: よく使う薬剤 / セット / 定型文
- **セット（約束処方）**
  - DigiKar は**カルテから作る**（［セット登録］＝今のカルテの内容をそのまま保存）方式で、フォルダを入れ子にでき、ドラッグで並べ替え、「現在のカルテで上書き」もできる。Halunasu は設定画面のフォームで作る。
  - 変更リスト:
    1. カルテの右上に［セット登録］を置き、今の処方とオーダーから `orderSets` を作る（`POST /v1/eye/order-sets` を流用。権限は現行 `EYE_SETTINGS_ROLES`=admin だけなので、医師にも開くかは決定が要る）。
    2. `orderSet.folder`（文字列のパス、または folderId）と `sortOrder` を追加する（データモデル・API の変更）。
    3. セットの編集に「☐現在のカルテで上書き」を足し、差分を左右に並べて見せる。
    4. カルテの右ペインのセット一覧をフォルダのツリーにする。
  - 設定画面のフォームは、細かい調整の場として残す。
- **定期（患者専用セット）**は Halunasu にない概念。`encounter-extras` の再診間隔（intervalWeeks）が近い。第2段階で「患者専用セット」（patientId 付きの orderSet。繰り返しは 次回/毎回/Nヶ月毎）を作るかを決める。
- **マスタ管理（レセコンから取り込み）**: アダプターを入れたら、「最終成功日時・前回実行結果・［更新］」の表の形で医師・用法・自費を取り込む画面を設定に足す。現時点では不要。

### 10.9 ヘッダー（`site-nav.js`）
- DigiKar にはタブ型のグローバルナビがない（アイコン＋利用者メニュー）。Halunasu のタブ（受付/診察/会計連携/設定）は**残す**（4つだけなので、分かりやすさの点で上回る）。
- 揃える点:
  1. 利用者メニューに「パスワード変更」「施設管理（＝設定）」を足す。設定のタブを利用者メニューへ移すかは選べる（DigiKar 準拠ならメニューの中、現行の分かりやすさを取るならタブ）。
  2. 受付画面と /billing の日付ナビを、DigiKar の日付ボタン（カレンダー popover。年月の切り替えは和暦併記）に揃える。現行の `<input type=date>` は残してよい。
  3. 患者検索のモーダル（10.3）をヘッダーの🔍から開けるようにする。
  4. アダプターを入れたら「連携」の接続状態アイコンを置く。
