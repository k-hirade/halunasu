## 0. 要点

1. **画面の骨格は「ドッキング型の多ペイン、1画面完結」**。どのペインにも見出しバーと、ピン留め・閉じるの印がある。これが LP の「自由なレイアウト」の正体とみられる [確認 02:21 のペイン見出し / 推測: 配置変更]。
2. **再診1件の流れは4画面の自動連鎖**(動画 02:20〜03:03、約45秒)。
   1. 患者一覧で行を選ぶ(概要がその場で出る)
   2. カルテ(3カラム)で、過去所見をドラッグ&ドロップして差分だけ直す
   3. 「診察終了」で**診療情報入力**が自動で開く。検査・処置を Do し、処方歴をドラッグ&ドロップする
   4. 「保存して次へ」で**診療予定**が開く。Do して「保存して次へ」を押す
   5. **医事送信の確認ダイアログ**で OK する
3. **検査入力(RegData)は別ウインドウ**。大タブ11 × 小タブの2段構え。視力は**上段に機器値の参照パネル3枚、下段に遠見/近見 × R/L/B の入力グリッド**を置く。両眼視・眼位は**図のボタン**で入力する。
4. **今日の検査は自動で「検査・処置」になる**。診療情報入力を開いた時点で、精密眼圧と矯正視力検査が入っていた [確認 02:42]。
5. **次回の検査指示(診療予定)は、次回カルテの「診療予定」枠に、実施欄つきの黄色い行として出る**。前回カルテで作った予定が、今日のやることリストになる [確認 02:21 概要「本日予定」、02:27 カルテ下段]。
6. Halunasu の差分で大きいのは次の5点。
   - (a) 検査値のデータモデルが「1受診1値」
   - (b) 次回予定に「項目×部位」の構造がない
   - (c) 診察終了から会計までが自動でつながっていない
   - (d) 患者一覧に、開かずに見られる概要ペインがない
   - (e) 過去カルテペインに種別フィルタがなく、カルテ記載が3カラムになっていない
   - §9 に変更リストを、§10 にデータモデル・API の要件をまとめた。

## 1. 共通の画面作法 [確認 02:21〜03:03]

- **ウインドウ構成**: 各ペインは「見出しバー(小さい文字)+ 本体」でできている。見出しバーの右端にピン留めと閉じるがある。患者一覧では次のペインが見えた。
  - 担当医選択
  - 患者指定
  - 場所一覧
  - カルテ概要
  - ツールバー
  - 終了
- **最右に縦のコマンド列**がある(患者一覧では「ツールバー」、カルテでは「ランチャー」)。アイコン+2〜4文字のボタンが縦に並び、幅は画面の約5〜6%。
- **表(グリッド)の作法**
  - 見出し行は濃い色で、行は白。選択行は全体が反転する。
  - 列幅は詰めてあり、はみ出した文字は省略される(「診察予定時刻」が「診予定時刻」のように切れる)。
- **日付ツリー**: 過去カルテ・処置歴・処方歴は、どれも「日付見出し(折りたたみ)→ 種別見出し【検査】【シェーマ】【文字所見】【検査・処置】【処方】→ 内容」の3段になっている。
- **ボタンの並び順**: 下部のコマンドは常に**左から「確定系 … キャンセル … 保存して戻る … 保存して次へ」**で、右端が「次へ進む」になる [確認 02:42、02:57]。
- **Do の位置**: 各リストの直下にある操作行「編集・削除・Do(・ゼロDo)」の中に置く。全体を一括で Do するボタンはない [確認 02:42]。

  - 下端に保険情報の表(名称/本人・家族/負担割合%)

### 3.3 中カラム「過去カルテ」(幅約24%)

- **上部ツール**: 3アイコン(別ウインドウ・設定・更新)[推測]。
- **種別タブ(2段)**: カルテ・初回・主/問・シェーマ・所見・書類・処方 / 傷病・処置・診療予定。
- 区分ラジオ(○外来 ○入院 ◉全て)と ▲▼(前後の日付へ移動)[推測]。

  - 【シェーマ】: サムネイル+【登録 - 記入者(職種):日時】
  - 【文字所見】: 本文+【記入者:日時】
  - 【検査・処置】: 「精密眼圧 (なし)×1」の形式(名称・部位・回数)

### 3.4 右カラム「カルテ記載」(幅約52%)

**上端の帯(高さ約12%)**
- 来院歴(11)と日付リスト(縦に5行+スクロール、今日の日付は選択色)、[本日][カルテ表示]
- 「カルテ - (日付)」、[散瞳開始][記入者▼]
- 受診区分「外来 受付 初診 眼科」と状態のマーク、「記入者:」
- 右側に「従編集に変更 / 🔒 / 主編集」(同時記入時の主従の切替)と「特記事項」の枠
- 右上に「⟳ / ▢ / □日付 □全表示 / ＋新規 / 中止」
- 最上段の右に**終了ボタン4つ**(縦に並ぶ): 診察終了 / 保存終了 / 次へ / キャンセル

**記載タブと記載ツール**
- 記載タブ: カルテ記載 / オーダー / 問診
- 記載ツール行: ⟳ + **[シェーマ][所見][予定]**(押すと、そのパネルを表示/非表示にする。表示中は色が付く)+ レイアウト + パネル表示
- カタログ版の同じ場所は「問診・所見 / シェーマ / オーダ登録」のタブと、[所見][病名][処置][処方] のボタン。**記入状況(未記入/記入中/記入済み)でボタンの色が変わる**(カルテガイド)[確認 カタログ]。

**シェーマパネル**(右カラムの左側、約48%)
- 左にボタン列(縦): 新規作成 / 編集 / 一覧 / 撮影一覧 / 前回Do / スキャン / 画像貼付 / 削除
- 上に「⟳ 従編集に変更 … 主編集」
- 本体は白いキャンバスで、**既定の下絵は2×2**(上段: 右眼・左眼の外眼。眼瞼の輪郭と角膜の円 / 下段: 右・左の眼底の円)[確認 02:27]。

**文字所見パネル**(右側、約52%)
- 見出し行: ⓘ ⟳ 従編集に変更 主編集
- **定型ボタン**: 4列×2行+スクロール。左に ⚙(登録)と C(クリア?)がある。動画の例は「著変なし / Slit.Fds) do / 散瞳 do / 無散OCT do / 散瞳OCT do / 眼精疲労 / フルオ do / 術翌日 両」。
- 書式行: フォントサイズ(12▼) / 文字色 / マーカー色 / [新規][削除][Do]

| **D1 視力・眼圧の項目** | `exam.{od,os}` に vaUncorrected / vaCorrected / correction(SCA) / refraction(SCA) / iop(1値) / iopMethod / vaCorrectionType / measuredAt / vaNear | 遠見・近見 × R / L / B、IOL・CL 列、RG、PD、眼圧3回+平均 | 互換を保って足す: `exam.binocular.vaUncorrected / vaCorrected`(BV)、`exam.{side}.near {va, vaCorrected, correction}`、`exam.{side}.iolCl`、`exam.{side}.rg`、`exam.pd {far, near}`、`exam.{side}.iopReadings [n1,n2,n3]`(iop は平均として残す) |
| **D2 検査記録の単位** | 1受診に検査値が1組 | 1受診に「検査日時+検者+種類」の記録が複数 | `content.examRecords[] {recordId, kind:'va'|'iop'|'refraction'|'kerato'|'worth'|'nine_gaze'|'cover'|…, takenAt, examinerId, values}` を足す。**`exam` は「代表値(その日の最終値)」として残し、記録から自動で作る**(前回値・トレンド・確認の既存ロジックを壊さないため)。眼ごとの確認(examConfirmations)も記録単位にするかは要決定 |
| **D3 次回予定** | `nextVisit {intervalWeeks, date, note}` | 予定日 + 項目 × 部位 × 作成時コメント、実施 / 実施者 / 実施時コメント | `nextVisit.items[] {code, name, eye:'od'|'os'|'ou'|'', comment}` を足す。**次の受診のカルテを作るときに、`orders[]` へ planned として写す**(作成元 encounterId を持たせる)。受付の「本日予定」、受診票、検査画面のチェックリストは、この orders から出す |
| **D4 機器値** | なし(手入力) | ケラト・レフ・眼圧の機器出力を複数回ぶん自動で登録する | `deviceReadings` コレクション(患者・日時・機器・raw テキスト・パース値)と取り込み API `POST /v1/eye/device-readings`。画面は参照パネルで「写す」だけにする(自動で採用しない) |
| **D5 処置歴・Do** | orders は受診ごと。Do は「前回のカルテから複写」だけ | 処置歴・処方歴を日付ツリーで持ち、項目単位でドラッグする | 新しい保存先は不要。履歴 API `GET /v1/eye/patients/:id/history?kind=orders|prescriptions|diagnoses` があると速い(いまは encounter 一覧から組み立てている) |
| **D6 セット** | orderSets(処置)、phrases(欄に差し込む文) | セット = 病名 + 処置 + 処方(+所見) | orderSets に `diagnoses[]`、`findingsText`、`prescriptions[]` を任意で足す |
| **D7 付箋・配慮マーク・サマリー** | profile に既往などはあるが、マークと付箋はない | 付箋(表示期間)、マーク(当日 / 期限なし)、医師・スタッフのサマリー | `profile.markers[]`、`profile.stickies[]`、`profile.summary` |
| **D8 終了の一括処理** | 確定と受付の状態変更が別々の操作 | 診察終了 → 送信 OK で、会計まで進む | `POST /v1/eye/encounters/:id/close {expectedRevision, appointmentId}`: 確定・状態を checkout に・billing へ載せる、を1つにする。失敗したら全部戻す |

- **テストへの影響**: E3(Enter の順)と D2(exam を代表値として作る)は、既存の exam-inputs / encounter のテストと、カルテの内容ハッシュに影響する。
- **gold ゲートへの影響**: ゲートは fee 側のため、eye の変更は対象外とみられる。ただし D8 で billing を触るなら、会計連携のテストを回す。

## 12. 公開資料では分からないこと(ショールームのデモで確認する)

**検査入力**
1. 大タブの 眼圧 / 色覚 / 屈折 / ステレオ / 前眼部 / 調節 / その他 / 大型弱視鏡 の中身(欄・順番・部品)
2. 視力の小タブのうち、近見視力・CL・ETDRS・コントラスト・装用テストの中身
3. VA のプルダウンの中身(値の並び、TAC 系、n.d. / m.m. / s.l. の表記)と、キーボードだけで入力できる範囲
4. 9方向眼位の異常の入力方法、Cover Test のプルダウンの選択肢
5. 機器値をグリッドへ写す操作(ボタンがあるのか、ドラッグなのか)

**カルテと各画面**
6. 「レイアウト」「パネル表示」のカスタマイズの範囲(保存は利用者ごとか、端末ごとか)
7. カルテを開く操作(ダブルクリックか Enter か)、サマリーと顔写真の出る順番
8. 診療情報入力の「会計して保存終了」と「保存して次へ」の違い、算定チェックのアラートの見た目と出るタイミング
9. 診療予定の Do で作られる予定日の決まり方。「予約」「予約日変更」と予約画面のつながり
10. 医事送信のあと、どの画面に戻るか(次の患者へ進むか)
11. 予約画面、受付登録フォーム、文書作成(紹介状・診断書)、設定画面
12. IMAGEnet R4 の比較画面(並べる数、同期ズーム・同期スクロール、OU、トレンド)とカルテからの呼び出し方
13. タブレット・ペンで使うときの画面(V5 はデスクトップ前提。ペンはシェーマのみか)
14. キーボードショートカット全般

**デモで確認するときのお願い**: 1件の再診について「受付 → 検査入力 → 診察 → 診療情報入力 → 診療予定 → 送信」を、医師役と検査員役でそれぞれ操作してもらい、タップ・クリックの回数と遷移を記録する。撮影の可否は事前に確認し、秘密保持の条件で競合目的の利用を禁じられた場合は、その情報を設計に使わない。
