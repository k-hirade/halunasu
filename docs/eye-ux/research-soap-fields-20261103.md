## 0. 結論

1. **「S/O/A/P の4つの欄」を持つ国内カルテは見つからなかった。** CLINICS・デジカルは、2号紙の左に **「主訴・所見」の大きな自由記載欄が1つ**、右に「処置・行為」がある [確認]。眼科特化の Medius CL も自由記載の「所見」欄が1つで、**「S) かわりなし」「O) 著変なし」「A) 病状に変化なし」「P) 経過観察を継続、点眼継続」といった定型文を差し込んで** SOAP の形にしている [確認: カタログのスクリーンショット]。CLIUS は資料で「SOAP欄」と呼んでいるが、機能一覧上は「主訴所見入力」である [確認]。最近の SOAP 対応は、AI の音声入力で**自由記載欄の中に SOAP 形式の文章を作る**ものになっている(デジカル・CLIUS・CLINICS・Henry)[確認/二次]。
2. **法令が求める区分は SOAP ではなく、2号紙の「既往症・原因・主要症状・経過等」と「処方・手術・処置等」の2つ。** 個別指導では、この2つを区別しない様式が指摘されている [確認]。当社の見開き(左=主訴・経過・所見、右=病名・評価・方針・処方)はこの区分をすでに満たしている。
3. **SOAP の4つの欄は足さない方がよい。** 当社はすでに S/O/A/P を構造化した欄に分けている。同じ内容を2か所に書けることになり、どちらが正なのか、どちらを印刷するのかが曖昧になる。代わりに次の3つを勧める。
   - (a) 見出しに S/O/A/P の小さな目印を付ける(表示だけ)。
   - (b) **所見に「その他(自由記載)」欄を足す。** 今は前眼部・中間透光体・眼底の3部位にしか書けず、眼位・瞳孔・眼瞼・全身状態の書き場所がない。
   - (c) 定型文を「S)/O)/A)/P)」や部位ごとに出し分ける。
4. **足りない項目で優先度が高いのは「瞳孔・対光反射(RAPD)」「眼位・眼球運動」「所見の自由記載(その他)」「既往・全身疾患・内服をカルテ画面に出すこと」「説明・同意の記録」。** 次点が「C/D 比(数値)」「近見視力」「角膜曲率(K値)」「隅角(van Herick / Shaffer)」「点眼アドヒアランス」。米国式の ROS や CPT/E&M のための項目は、日本では不要。
5. **データモデルの変更は、どれも追加だけで済む。** ただし、`validateFindings` は知らないキーを**何も言わずに捨てる**。`validateEncounterSections` は知らない上位セクションを**エラーにする**。どちらも、契約・印刷・比較表示・定型文の対象・衝突判定の単位をそろえて直す必要がある(§6.4)。

## 2. 日本の前提

### 2.1 法令と指導
- **医師法施行規則 第23条**: 診療録に書くのは「住所・氏名・性別・年齢」「**病名及び主要症状**」「**治療方法(処方及び処置)**」「診療の年月日」[二次: 厚労省審議会資料 https://www.mhlw.go.jp/shingi/2005/10/s1005-14b.html]。
- **療担規則 様式第一号(1)の2(2号紙)**: 「既往症・原因・主要症状・経過等」欄と「処方・手術・処置等」欄の2つ。東海北陸厚生局の指導指摘事項には「**「既往症・原因・主要症状・経過等」欄と「処方・手術・処置等」欄とを区別して記載する様式となっていない**」がある [確認: https://kouseikyoku.mhlw.go.jp/tokaihokuriku/iryo_shido/documents/h28-shitekijikou-ika.pdf p.3]。
- 同じ資料の傷病名の指摘には、「**左右の別、部位の記載がない**」「開始日、終了日、**転帰**の記載がない」「長期にわたる『疑い』」がある。外来管理加算については「**患者からの聴取事項や診察所見の要点を診療録に記載していない**」が挙がっている [確認: 同 p.4]。当社は病名に眼・転帰・疑いを持っているので、この点は満たしている。
- 結論: **法令上の必須は「主要症状・経過」と「処方・処置」を分けることで、SOAP の4区分は求められていない。** SOAP は記載の作法として推奨されているもの [確認: デジカルのSOAP解説 https://digikar.m3.com/articles/how-to-choice-emr/article122]。
- 定型文の使いすぎについて: 「毎回ほぼ同じ記載」は査定や指導のリスクになるとの解説がある [二次: CLIUS mag https://clius.jp/mag/2026/07/01/shinryoroku-soap-kakikata/]。

### 2.2 眼科の所見の書き方
- **前眼部・中間透光体・眼底の3区分は、行政の診断書様式にもある。** 例: 「⑨ 眼所見(前眼部、中間透光体、眼底所見)」、視力は「右 × D cyl D °」[確認: 滋賀県 https://www.pref.shiga.lg.jp/file/attachment/5129192.pdf 、長岡市 https://www.city.nagaoka.niigata.jp/download/cate08/file/0805012.pdf]。当社の3部位はこの慣習に合っている。
- 開業医は実際には英略語で短く書く。例: 「**s) ac deep clear / cornea clear**」「**f) disc ma np**」(s = slit、f = fundus、np = 特記なし)[確認: 岐南眼科ブログ https://ginan-eye.com/blog/2025/blog1552.html]。よく使う略語は AC(d/s)、Cornea、Conj、Lens/IOL、Vit opa、PVD、C/D、ME、EOM、XT、pupil、light reflex、F.C.、HM、n.c.、AT/NCT、Dx、R/O、f/u、n.p. [確認: かつむらアイプラストクリニック https://eye-plast.clinic/blog/katsumura-aiplast-clinic-chart-abbreviations/]。
  → **自由記載で速く書けることが前提で、部位ごとの構造化はあくまで補助。**
- 眼位は Hirschberg 法などで、対光反射は直接と間接を分けて見る [確認: 杏林医会誌 https://www.jstage.jst.go.jp/article/kyorinmed/49/3/49_241/_pdf]。

### 2.3 誰が何を書くか
- **医師が書く**: 主訴・経過、細隙灯と眼底の所見、病名、方針、処方。
- **視能訓練士・検査員が書く**: 視力・屈折・眼圧・ケラト、そして**眼位・眼球運動・両眼視・色覚・視野**などの検査テンプレート。京都市立病院の仕様では、眼位(Krimsky・Hirschberg・9方向・4方向)、眼球運動、Worth4灯、近点計、Mチャートなどを「**眼科検査入力テンプレート**」として、医師の経過記録とは別に持たせている [確認: https://www.kch-org.jp/wp-content/uploads/2022/03/2d245f88d0972cb80545103558b00b98-5.pdf 1-5-6]。
- 当社も「検査帯=検査員、所見以下=医師」と分けている。**眼位・眼球運動・瞳孔を検査側に置くか医師側に置くかは設計で決める必要がある**(§6.2)。

## 6. ギャップ分析と推奨

### 6.1 SOAP の欄は足すべきか → 欄としては足さない。表示・定型文・出力で SOAP に合わせる

**理由**
1. 当社の欄はすでに S/O/A/P に1対1で対応している。S/O/A/P の自由記載欄を別に足すと、次の問題が出る。
   - 「主訴」と「S」、「方針」と「P」のどちらに書くか迷う。
   - 二重記載になる。
   - 印刷と紹介状の差し込みが重複する。
   - 前回の Do をどちらから写すかも曖昧になる。
2. 競合で SOAP の欄を分けている国内製品は確認できなかった。Medius の「S)…/O)…」定型文のように、**1つの記載欄の中で接頭辞として書く**のが日本の眼科の実際の形。
3. 法令が求めるのは「主要症状・経過等」と「処方・処置等」の区別で、これはすでに見開きで満たしている。

**代わりにやること**
- **(推奨A) 見出しに SOAP の目印を付ける**(コストはほぼゼロ)。
  - 例: 「主訴・経過 `S`」「検査 `O`」「所見 `O`」「病名・評価 `A`」「方針・処方・次回 `P`」。小さい灰色のバッジにし、設定で消せるようにする。
  - 「SOAP の欄はないの?」という質問には、これで「ある」と見せられる。
- **(推奨B) 所見に「その他」の自由記載欄を足す**(§6.2 の P1-3)。O の受け皿がないことが、実際の欠落。
- **(推奨C) 定型文の対象と見出しを SOAP 単位に整える**。
  - 今の対象は 主訴/経過/評価/方針/スタッフメモ/所見3部位。ここに「所見その他」「説明」を足す。
  - 定型文の一覧を S/O/A/P と部位のタブで出す(Medius の「区分上/区分横」と同じ考え方)。
- **(推奨D) 出力**: 紹介状・返書への差し込みと、将来の AI 下書き(音声→SOAP)は、**今ある欄へ振り分けて入れる**方式にする。AI の出力を「SOAP 欄」という別の塊として保存しない。
  - デジカル・CLIUS は自由記載欄1つに SOAP 文を流し込む。当社は欄が分かれているので、振り分けの方が精度も再利用もよい。
- **(任意E) 「自由記載モード」**: 2号紙のように1欄に書きたい医師向け。ただしデータの一貫性を崩すので**作らない方がよい**。どうしても必要になったら「所見その他」を大きくする方向で対応する。

- SOAP の目印は**見出しの右に小さいバッジで付けるだけ**にし、新しい塊は作らない。
- 新しく足す欄はどれも**空なら「+」チップに畳む**(今の方針と同じ)。再診で開く欄は増やさない。
- 瞳孔・眼位・近見・ケラトは**検査帯の詳細行**に置き、検査員が入れる。医師は読んで確認する(今の分担に合わせる)。
- 「空欄を異常なし」の対象に、その他・瞳孔(正常)を入れるかは**慎重に決める**(§6.5)。
- 狭い画面では今と同じく1列にし、順番は 主訴 → 検査 → 所見 → 病名 → 方針 → 説明 → 処方 → 次回 → +追加。

### 6.4 データモデルの変更(どれも追加。注意点あり)

- 追加するフィールドは**任意**にする。**未入力のときはキーを持たせない**(`validateOptical` の `compactStrings` と同じ)。古いデータの形を変えないため。
- **注意1(黙って消える)**: `validateFindings` は `anterior/lens/fundus` だけを返し、**知らないキーを何も言わずに捨てる**(`index.js` 416〜427行)。
  - `findings.other` などを画面だけに足すと、保存したのに消えるバグになる。**契約を先に直す**。
  - `validateEyeExam`(393行)も同じで、pupil や keratometry を足すときに直す必要がある。
- **注意2(エラーになる)**: 新しい上位セクション(`counselling`、`adherence`)は、`ENCOUNTER_SECTIONS` に足さないと `validateEncounterSections` が `unknown section` で**エラーにする**(147〜148行)。
  - 保存と衝突判定はこのセクション単位なので、次も一緒に直す: 衝突時のマージ、印刷(`print-view.js`)、過去カルテの表示(`encounter-panels.js` の `FINDING_PARTS`)、Do(前回コピー)、定型文の対象(`PHRASE_TARGETS`)。
- **注意3(両眼の値)**: `exam` は今 `EYE_SIDES` だけを持つ構造。`exam.binocular` を足すと、`hasExamValues`、前回値のコピー、確認(`validateExamConfirmInput` は od/os/both)、検査ページなど **od/os だけを前提にしているコード**に影響する。
  - `exam` の外に `binocular` という上位セクションを作る案と、どちらがよいか比べる必要がある。**衝突判定の単位を検査員の入力とそろえるなら `exam` の中が自然。**
- **注意4(印刷)**: 2号紙の印刷に新しい欄を足すときは、「空なら行を出さない」(今の方針)を守る。

### 6.5 リスク

- **SOAP 欄を足すことそのものがリスク**: 二重記載、どちらが正か、Do・印刷・紹介状の重複。→ 目印だけにする(§6.1)。
- **「一括で正常」の拡大**: 瞳孔や「その他」まで一括で「異常なし」にすると、診ていない部位に正常を書く記録になる。
  - 指導では「毎回同じ記載」が問題視される [二次]。
  - → 一括の対象は**医師が見た部位だけ**にする。瞳孔は検査員が「正常」を押す方式にし、記録者を残す。
- **定型文の使いすぎ**: S)/O)/A)/P) の定型文を入れると、毎回同じ文になりやすい。
  - → 前回と同じ文が続くときに目立たせる表示を検討する(今回の範囲外)。
- **既往を画面に出す範囲**: 全身既往は個人情報の度合いが高い。患者帯に出す範囲(医師だけ、またはロールで制御)は既存の権限設計に合わせる。
- **AI の SOAP 生成(将来)**: 国内 AI という方針に従う。生成した文は**下書きとして各欄へ振り分ける**だけにし、確定は医師が行う。
