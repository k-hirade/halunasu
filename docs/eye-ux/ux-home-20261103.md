## 0. 結論（先に要点）

1. **ホームを「受付の縮小コピー」のまま残す理由はない。** 今の `/` は受付と同じ予約データを、より情報の少ない 2 行カード（全員に「予約」「カルテ未作成」タグ）で並べ直しているだけ。しかも**自動更新がない**（受付は 15 秒ごとに更新）ので、医師が見ると情報が古い。
2. **他社の答えは「医師には自分の待ち行列と未処理の仕事を見せる」。** デジカルはログインすると受付画面に入り、カルテ画面の上部に「**患者リスト（診察待ちの患者だけ）＋人数バッジ**」を置いている [確認]。Epic は医師ごとの Schedule / Patient List と In Basket（未処理タスク）を分けている [二次]。ModMed は担当医の Agenda View とタスク（To Do を受診に紐づける）[二次]。CLINICS は受付一覧がハブで、別のホームはない [確認]。
3. **提案: `/` を「診察」（医師・視能訓練士の作業場）に変える。** 受付と同じ「段階で区切った 1 人 1 行のリスト」と人数チップを使い、中身を医師向けに絞る: **診察待ち → 診察中 → まもなく（検査中・散瞳中・受付済）→ 来院予定（たたむ）**。チップの右側に **要対応（未確定カルテ・紙カルテ要約の未確認・文書の下書き）** を並べ、押すとその一覧に切り替わる。日付送りと「新規患者を登録」の大きなボタンはホームから外す（受付と検索に移す）。
4. **ヘッダーに致命的な表示崩れがある。** 768〜約 1150px で「会計連携」「設定」が患者検索の下に隠れて押せない（スクリーンショット home-768 / home-1024 / menu-1024 で確認）。iPad 横・小型ノートで設定に行けない。
5. **患者検索は日本語入力で事故が起きる作り。** ①変換確定の Enter で候補の先頭患者が開く恐れ（IME 判定なし）②ひらがなで検索するとカタカナ名に当たらない（サーバーは NFKC 正規化のみ。CLINICS は「ひらがな→カタカナ」対応 [確認]）③名だけ（「ハナコ」）では当たらない（前方一致のみ）④結果に生年月日がなく同姓同名を区別できない ⑤スマホでは検索がメニューの中に隠れている。
6. **新規患者登録は重複登録を防げない。** 同じ氏名・カナの患者がいても確認なしで作る。エラーがダイアログの裏（ページ上部）に出て見えない。同じダイアログが home と reception に 2 つある。保険はレセコンで登録するという案内もない。
7. **ログインは毎回「病院コード」を手で打つ。** 端末に覚えさせる仕組みがない。iOS で個人 ID の先頭が大文字化される設定（autocapitalize）が残っている。パスワードを忘れたときの案内がない（デジカルはログイン画面に「ログインできない・パスワードをお忘れの場合」[確認]）。

**読み取れること**
- 国内の汎用クラウドカルテは「受付一覧＝ホーム」で、ホームを別に持たない。持つ場合も、中身は**医師の待ち行列（診察待ちだけ）＋人数**で、全体の流れの表は受付に任せている（デジカル）。
- 海外は「自分の予定」と「未処理の仕事（受信箱）」を分ける。眼科では、未確定カルテ、文書、外部資料の確認が溜まりやすい（推測）。
- **この製品の場合**: 受付が全体の流れを持つようになったので、`/` を二重の当日一覧にしておく意味はない。医師・視能訓練士の「次に診る人」と「やり残し」に絞れば、受付と重ならない。

### 1-3. 新規患者登録（保険とレセコン）

- **デジカル（ORCA 連動版）**: 新患は **ORCA の「12 登録」で頭書き（氏名・生年月日・性別・保険）を入力**し、ORCA で受付するとデジカルにも患者ができる。患者番号は自動発番（`*` を入力）か任意番号。**氏名・生年月日など頭書きの修正も ORCA で行う** [確認] p.48–50, p.64。再来は受付時に「未確認保険公費」を [未]→[済] で確認する [確認]。
- **CLINICS**: 「当日受付」→「＋新規患者登録」で**氏名・性別・生年月日**を登録。チェックイン機能が有効なら、**オンライン資格確認の情報が基本情報・連絡先に自動転記**される [二次: ヘルプ記事 8850360 の検索要約。本文は取得できず]。
- **Epic の受付研修資料**: 新しいカルテを作る前に、名前＋生年月日などで**必ず既存患者を検索してから作る**（重複カルテ防止）[二次] t2flex Guide 52。
- **含意**: レセコンと連動する国内製品では、カルテ側の新患登録は「**氏名・カナ・生年月日・性別・患者番号**」の最小限で、**保険はレセコン（または資格確認）の仕事**。Halunasu もレセコンはアダプター方針なので、登録画面で保険を扱わず「保険はレセコンで」と明示するのが正しい。重複防止の「先に検索」は全製品共通。

### 1-4. ログイン

- **デジカル**: ログイン ID とパスワード（端末にはクライアント証明書を入れて施設を識別）。**5 回失敗でロック**、管理者が施設管理で仮パスワードを発行。ログイン画面に「**ログインできない・パスワードをお忘れの場合**」のリンク。ログイン後は受付画面 [確認] p.8, p.16–17。電子処方箋用の HPKI ログインは 18 時間有効 [確認] p.277。
- **Epic・ModMed**: 指紋・Face ID（PocketEMA）[二次]。共有端末でのすばやい利用者切替（推測。公開資料で確認できず）[未確認]。
- **含意**: 施設コードを毎回打たせる製品は確認できなかった（デジカルは証明書で省略）。**病院コードは端末に記憶し、表示だけしておく**のが妥当。

### 1-5. グローバルナビ

- デジカル: 受付画面とカルテ画面でヘッダーのアイコン列が変わる。どちらにも「**検索**」「お知らせ（未読バッジ）」「ヘルプ」、右上の**ログイン名メニュー**（施設管理・パスワード変更）[確認] p.27–29。カルテ画面に「患者リスト（診察待の人数バッジ）」。
- CLINICS: 機能の場所が分からないという口コミ（過去調査 §278）。
- **含意**: ①検索はどの画面でも見える場所に常時置く ②利用者名をメニューにして、ログアウトや設定はそこへ入れる ③医師向けの入口に**診察待ちの人数バッジ**を付ける。

```
│ © ハルナス 眼科カルテ │        │ ログインできない・パスワードを忘れた   │        │
│  約 36%               │        │ → 院内の管理者に再発行を依頼してください │        │
└──────────────────────┴──────────────────────────────────────────────────────┘
```

- **病院コードの記憶**: ログインに成功したら病院コード（秘密ではない）だけを localStorage に保存し、次回は「病院 YMMT01 [変更]」と表示して個人 ID にフォーカスする。病院名はログイン前には分からないので**コードだけを表示**する（病院名を出すにはログイン前に引く API が必要で、施設の存在が外から分かる問題が出るのでやらない）。[変更] を押すと今の入力欄に戻る。共通部品（`LoginFormView`）の props に `rememberOrganization` を足し、眼科側で有効にする（他製品の挙動を変えない）。
- 病院コード欄: `autoComplete="off"`（または `"organization"` をやめる）、`autoCapitalize="characters"`（コードが大文字英数字の場合。形式はサーバーで正規化されているので見た目だけ）。個人 ID: `autoCapitalize="none" autoCorrect="off" spellCheck={false}`。
- ログインボタンを入力欄と同じ幅に。送信中は「ログイン中…」。失敗表示は `role="alert"`。パスワード欄で Caps Lock を検知したら（`getModifierState("CapsLock")`）注意を出す。
- 宣伝の面は 1440px で約 36% に縮める（`.operator-gate-shell` の列比を眼科の globals.css で上書き）。1024px 以下では面を 120px の帯にし、390px では今と同じく見出し 1 行だけ（今の上書きを残す）。
- 「パスワードを忘れた」は今のところリンク先がないので、**文言だけ**（管理者に依頼）。再発行の画面は作らない。

## 5. 入れなかった案（事故やバグが起きやすいもの）

- **役割でログイン後の画面を自動で振り分ける**（事務は受付、医師は診察）: 戻るボタンとの相性やリダイレクトの繰り返しが起きやすい。まず「ブランドを押すと診察」「受付はナビの左端」で十分。必要なら後で利用者ごとの既定画面を設定に置く。
- **ホームで受付と同じ全段階の操作**（会計済みなど）: 二重の操作場所になり、どちらで何をしたか分からなくなる。ホームは診察に関係する操作だけ。
- **最近の患者を localStorage に保存**: 共有端末に氏名が残る。sessionStorage にしてログアウトで消す。
- **6 桁の生年月日（`500304`）**: 1950 年か 2050 年か決まらない。受け付けない。
- **ログイン前に病院名を表示**: 施設コードから病院名が分かる API は、外から施設の存在を調べられてしまう。コードだけを表示する。
- **検索の右側に患者の詳細パネル**（Henry の 2021 年の改修と言われる [未確認]）: ドロップダウンの中で操作が増え、フォーカス管理が難しい。患者ページへの移動で足りる。
