# 競合調査と改善案: 文書の作成・編集 / 文書の印刷

調査日: 2026-11-03 / 対象: `/documents/[id]`(`DocumentEditor`)、`/documents/[id]/print`(`DocumentPrint`)、作成入口 `DocumentsPanel`、API `services/eye-api/src/documents.js`

> 確度の表記: **[確認]** = 公式ヘルプ・マニュアル・通知の原文で確認した / **[二次]** = ベンダーの解説記事や第三者資料で確認した / **[未確認]** = 公開情報で確認できなかった(推測は「推測」と書く)

## 0. 結論(先に要点)

1. **他社は「穴埋め式の帳票」と「カルテからの差し込み選択」の組み合わせ。** 1つの大きなテキスト欄に定型文を流し込むだけの製品は、調べた中にはなかった。デジカル・CLINICS・Medicom はどれも、**項目ごとの欄がある帳票(様式11 に沿った枠)**を出し、傷病名・処方・検査値をカルテから入れる。CLINICS は作成時に「**傷病名を選択する / 既往歴を選択する / 投薬を選択する**」画面を出し、**どの病名・どの処方を載せるかを医師が選ぶ** [確認]。Medicom は「**カルテの記載内容をまとめた画面を同時に開き、クリックした項目を紹介状に転記する**」 [二次]。
2. **差し込み元は「最新の確定カルテ」が基本。** デジカルの検査結果は「登録されている最新日付の検査結果」、処方は「最新日付のカルテの処方」 [確認]。CLINICS の投薬は「診察完了した内容のみ」 [確認]。当院の「直近の確定カルテ」方式と同じだが、**他社は差し込んだ日付や元のカルテを画面で見せ、選び直せる**。当院は選び直せず、何日のカルテから入ったかも本文の1行でしか分からない。
3. **確定前に完成形を見せる。** デジカルは作成すると PDF を別タブで開き、編集後も「右下の[編集]で文書プレビューが表示」 [確認]。CLINICS は「下書き保存 → 印刷プレビューで確認 → 確定(確定後は編集不可)」 [確認]。当院は確定と印刷プレビューが別の画面に分かれ、**下書きのまま印刷すると紙に「下書き」の印が出ない**(下記 §2 の P-1)。
4. **様式11 の必須の枠が足りない。** 厚労省の別紙様式11(令和8年度版)には、紹介先・担当医「殿」、紹介元の所在地・名称・電話、**医師署名(又は記名押印)**、患者の住所・電話・職業、**傷病名 / 紹介目的 / 既往歴及び家族歴 / 症状経過及び検査結果 / 治療経過 / 現在の処方 / 備考** の枠がある [確認]。当院の本文には「治療経過」「家族歴」「備考」がなく、印刷には署名欄・患者住所・電話がない。差出人の医療機関名も、施設の登録がなければ空のまま印刷される(現状のスクリーンショットがそう)。
5. **宛先はマスタ(候補)から選ぶ。** モバカルは設定済みの連携施設から「施設名を入力すると候補が出て選択」、未入力で欄を押すと登録施設の一覧 [確認]。Eyefinity は宛先の氏名・住所・FAX を差し込み項目で持つ [確認]。当院は3つの自由入力欄だけで、2回目以降も毎回手で打つ。眼科は大学病院の **専門外来・担当医を宛先に書く** 運用がある(北里大学病院眼科は疾患別に「白内障専門 または ○○医師 宛て」を指定) [確認]ので、宛先の再利用の効果が大きい。
6. **眼科ならではの差し込みは「異常所見だけ」と「全部」の切り替え。** Eyefinity の差し込み項目は `@VisitExam`(異常所見だけ。正常所見は入らない)と `@VisitExamDetailed`(正常も含め全部)の2種類 [確認]。当院は全部を入れるだけ。

**提案(§3):** 1つの大きな textarea を、**「宛先カード」+「紹介目的」+ 様式11 の見出し順に並べた本文」+「右側に常時出る A4 プレビュー(印刷と同じ部品)」**の2ペインに変える。カルテからの差し込みは「＋カルテから挿入」パネル(病名・検査値・処方・既往・画像をチェックして入れる)にする。印刷は **下書きなら紙にも「下書き」の透かし**を出し、A4 の `@page` 指定と署名・押印欄を付ける。第1段階は **API を変えず** 画面だけで行い、構造化した本文(sections)や宛先マスタは第2段階の API 変更として分ける。

## 1. 製品ごとの調査結果

### 1-1. エムスリーデジカル — 様式の入力画面 → PDF [確認]
- 出典: 操作マニュアル(ORCA連動版) https://digikar.m3.com/documents/digikar_manual.pdf p.118〜126, p.212〜216
- **入口:** 診察画面の患者情報エリア「ファイル」→[文書作成]→ プルダウン「①診療情報提供書」(p.118)。
- **自動で入る項目(p.118):**
  - 紹介元の医療機関名・住所など ← 施設管理の医療機関情報
  - 患者名・**患者住所**など ← 登録済みの患者情報
  - 傷病名 ← その患者に登録された傷病名
  - 検査結果 ← **最新日付の検査結果**
  - 現在の処方 ← **最新日付のカルテの処方**
- **出力(p.119):** [作成]で **PDF が作られ別タブで表示**、ファイルタブに PDF が自動保存される。編集は鉛筆マーク →「文書編集」→ 右下の[編集]で **文書プレビュー** が出る。
- **院内様式(p.121, p.212〜216):** Word/Excel の雛形を登録できる。`DK_PATIENT_NUMBER` などのパラメータを貼ると自動で入る。作成時に「文書医師選択」ダイアログで医師を選んでダウンロードする(医師名の差し込みは医師の選択で決まる)。
- **見た目:** 入力画面のスクリーンショットはマニュアルにあるが、テキスト抽出できず細部は **[未確認]**。

### 1-2. CLINICS カルテ(メドレー) — Word 雛形+差し込み項目の選択 [確認]
- 出典: 「【カルテ】文書雛形を作成する」 https://intercom.help/clinics/ja/articles/4455225 (2026/10/2 更新)、主治医意見書の作成 https://intercom.help/clinics/ja/articles/14834621
- **パラメータ(差し込み項目):** 書類の作成日(西暦/和暦)、医療機関名・住所・電話・ログイン者名、カルテ番号、患者名・カナ・性別・**郵便番号・住所・電話**・年齢・生年月日(西暦/和暦)。
- **カルテ情報:** 傷病名(最大30)、既往歴(最大30)、投薬(最大30。処方グループ単位で選べる。「薬剤名・用法用量・処方日数・コメント」が入る)。**投薬は「診察完了」した内容のみ**。
- **作成時の選択画面:** 傷病名・既往歴・投薬のパラメータが入った雛形を作るときは、「**傷病名を選択する」「既往歴を選択する」「投薬を選択する**」をクリックし、**書類に引用したい情報を選ぶ** 画面が出る。全部を自動で入れるのではない。
- **流れ:** 書類 → 文書作成 → 下書き保存 → 印刷プレビューで確認 → 確定(確定後は編集できない)(14834621 の要旨。原文は検索結果の抜粋で確認 [二次])。
- **補足:** 区切り記号に「・」や「，」を使うと、選んだ数が少ないときに記号だけが残る、という注意書きがある。**空の項目の見え方** まで気にしている。

### 1-7. 厚労省 別紙様式11(診療情報提供書) [確認]
- 出典: 令和8年度診療報酬改定の様式 https://www.pt-ot-st.net/pdf/2026/r8besshi/b11.pdf (原本は厚労省通知の別紙様式11)。医科の様式は参考で、**示された事項がすべて入っていれば同じ形でなくてよい** [二次: knowlety.jp]
- **並び(上から):**
  1. 紹介先医療機関等名 / 担当医 ___ 科 ___ **殿** / 年月日
  2. 紹介元医療機関の所在地及び名称 / 電話番号 / **医師署名(又は記名押印)**
  3. 患者の枠: 氏名 / **住所** / 性別 / **電話番号** / 生年月日(歳)/ **職業**
  4. 本文の枠(この順): **傷病名 → 紹介目的 → 既往歴及び家族歴 → 症状経過及び検査結果 → 治療経過 → 現在の処方 → 備考**
- **記載上の注意:** ①必要なら続紙を付ける ②必要なら画像診断のフィルム・検査の記録を添付する ③紹介先が保険医療機関以外(薬局・市町村など)なら **患者住所・電話番号を必ず記入** ④2回目以降や手渡しなど作成元が明らかな場合は、医師名は **記名のみで署名・押印を省略してよい**。
- **電子的な提供:** 電子カルテ情報共有サービスでは、診療情報提供書は「HS038 診療情報提供書 HL7 FHIR 記述仕様」、**宛先の指定が必須**、添付は可能、保存6か月。**当面は医療機関の判断で電子署名なしでも共有できる** [確認: 厚労省資料 https://www.mhlw.go.jp/content/10808000/001262035.pdf ほか]。オンライン資格確認の導入が前提。
- ORCA 系の MEDPost は HPKI(医師資格証)のタイムスタンプ付き電子署名で紹介状をやり取りする [二次: https://www.orcamo.co.jp/doc/MEDPost-1612.pdf ]。

### 1-8. 眼科の紹介の実際 [確認]
- 北里大学病院眼科の紹介フロー(2020/10/7版) https://www.khp.kitasato-u.ac.jp/SKA/ganka/reservation/file/flowchart2.pdf

  - → 眼科の紹介状では **「宛先の専門外来」と「緊急度」** が実務上の重要項目になる。

## 3. 改善案

### 3-1. 方針
1. **2ペインにする: 左=入力、右=A4 プレビュー(常時表示)。** 右のプレビューは印刷ページと **同じ部品(`LetterSheet`)** を使う。打った内容がすぐ紙の見た目で見える(デジカル・CLINICS の「プレビューで確認してから確定」を、画面を移らずに行う)。
2. **入力欄の並びを様式11 に合わせる:** 宛先 → 紹介目的(+緊急度) → 本文(傷病名 / 既往歴・家族歴 / 症状経過・検査結果 / 治療経過 / 現在の処方 / アレルギー / 備考) → 添付。**表題・発行日は「文書の設定」として畳む。**
3. **カルテからの差し込みは「選んで入れる」形にする。** 「＋カルテから挿入」パネルに、**元にするカルテの日付** を選ぶプルダウン(既定は当日の下書きカルテがあればそれ、なければ直近の確定カルテ)と、病名・検査値・所見・処方・既往・画像のチェック一覧を出し、選んだものを本文のカーソル位置に入れる(CLINICS の選択画面+Medicom のクリック転記)。所見は「異常のみ / すべて」を切り替える(Eyefinity)。
4. **宛先は候補から選ぶ。** 第1段階は、この患者の過去の文書の宛先(患者の文書一覧 API が返す `recipient`)を候補に出す。第2段階で院内全体の「よく使う紹介先」を API に足す。
5. **確定前チェックを画面に常に出す:** 「宛先が空」「紹介目的が空」「差出人(施設名・住所・電話)が未登録」「差し込み元が前回のカルテ」の4つ。止めるのは **紹介目的の空だけ**(紹介状の場合)。他は警告に留める(他院の運用を縛らない)。
6. **印刷は「紙として正しく」する:** 下書きは紙にも透かし、A4 の余白、署名・押印欄、空の見出しは印刷しない、2枚目以降に患者名とページ番号。
7. **確定済みは読む画面にする:** 確定後は入力欄を隠し、プレビュー(紙の見た目)を主役にする。上部に「確定 11/03 14:20 院長」「複製して修正」「印刷」。

### 3-5. 操作の決まりごと
- **[印刷プレビュー] は保存してから開く。** `await save()` が成功してから `window.open()`。失敗したら開かずにエラーを出す(P-2 の対策)。
- **⌘S / Ctrl+S** で即保存。`beforeunload` で未保存があれば確認を出す(E-9, E-10)。
- **確定ダイアログに「確定前の確認」の結果と縮小プレビューを出す。** 紹介目的が空の紹介状は確定ボタンを無効にする(画面側のチェック。API はそのまま)。
- **差し込みはカーソル位置に追記するだけ。** 既存の本文を置き換えない(書いた文章を消さない)。「元のカルテ」を変えても、既に入れた本文は変わらない。
- **確定済みの文書を開いたとき:** 左の入力欄を出さず、プレビューを中央に大きく出す。上部に [印刷] [複製して修正]。
- **宛先候補はクリックで3欄(医療機関・診療科・医師)をまとめて埋める。** 入力中は候補を前方一致で絞る。

### 3-6. 本文は「構造化した欄」か「1つの欄」か
- **結論: 第1段階は1つの textarea のまま(保存形式 `body: string` を変えない)。** 次の改善だけ入れる:
  - 内容に合わせて高さを伸ばす(`field-sizing: content` が使えるブラウザはそれ、なければ `scrollHeight` で高さを合わせる)。二重スクロールをなくす(E-2)。
  - 本文の上に「目次」チップ。【見出し】の行を **読み取り専用で** 拾い、押すとその行へカーソルを移す。見出しの下が空なら目次のチップを赤い点線にする。
  - **画面上で本文を見出しごとの欄に分割して編集させることはしない。** 入力中に「【」を打つと区切りが変わってフォーカスが飛ぶ、往復で空行がずれる、などのバグを生みやすいため。
- **第2段階(API 変更): `sections` を足す。** `document.sections = [{ key: "purpose", label: "紹介目的", text }]` を保存し、`body` はサーバーが `sections` から組み立てる(印刷・内容ハッシュ・会計連携は今の `body` を使い続けられる)。`schemaVersion: 2`。v1 の文書は今の textarea で開く。紹介目的・宛先が様式の欄として独立するので、FHIR(HS038)の項目に対応させやすい。

**P2 — 作成の入口と一覧**
14. `DocumentsPanel`: チップで即作成をやめ、**小さなダイアログ**(種類・元のカルテの日付・宛先候補)を経て作成する。作成ボタンは1つ「＋文書を作成」にまとめる。(D-1, D-2)
15. 一覧を「下書き」「確定」の2グループに分け、種類のバッジ(紹介/返書/診断書)と宛先を列で揃える。(D-3)
16. 定型文の見直し: 紹介状の見出しを様式11 の順と名前に(「症状経過及び検査結果」「治療経過」「既往歴及び家族歴」「備考」を追加)、診断書は「傷病名 → 所見 → 付記(上記の通り診断いたします)」の順に、返書の先頭に「○月○日付でご紹介いただいた…」の行。`renderTemplate` の変更なので **新しく作る文書だけ** に効く(既存の文書は変わらない)。(E-13, E-14)

### 3-8. API の変更が要るもの(要判断)
| # | 内容 | 理由 | 影響 |
|---|---|---|---|
| A-1 | 下書きの破棄(`POST /documents/{id}/discard` で `status: "discarded"`、一覧から除く) | 押し間違いの下書きがたまる(D-1) | 会計連携は確定文書しか見ないので影響なし。監査ログに残す |
| A-2 | `recipient` に `honorific`(御侍史/殿/御中)、`urgency`、`purpose` を足す | 敬称・緊急度・紹介目的を独立した項目に | 内容ハッシュの対象を増やすときは `schemaVersion` を上げる |
| A-3 | 院内全体の紹介先候補 `GET /v1/eye/documents/recipients`(確定済み文書の宛先を集計) | 宛先マスタの代わり(マスタ画面を作らずに済む) | 読み取りのみ |
| A-4 | `sender.doctorName` に役割を含まない氏名を入れる | 印刷の署名が「院長(管理者・医師)」になる(P-4) | プラットフォームのユーザー情報に氏名フィールドがあるか要確認 |
| A-5 | `patientSnapshot` に住所・電話(文書用) | 様式11 の注意③(紹介先が医療機関以外) | 個人情報の範囲が広がるので、文書の作成時だけ取り込む |
| A-6 | `sections`(§3-6 第2段階) | 様式の欄・FHIR 対応 | `body` はサーバーで組み立てて互換を保つ |
| A-7 | 画像の添付(`attachments: [fileId]`)と印刷への貼り込み | 眼科紹介で OCT・眼底写真を添える(様式11 注意②) | ファイルの URL の有効期限と印刷のタイミングに注意 |
| A-8 | 印影画像の登録・PDF 保存・電子カルテ情報共有サービス | 他社並みの出力 | 後回し。電子署名は当面任意(§1-7) |

### 3-9. 入れないもの(バグや誤用を招きやすい)
- **本文の見出しごとの欄に、画面上で分割して編集させること**(§3-6 の理由)。
- **差し込みの自動更新**(カルテが変わったら文書も書き換わる)。医師が書いた文章を黙って変えることになる。差し込みは常に手動・追記のみ。
- **リッチテキストエディタ**(太字・表)。保存形式が変わり、内容ハッシュ・印刷・会計連携に波及する。見出しの太字は描画側で行う。
- **プレビューの中での直接編集**。編集は左の欄だけ、プレビューは見るだけ。
