# カルテ入力画面(/encounters/[id])の競合調査・現状監査・再設計案

作成: 2026-11-03 / 対象コード: `components/encounter-editor.js`, `encounter-sections.js`, `encounter-panels.js`, `encounter-dialogs.js`, `patient-banner.js`, `sketch-pad.js`, `app/globals.css`

凡例: [確認] 公式ページ・マニュアル・医療機関の手順書で確認 / [二次] 第三者の記述・検索スニペット / [未確認] 推測・資料なし

## 0. 結論

1. **今の画面は「医師が確認する画面」ではなく「入力フォームを全部広げた画面」です。** 1440px でページの高さは 3,035px、11 セクションがすべて同じ重さのカードで縦に並びます。操作要素は 131 個で、最初の画面に見えるのはそのうち 69 個です。値が空の欄(オーダー、シェーマ、眼鏡、スタッフメモ、評価、現病歴、屈折 S/C/Ax)も、値のある欄と同じだけ場所を取っています。
2. **前回の値が3か所に重なって出ています。** 左の過去カルテ、検査欄の「前回 1.0」、右の「前回との比較」です。そのうえ右の「確定前の確認」は、通常の途中状態(検査値の確認待ち、引き継ぎ処方)を赤い警告で常に表示しています。色が「異常」を意味しなくなっています。
3. **競合の共通形は「左 = 過去、中央 = 今日の2号紙(左に所見、右に処置・処方)、操作は上か右下に1つ」です。** CLINICS、デジカル、Medius、京都市立病院の仕様書(見開き)がこの形です。眼科の視力・眼圧は、日本の表記どおり **眼ごとに1行**(`RV=0.9(1.2×S−1.00D C−0.50D Ax180°)`)で読むのが自然です。今の「行 = 項目、列 = 眼」で入力欄を大きく並べる表は、検査員の入力画面(`/exam`)の形です。
4. **提案は次のとおりです。**
   - (a) 右の補助パネルを常設しないで引き出し式にし、中央を **2号紙の見開き**(左 S/O、右 A/P・処方)にする。
   - (b) 検査は **眼ごとに1行の密な表** にして、前回値は各眼の下に1行で添える。
   - (c) 空のセクションは「+ 追加」チップ1行にまとめる。
   - (d) 処方は1剤1行の読める文で表示し、押したときだけ編集欄を開く。
   - (e) 確定前の確認は「確定する」ボタンの件数表示に集約する。
   
   この5つで、典型的な再診(本デモの内容)は **1440×900 の1画面にほぼ収まる見込み**(推定 高さ 950〜1,050px)です。API の変更は不要です。

## 1. 競合はこの画面をどう作っているか

### 1-1. 製品別

**CLINICSカルテ(メドレー)**
- 画面の構成 [確認](intercom 2892066 / 3637857)
  - 左: メニューと診察履歴。
  - 中央: 2号紙。上に「主訴・所見」、下に「処置・行為」。
  - 右: オーダー・セットの検索。
  - 履歴は左に日付の一覧として出て、無限スクロールで読み込まれます。**日付を押すと、その回だけが展開されます。** 当日カルテには「編集中」のバッジが付きます。
- 複写(Do)[確認]: 開いた過去回の各グループ(主訴・所見、処置・行為、シェーマ)の右上にある **「→」1つ** で今日のカルテに転記します。シェーマは1枚ずつです。
- 新カルテ画面(2025-11〜、旧画面は 2026-03-11 に廃止)[確認](12759289)
  - 主訴・所見欄の高さはドラッグで変えられ、その高さが記憶されます。
  - 処置行為エリアとセットエリアの境界もドラッグで動かせます。
  - 処置行為の右上に「帳票」ボタンがあります。
- 主訴・所見欄は、オーダー入力中は既定で隠れます。ピンで常時表示に固定できます [確認](2892062)。つまり **使っていない領域は畳む** 設計です。
- 完了ボタン [確認](2892077)
  - **画面右下の「診察を完了する」1つ** です。押せるのは担当医だけです。
  - 完了すると「本日の診察待ち一覧」が出て、次の患者に移れます。
- 処方 [確認](3652589)
  - 処置・行為の中で、薬剤はグループ単位にまとまります。
  - 外用薬は全量を「( )」欄に入れ、コメントは各行の「︙」から付けます。
  - 1薬剤が1行で表示されるかどうかは本文に書かれていません [未確認]。
- 本文の既定の文字サイズは 14px です [確認]。

**エムスリーデジカル**(公式操作マニュアル PDF、2026/10/6 版)[確認]
- 3列構成です。
  - 左: 患者情報のタブ(診療履歴、投薬履歴、検査結果、傷病名など)。Shift+数字でタブを切り替えます。
  - 中央: 主訴・所見と処置行為。
  - 右: オーダーとセット。
- 過去カルテは左の「診療履歴」に出ます。**グループを押すと、そのグループがそのまま今日のカルテに複写されます。** 主訴所見全体、処置行為全体の複写ボタンもあります。
- 保存系のボタンは **右上にまとめて「送信 / 検査依頼 / 保存 / 印刷 / 次へ」** と並びます。警告は保存したときに一覧で出ます(常時は出しません)。
- 投薬履歴、検査結果、傷病名は **別ウィンドウで開けます**。見ながら書く使い方を想定しています。
- 「学習リスト」: 過去の用法・日数を頻度順に出します。

**Henry**
- 編集画面の公開資料は見つかりませんでした [未確認]。
- 口コミには「画面上のボタンの数も少なく、他のカルテよりも見た目がすっきり」とあります [口コミ、既存調査]。

**CLIUS**

**CLIPLA Eye(眼科専用で、直接の競合)**
- 「1画面完結」をうたっています [確認](導入事例 Vol.23)。
  - 画面は受付とカルテの2つだけで、病名入力や処置入力の画面を開け閉めしません。
  - **右眼と左眼はタブで切り替えます。**
  - 自費の場合は画面の色が変わります。
- レフケラは「見慣れたレシート形式」で表示します [確認]。
- 検査値の入力は **iPad の検査員用画面** で行います [確認]。医師のカルテとは役割が分かれています。

**Medius CL(ビーライン)**
- 「検査結果は右、所見記載は左に配置したい…などの好みに合わせ、医師ごとにレイアウトを変更できる」(My Room)[確認]。

**NAVIS-CL(NIDEK)**: 2号紙スタイルで、タブレットでシェーマを描けます [二次]。

**京都市立病院の仕様書(Claio / C-Note)**
- 2-1-2「カルテ入力は**見開き型**」[確認]。
- 2-1-3「経過記録に検査データや画像を **貼り付け**」[確認]。

**海外の製品**
- Epic Kaleidoscope [確認、ユタ大学 Moran の院内手順書]
  - 視力は sc/cc × OD/OS の箱に入れ、Method の既定は Snellen です。
  - 眼圧は値を入れて Method を選ぶと **時刻が自動で入ります**。
  - 署名は Wrap Up(最後のまとめ画面)から行います。
- Eyefinity [確認、公開ヘルプ]
  - Visit Overview の各領域に進捗表示があり、橙から緑に変わります。**未完了は警告色ではなく「途中」の色です。**
  - Finalize は画面上部の Action Bar にあります。
  - 患者カルテの「Clinical summary」は開閉式で、**直近3回の日付・VA・IOP・診断・処置・目標眼圧を表** で出します。
  - 確定前は編集画面、確定後は PDF の Visit Note として開きます。
- NextGen Ophthalmic [二次]
  - Eye Summary は当日と過去の所見をグリッドで並べます。
  - VA グリッドは過去値の閲覧専用です。
  - 引き継ぎ(Copy forward)は3種類あります。
- ModMed EMA [二次]
  - 前回の検査・所見・計画を引き継げます(pull forward)。
  - 屈折の履歴を並べて見て、ワンタッチで当日に取り込めます。
  - VA・IOP・C/D の推移をタイムラインで出します。
  - 確定前に、検査の充足度を示す表示が出ます。
- Nextech: 1ページ型の検査画面で、緑内障フローシートがあります [既存調査]。
- Compulink: OneTab(1画面で記載)[二次]。使いやすさの評価は 9.1% でした(AAO 2015)。

### 1-2. 日本式の視力・眼圧の表記
- 視力 [二次、教育サイト。行政の診断書様式も同じ欄構成で確認]
  - `Vd=0.2(1.2×S−1.75D C−0.50D Ax180°)`。RV/LV という書き方もあります。
  - **括弧の外が裸眼、内が矯正** で、**眼ごとに1行** で書きます。
- 眼圧: 「R 14 / L 16 mmHg(NCT)」形式の一次資料は見つかりませんでした [未確認]。ただ、紙カルテでもレセプトでも左右を並べて書くのが一般的です。Epic は「値 + 方法 + 時刻(自動)」を1組で持ちます [確認]。

## 3. 再設計案

### 3-1. 方針(受付ボードの方針を当てはめる)
1. **読むのが先、書くのはその場で。** 値がある欄は読める文として表示し、押すと編集できる(処方、検査の詳細)。値がない欄は「+ 追加」チップにする。
2. **今日の2号紙を見開きにする。** 左が S/O(主訴・経過、検査、所見、シェーマ)、右が A/P(病名、評価・方針、処方、次回)。検査だけは左右を横断する帯にする。
3. **前回は1か所にまとめる。** 検査値は各眼の行の下に「前回」を1行添える。それ以外は左の過去カルテで見る。右パネルの「前回比較」は「変更点」として左のタブに移す。
4. **主操作は1つ。** 「確定する」1つだけにし、確認待ちの件数はそのボタンに出す。止まる理由と確認作業は既存の FinalizeDialog で解消する(すでに対応済み)。
5. **色は状態にだけ使う。**
   - 赤: 止まる理由、アレルギー、眼圧が閾値を超えた値。
   - 黄: 確認待ち、引き継ぎ。
   - 緑: 確認済み、保存済み。
   - 右眼・左眼は文字色(R = 赤系、L = 青系)と細い左罫線だけにし、面で塗らない。

### 3-3. ブロックごとの中身

**患者帯(1行)**
- 並び順: ← 氏名・カナ、年齢・性別・生年月日、アレルギー(赤バッジ・常時)、主病名1つ + 「ほか n」、✎(編集)| 右寄せ: 診療日・区分(ボタン表示)、保存状態、印刷、確定する(件数付き)、…。
- 「下書き」タグは「確定する」ボタンがあれば状態が分かるので外す。確定後は「確定済み v1」だけを出す。
- 項目ジャンプ(`section-jump`)は 1024px 以上では出さない(ページが短くなるため)。

**検査(全幅の帯、行 = 眼)**
- 1行の並び: 眼 | 裸眼 | 矯正 | 矯正レンズ S・C・Ax | 眼圧 | 方法 | 確認。
- 他覚屈折、矯正の種類・時刻、近視治療中は「詳細 ▾」の中に入れる。**値があるときは自動で開く**ので、値が隠れることはない。
- 各眼の行の下に「前回 10/13: 1.0(1.2) 13」を 13px のくすんだ色で1行出す。今の各欄の下の hint はやめる。
- 確認
  - 各行の右端に小さい「確認」を置き、確認済みなら「✓ 院長 10:32」と表示する。
  - 帯の見出しに「両眼を確認」を置く。中身は既存の `confirmExam` を od → os の順に2回呼ぶだけ。片方が失敗したら、その眼だけ未確認のまま残し、エラーを出す。
- 散瞳は見出しのチップ「散瞳 なし ▾」にする。開くと「両眼 / 右のみ / 左のみ / 取消」が出る。散瞳中は「散瞳(両) 18分」と表示し、20分を過ぎたら緑にする。
- 眼圧が 21 を超えたら、値の欄そのものを赤文字・太字にし、title 属性に「21 mmHg 超」を入れる。文の注記はやめる。
- 色: 行の頭の「R」「L」だけを `--od` / `--os` の色にし、行全体は塗らない。

**所見(左)**
- 今の R | L の並びは残し、塗りをやめる。部位のラベル(前眼部、中間透光体、眼底)を左に置き、R と L の textarea を横に並べる行グリッドにする。
- 「異常なし」は見出しの「両眼 空欄を異常なし」1つにする。片眼用は各眼の列見出しにアイコンボタンで小さく残す。

**シェーマ・現病歴・評価・オーダー・眼鏡・スタッフメモ**
- **空なら「+ 名前」のチップ** にする。押すとそのセクションが開いてフォーカスが入る。
- 値が1つでもあれば最初から開いた状態で出す。一度開いたセクションは、その画面のあいだは開いたままにする(入力中に中身を消してもセクションが消えないように)。

**病名(右の先頭)**
- 表示専用の1行にする(「主 右 白内障術後 9/22〜 / 左 加齢性白内障」)。説明文は title 属性に移す。

**処方(右)**
- 1剤1行の読める文にする: 薬剤名、眼、1日 n 回、数量・単位、院内外、日数、引継タグ。
- 行を押すと、その行だけが今の2段の編集欄(`rx-main` / `rx-sub`)に開く。新しく追加した行は開いた状態で始める。
- 引き継ぎ
  - セクションの見出しに「引き継ぎ2件 [このまま継続]」を出す。中身は既存の「すべて今回の処方として確認」と同じ処理。
  - 各行には黄色の「引継」タグだけを付け、行ごとの「確認」と黄色い帯はやめる。編集すれば確認済みになる既存の仕様は変えない。
- 「今回処方」のチェックは編集欄の中で「今回は出さない」というスイッチにする(意味は逆にせず、表示の文言だけ変える)。今回出さない行は、文の頭に「(今回なし)」と出す。

**次回(右)**
- 「[2] 週後 11/17(火)」、メモ、「予約を取る」を同じ行に置く。予約を取るのは `context.canReceive` のときだけで、今の「次回予約」タブの中身をここに移す。

**過去カルテ(左)**
- 上にタブを置く:「過去 4」「変更点 5」「セット」。
  - 変更点 = 今の ComparePanel の「今回変わった所」。
  - セット = SetsAndPhrasesPanel と CandidatesPanel。
- 最新の1回だけを展開し、それ以外は1行(日付、区分、R 視力/眼圧、L 視力/眼圧、主病名)に畳む。日付を押すと開閉する(CLINICS と同じ)。
- 所見は部位ごとに「R … / L …」の2行にし、接頭辞の繰り返しをやめる。
- 複写
  - グループの見出し(所見、処方、方針、シェーマ)の右に「→」アイコンを1つ置く。aria-label は「処方を今回へ複写」。
  - カードの見出しに「Do」を1つ置く(= すべて複写)。
  - 今の5ボタンは2種類の配置にまとまる。

### 3-4. 1024px / 768px / 390px

- **1024px**
  - 過去カルテは今と同じく左からの引き出しにする。ヘッダーに「過去4」ボタンを置く。
  - 中央は全幅で、見開きの2列(約 480px ずつ)を保つ。
  - 検査の帯は1行に約 640px あれば入る(眼 32、視力 64×2、S/C/Ax 60×3、眼圧 56、方法 80、確認 72、間隔)。
- **768px**
  - 見開きをやめて1列にする。順番は 主訴 → 検査 → 所見 → 病名 → 方針 → 処方 → 次回 → + 追加。
  - 検査の帯は1行のまま入る(約 700px)。
  - 患者帯は2行まで: 1行目が氏名とアレルギー、2行目が日付・区分、保存、確定。
- **390px**
  - 検査は眼ごとに2行にする。1行目は 裸眼・矯正・眼圧、2行目は S・C・Ax(値がなければ「詳細」の中)。R と L を上下に並べ、すぐに見比べられるようにする(ブロックごと積むのをやめる)。
  - **下に固定のアクションバー**(高さ 56px)を置き、保存状態と「確定する(要確認 n)」を常に見せる。上のヘッダーは氏名とアレルギーの1行だけを固定する。
  - 項目ジャンプは、下のバーの「目次」ボタンから出すシートにする。

### 3-5. 操作の細部
- ⌘/Ctrl+Enter で確定ダイアログを開く(今と同じ)。
- 確定ダイアログは既存のまま使う。readiness の blocker と warning、検査の確認、引き継ぎ処方の確認は、そこで解消できる。ヘッダーの件数は `readiness.blockers.length + readiness.warnings.length` を出す。
- 赤は blocker が「確認だけでは解消できないもの」の場合だけに使い、それ以外は黄色にする。
- 「+ 追加」チップや処方の行を押して開いたら、最初の入力欄にフォーカスを入れる。Esc でその行の編集を閉じる(値は保存されたまま)。
- 診療日・区分のボタンは、押すと小さなポップオーバーで date と select を出す。値は今と同じ `updateMeta` で更新する。確定済みのカルテでは表示だけにする。

## 4. 実装の優先順位

API の変更は **すべて不要** です(既存の `update` / `confirmExam` / `updateMeta` / readiness / FinalizeDialog だけで実現できます)。

| 順 | 変更 | 触る場所 | 効果 | 注意点 |
|---|---|---|---|---|
| 1 | 「確定前の確認」をやめて、件数を確定ボタンに出す。未確認の表示を黄色に変える | `encounter-editor.js` の header actions と side の ReadinessPanel 削除、`.readiness .is-blocker` の使い分け | A3、H4 | blocker の文言は確定ダイアログに出ることを確認する |
| 2 | 右の補助パネルを常設から引き出しに変える。前回比較・候補は左のタブへ、次回予約は NextVisit へ、文書・確定履歴は「…」メニューから引き出しで開く | `SIDE_TABS`、`.encounter-3col` の列を `300px 1fr` に、`.encounter-side` を全幅で引き出しのスタイルに | A2、A5、P3、P4 | 引き出しの開閉は既存の `drawer` state を流用する |
| 3 | 空のセクションを「+ 追加」チップにする | `Section` に `empty` / `defaultOpen` prop を追加。シェーマ、オーダー、眼鏡、メモ、現病歴、評価に適用。チップ行のコンポーネントを新しく作る | A1、F2、F4 | 開閉は初回の値で決め、開いた後は state で開いたままにする。値がある欄は絶対に畳まない |
| 4 | 検査を行 = 眼に転置し、前回は眼ごとに1行、詳細は開閉、確認は行の右端と「両眼を確認」 | `ExamTable` の rows 定義を列の定義に変える。`.exam-grid` の `grid-template-columns` を作り直す。`/exam`(ExamWorkbench)は `layout="table"` のような prop で今のまま残す | E1〜E7 | DOM の順(右眼の全項目 → 左眼)は変えないので、`moveToNextOnEnter` の Enter 移動はそのまま動く。両眼の確認は2回呼び出す |
| 5 | 中央を見開きの2列にし、セクションの順番を入れ替える | `encounter-form` の中を `.sheet-left` / `.sheet-right` に分ける。CSS は `grid-template-columns: 1fr 1fr`、1023px 以下で1列 | A1、2号紙の要求 | `id="sec-*"` は残すので、ジャンプとアンカーは壊れない |
| 6 | 390px で下にアクションバーを固定する | `.encounter-actions` を 767px 以下で `position: fixed; bottom: 0`。本文に下の余白を足す | H7 | iOS のセーフエリア(`env(safe-area-inset-bottom)`)を考える |
| 7 | 処方を1剤1行の表示にし、押したら編集。引き継ぎは見出しの1か所にまとめる | `Prescriptions`。表示には `prescriptionText` を流用する。展開する行の index を state で持つ | R1〜R3 | 行を開くだけでは `setRow` を呼ばない(引き継ぎの確認状態を勝手に変えないため) |
| 8 | 過去カルテを畳み、複写を「→」と「Do」に整理する | `HistoryPane`、`COPY_ACTIONS` の配置、`.history-card` | P1、P2 | 複写の処理(`copyFrom`)は変えない |
| 9 | 患者帯を1行にする。ジャンプは 1024px 以上で出さない。診療日・区分はボタンとポップオーバーに | `PatientBanner` の compact 表示(病名 1 + ほか)、`.encounter-toolbar`、`SECTION_LINKS` | H1〜H3 | 日付の変更は今と同じ経路で行う |
| 10 | セクションのカードをやめ、1枚のシートと区切り線にする。左右の塗りをやめる | `.form-section`(枠線と背景を外し、上罫線にする)、`.exam-eye-od > *`、所見の `.eye-column` の背景 | A6、E5、暗室 | 印刷 CSS には影響しない(print-view は別) |
| 11 | 細部の修正 | 傷病名の説明文と「編集」ボタンの文言を合わせる。眼圧の値そのものを赤く。`font-variant-numeric: tabular-nums`。チェックボックスと戻るリンクの押せる範囲を 32px 以上に | H5、H6、E6 | — |

## 5. やらないこと・保留
- 自由に配置できる2号紙(C-Note 型)や、医師ごとのレイアウト保存(Medius 型)は、作るものが大きいので保留する。
- AI による過去カルテの要約(CLIPLA の新機能)は API と国内 AI が必要なので、別の検討にする。
- 他覚屈折を機器から取り込むこと、レフケラのレシート表示は、機器連携が必要なので別の検討にする。
